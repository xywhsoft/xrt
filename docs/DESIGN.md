# XRT 设计总览

XRT 是可组合的 C 运行时库，而不是应用框架。它提供可单独启用的基础模块；应用负责
主循环、线程拓扑、业务对象和部署策略。选择模块时，应从实际任务和数据边界出发，而
不是从内部目录、旧名称或实现策略出发。

## 选择能力

先选择需要解决的问题，再选择最小模块集：

| 任务 | 首选能力 |
|---|---|
| 文本、编码、容器与配置数据 | String、Codec、Array/Map、JSON/XSON |
| 并发工作与取消 | Task、Future、TaskGroup、Channel |
| 文件、进程与日志 | File、Process、Logger |
| 加密与安全传输 | Crypto、X509、TLS |
| 字节流与协议处理 | TCP/UDP、NetPort、HTTP、WebSocket |

模块化接入与单头接入使用同一套公开 API。功能选择宏、依赖闭包和单翻译单元实现规则见
[功能选择](FEATURE_SELECTION.md)。

## 生命周期与数据边界

每个对象的文档都会说明创建、销毁和借用规则。调用方应把“谁释放”“可保存多久”和
“能否并发访问”当作 API 的一部分：

- 返回的拥有对象由对应 `Destroy`、`Free` 或 `Release` 函数释放。
- 输入缓冲区、回调视图和临时字符串通常只在当前调用或回调期间借用；跨边界保存前先复制。
- 未明确标为线程安全的可变对象由一个执行流串行驱动；要跨线程共享时，使用明确的同步原语或消息传递。
- 关闭顺序是生命周期的一部分：停止新提交、取消或关闭来源、等待在途任务，再释放依赖对象。

错误返回不能被当作部分成功。面对网络、文件或不可信输入时，应设置容量、长度、深度、
超时和并发上限，并处理短读、短写、取消和资源不足。

## 核心与扩展

核心提供协议原语和通用基础设施，但不规定应用级对象模型。例如 HTTP 核心负责消息
解析与生成，不负责客户端池、路由、认证或缓存；WebSocket 核心负责帧和传输辅助，
不负责重连、连接组或业务会话。需要这些能力时，选择独立发布的扩展库。

扩展库不会成为核心单头包或核心兼容性承诺的一部分。完整边界见[范围说明](SCOPE.md)。

## 面向发布的使用方式

发布前应从干净输出目录构建模块化产物和单头包，并在目标平台运行对应测试。跨编译或
示例成功只能证明编译与链接闭包；网络后端、TLS、进程和高并发取消仍需要目标环境的
真实运行验证。具体命令和验证范围见[构建与发布](BUILD.md)与[发布支持](RELEASE_STATUS.md)。
