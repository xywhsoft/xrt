# XID 使用指南

XID 用于在没有中心分配器的情况下生成紧凑标识。完整布局、错误和所有权契约见 [XID API](../api/xid.md)；本指南只回答如何选择和使用这些入口。

## 适用场景

XID 适合订单、任务、追踪、日志、缓存工件和临时资源等公开标识。每个进程都可以本地生成，不需要先访问数据库或 ID 服务。

XID 由 Unix 微秒和 128 位系统安全随机后缀组成。随机后缀让多个线程、进程和主机无需共享计数器；唯一性仍是基于随机空间的概率保证。持久化系统需要绝对拒绝重复时，仍应保留唯一索引并处理极低概率的冲突。

## 选择入口

| 需求 | 入口 | 所有权 |
| --- | --- | --- |
| 把标识直接嵌入对象或数组 | `xrtXidMake` | 调用方提供 `xid` |
| 一次生成大量标识 | `xrtXidMakeMany` | 调用方提供连续 `xid[]` |
| 写入固定缓冲 | `xrtXidWrite` | 调用方提供 33 字节缓冲 |
| 直接取得拥有型文本 | `xrtXidMakeString` | 使用 `xrtFree` 释放 |
| 把已有值转成拥有型文本 | `xrtXidFormat` | 使用 `xrtFree` 释放 |
| 解析外部文本 | `xrtXidParse` | 成功后写入调用方值 |

服务热路径优先使用值类型和固定缓冲，避免逐 ID 分配。业务脚本、日志拼接和一次性配置代码可以使用 `MakeString` 或 `Format` 换取更短的写法。

## 存储与排序

二进制形式固定为 24 字节，文本形式固定为 32 个 URL-safe ASCII 字符。文本不含填充符，可以直接用于数据库键、文件名和 URL 路径段。

`xrtXidCompare`、24 字节二进制比较和规范文本字典序保持一致。时间不同的值按生成时钟排序；同一微秒内由随机后缀决定顺序。因此 XID 适合近似时间聚簇，不代表线程调用顺序，也不代表不同主机之间的严格业务顺序。需要严格顺序时，应另外保存业务序号、提交序号或数据库版本。

## 不应替代的能力

- XID 不是登录令牌、重置密码 token、CSRF secret 或签名。文本公开携带时间，业务应把它视为可见标识。
- XID 不是数据库事务序列。自增键在单一数据库内仍适合紧凑整数外键和严格提交顺序。
- XID 不是全局时钟。主机时间回拨或时钟偏差可能使后生成值排在前面。
- XID 不是业务数据容器。时间可以由 `xrtXidTime` 提取，但状态、租户和权限等字段应单独存储。

## 解析与失败

外部输入必须通过 `xrtXidParse`。解析只接受完整规范文本，失败时不修改输出；`xrtXidErrorOffset` 可以取得第一个非法、缺失或多余字节的位置。

生成失败不会退化到普通伪随机数。`xrtXidMake` 把失败输出保持为零值，`xrtXidMakeMany` 在随机源失败时清零整批。调用方应把失败作为真实错误处理，不能继续发布全零标识。
