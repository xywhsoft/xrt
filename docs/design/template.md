# Template 设计

## 目标

模板库不是一个只能覆盖固定页面场景的封闭 DSL，也不把文件系统、扩展执行或业务对象强制绑在核心上。设计遵循 XRT 的递进原则：最小核心直接可用，复杂能力逐层建立，底层对象与检查 API 充分公开，常见路径再提供一行式 helper。

实现优先复用旧版 XRT 已经验证的模板语法、格式化能力、`xvalue` 容器、字符串构建器、文件整读和测试边界。重构重点是收紧所有权、预算、线程和错误契约，删除重复入口与隐式状态，而不是为了改写而改写。

## 分层

模板体系有五个可裁剪模块：

1. `template_core` 只负责源代码、路径、基础输出、编译对象、检查和渲染框架。
2. `template_control` 在核心节点与统一求值器上增加表达式、条件和循环。
3. `template_compose` 在 control 的块结构上增加本地定义、外部解析、包含和 raw。
4. `template_extension` 在 compose 的解析和渲染分派上增加不可变注册表与用户回调。
5. `template_file` 是 core 的正交便利层，只复用 `file_whole`，不会因为从文件编译而被迫链接完整模板语言。

这一依赖方向没有底座函数表，也没有为了形式解耦复制协议。高级层直接依赖它确实需要的低级层；不需要高级语法的程序可以只裁剪出 core。

## 编译对象

编译器复制源代码，并把节点、路径、表达式和参数转换为紧凑的只读表示。路径段与表达式只编译一次，渲染热路径不重新扫描模板文本。模板使用原子引用计数，所有运行时可变状态都位于单次 render context 中，因此同一对象可以由线程、任务或协程并发使用。

`xtemplatenodeview` 只公开稳定语义，不公开内部节点布局和指针。这样调试器、模板检查器和外部绑定可以遍历编译结果，而内部仍可在不破坏公共契约的情况下调整布局。

## 预算模型

编译预算分别限制源字节、节点、路径总量、路径深度、表达式数量、块深度、表达式深度、扩展参数总量和单调用参数量。渲染预算分别限制总输出、总步骤、运行深度、循环次数和包含深度。

预算在各层共享同一个上下文：扩展写入、重复渲染主体、外部 include 和循环都不能绕过总输出或总步骤限制。默认值足以覆盖普通模板，但始终有限，防止不可信模板用极深嵌套、巨量空节点或无界输出耗尽进程资源。

## 作用域

Root、Current 和 Global 是三个明确入口。普通路径只从 Current 开始，不做“找不到就依次尝试其他根”的隐式回退。显式 `root` 和 `global` 让模板含义不随局部对象新增同名字段而改变。

循环和解析块通过栈临时替换 Current，并保存独立 loop 元数据。扩展可以用 `xrtTemplateCallRenderCurrent` 选择新 Current 后重复渲染主体，但不能访问或保存内部 render context。循环控制信号只在当前模板控制栈传播，不能穿过扩展回调，避免 C 回调意外改变调用方外层控制流。

## 输出模型

渲染器只有一个 writer 原语。字符串渲染、构建器追加、扩展输出和未来的网络输出都建立在同一分片写入路径上，没有第二套拼接实现。

流式 writer 适合文件、socket 和大输出，它的外部副作用无法回滚。`xrtTemplateRenderTo` 在进入时记录 `xstrbuf` 长度，失败时恢复长度，从而给内存输出提供事务语义。`xrtTemplateRender` 只是基于构建器的所有权便利封装，不复制另一份求值逻辑。

## 控制与迭代

表达式解析器把逻辑短路和比较编译为内部节点。整数与浮点比较避免先把大整数无条件转成 double，NaN 明确按无序值处理。路径、字符串字面量和扩展参数全部借用模板持有的源存储，减少每次渲染的小对象分配。

`foreach` 通过 XRT 容器迭代接口建立稳定遍历状态。Current 指向当前值，loop 提供位置和键，不为数组、映射、集合和对象各写一套模板循环。所有循环共用一次渲染的总次数预算。

## 组合与解析

本地 define 在编译期登记，因此 include 可以前向引用，不需要运行时按源顺序修改符号表。外部 resolver 是唯一的动态模板来源；它返回普通 `xtemplate` 引用，渲染器统一接管并释放。

resolver 的输出参数先清零，并规定“任何非空输出都被接管”，解决失败路径究竟由谁释放的歧义。渲染上下文保存当前 include 链，按模板身份做精确环检测；深度预算负责限制合法但过深的无环链。

raw 是编译器识别的明确节点，不是在渲染时重新搜索或转义文本。主体因此可以逐字节输出，也不会让扩展或控制语法在 raw 内产生副作用。

## 扩展边界

旧版扩展引擎同时暴露可变 engine、函数与语句两套重复 API、大量 `Require*` helper、解析/释放回调和语义混合的 statement。新版把它收敛为不可变 registry、一个 `xtemplatecall` 接口和四种明确形态：function、statement、parsed block、raw block。

注册表复制名称并独立拥有每项 Data。创建只有全成功才转移所有权，避免部分失败时调用方无法判断哪些数据已经被析构。函数和语句分开建表，使相同名称可以在 `{@...}` 与 `{#...}` 中各自表达清晰语义。

参数在编译期按顶层冒号切分并预编译表达式。回调通过 argument view 和统一 Eval 读取，不需要为整数、字符串、对象分别维护一组易膨胀的 `Require*` API。`xtemplatevalue` 是借用的 tagged view，不把 XRT 值复制为扩展专用对象。

回调使用共享 writer 和共享预算。回调内部产生的模板域错误通常来自 `CallEval`、`CallWrite` 或 `CallRender`，应原样传播；其他域错误会作为 cause 包装，补充扩展名和源码位置。成功回调不能把一次试探留下的线程错误泄漏给调用者。

## 文件边界

文件入口调用 `xrtFileReadAllLimit`，以编译配置的源上限限制读取，再把明确字节长度交给唯一编译入口。它不复制文件读取循环，不处理 BOM，不猜测编码，也不改变核心模板的内存源契约。

把 `template_file` 设计为 core 的旁路依赖很重要：只需要从文件加载基础占位符的程序无需引入表达式、map、扩展注册表；已经从资源包、网络或内存取得源代码的程序则完全不需要文件模块。

## 错误边界

模板语法、求值、格式、预算、writer、扩展和 include 使用 `xrt.template` 域，并尽可能带源码字节范围和一基行列。文件读取仍是 `xrt.file`，内存不足仍是通用 `XERR_MEMORY`。跨域边界只在确实增加语义时添加 cause，不用包装掩盖底层错误。

错误位置放在结构化 Data 中，由 `xrtTemplateErrorLocation` 读取。公共调用方不需要解析错误消息，上层宿主可以把同一范围直接映射到自己的诊断位置。

## 旧版资产取舍

新版保留旧版中有价值且已经压实的能力：字符串、数字与时间输出，表达式和控制块，本地子模板、动态加载、raw、writer、扩展参数预解析、主体与作用域访问，以及相应边界测试。

没有保留二进制 AST 保存/加载。它会把内部布局变成持久格式，并引入版本、端序、指针重绑定和不可信文件校验负担；这与“内部实现可持续演进”的目标冲突。需要缓存时，上层应缓存模板源或进程内 `xtemplate` 引用。

没有保留专用 textual dump。`xrtTemplateSource`、`xrtTemplateNodeCount` 和 `xrtTemplateNode` 已公开足够的稳定检查信息，调试器可以按自身格式输出，不需要模板库长期维护第二套展示语法。

## 验证

每一层都有普通行为、边界、故障分配和单头文件测试。compose 与 extension 额外覆盖多线程共享，file 覆盖读取上限和文件错误域。裁剪测试分别验证正向最小闭包和缺少 core、control、compose、map、file_whole 等直接依赖时的失败。

发布回归同时使用 GCC x64 与 TCC x86，保证常规编译器和经典单头文件工具链得到同一套模板契约。
