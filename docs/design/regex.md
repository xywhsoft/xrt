# Regex 设计

## 分层

正则实现由六层组成：BBRE 只负责解析、编译和线性时间执行；`regex_core` 提供字面量转义，把模式包装为 XRT 不可变引用对象并接入统一分配器与错误模型；`regex_match` 把 BBRE 原先内嵌的可变执行缓存移入独立 matcher；`regex_replace` 在 matcher 之上提供模板与回调重写；`regex_split` 提供流式字段状态机；`regex_set` 把多个只读程序合并成一次分类执行。

这一边界允许一个编译对象被多个线程共享，每个线程或协程只需持有自己的 matcher。常见的一次性检查由便捷函数创建临时 matcher，高负载路径则显式复用 matcher。

核心实现复用 XRT 的统一错误、内存和字符串原语。错误对象通过 `xrtSetErrorTake` 转移所有权，替换层通过 `xrtStrBufValid` 与 `xrtStrBufAlias` 检查构建器，拆分层通过 `xrtStrListAlloc` 与 `xrtStrListWrite` 构造单块结果；正则模块不复制内存布局或错误状态逻辑。

字面量转义属于编译前的数据构建原语，不进入 BBRE。长度、调用方缓冲和自动分配三层入口共用同一字节分类；同址扩展从后向前写，非重叠输出从前向后写，容量不足和非法重叠均在写入前失败。

## 所有权

- `xregex` 复制原始模式并拥有编译程序。
- `xregexmatcher` 增加 `xregex` 引用并拥有执行上下文与捕获数组。
- `xregexset` 增加全部 `xregex` 引用并拥有合并后的只读执行程序。
- `xregexsetmatcher` 增加集合引用并拥有执行上下文与命中索引数组。
- 输入和捕获文本始终借用调用方内存。
- 下一次匹配会覆盖捕获数组，但不会修改编译程序。

## 替换边界

替换层不把模板逻辑塞进正则引擎。每次调用先把模板解析为借用原模板的紧凑令牌，再复用一个 matcher 遍历输入；命名捕获只在模板解析阶段查找一次，热循环只读取捕获索引。普通文本、模板和输出构建器仍由字符串模块负责，因此引擎不承担字符串所有权和增长策略。

输出采用追加事务：进入调用时记录构建器长度，任何匹配、回调或分配错误都会恢复该长度。模板和输入若借用输出当前内容，会先复制后再增长，避免 realloc 使来源悬空。回调入口临时隔离调用前遗留的线程错误；回调成功恢复原错误，回调失败保留 OOM 或建立带 cause 的 `XREGEX_ERROR_CALLBACK`。

## 拆分边界

拆分器始终用明确搜索位置调用 matcher，而不依赖 matcher 的隐式 `Next` 状态。只有一次分隔匹配成功后才提交 `Position`、`Search` 和计数，因此执行错误不会推进拆分状态。空匹配通过 Regex 共享的 UTF-8 推进原语计算下一搜索位置；字段起点仍保留在分隔结束处，跳过的标量会自然落入下一字段。

捕获项必须在下一次搜索前输出，因为它们借用 matcher 当前捕获数组。状态机因此按“字段、捕获 1..N、下一次搜索”的顺序运行。默认复制 helper 不需要捕获元数据，先计数再重置状态机，并复用同一 matcher 的执行缓存完成第二遍；最终列表复用字符串模块的唯一单块分配与写入实现。

## 集合边界

集合只回答哪些模式命中，不返回每个模式的捕获。这个边界避免为大量规则预留捕获存储，并让结果数组固定为每个模式一个 `unsigned int` 索引。需要捕获的调用方从集合借用候选 `xregex`，再交给普通 matcher。

集合允许零个模式，便于上层以数据驱动方式原子替换规则表。批量编译逐项构建普通 `xregex`，语法和预算失败时用模式索引包装原始错误，内存不足则不执行二次分配；从已有对象创建保留每个模式自己的标志和资源预算。集合与 matcher 分离后，分类执行不会修改共享集合，因此线程模型与普通正则一致。

## 安全边界

默认模式字节数和捕获数有限。BBRE 继续提供 AST、重复次数、组名和规范化字符类的内部硬限制。匹配为非回溯 NFA/DFA，不接受会破坏线性时间保证的反向引用和环视。

## 第三方扩展

XRT 在 `bbre_xrt.h` 中增加独立执行上下文和真正的完整匹配入口。原始 BBRE API 仍用于其完整上游测试，XRT 公共 API 不暴露这些符号。引擎扩展由专门测试锁定非零起点捕获、完整匹配优先级、集合上下文和 OOM 恢复。
