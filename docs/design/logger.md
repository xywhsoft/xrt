# 日志设计

## 用途

日志模块将应用事件写入控制台、文件或调用方提供的输出端。它支持等级、时间、来源和结构化字段，适合在库与应用之间传递可诊断信息；它不是审计、指标或分布式追踪系统的替代品。

## 配置与数据边界

在程序启动时配置级别、格式、输出目标和轮转策略，并在开始写入前完成初始化。结构化字段和格式化参数在一次写入期间由调用方提供；异步或延迟输出场景必须使用日志 API 提供的复制/拥有语义，不能让后台任务引用已失效的栈内存或临时缓冲区。

## 可靠性与安全

日志失败不得改变业务操作的正确性，但必须能被调用方发现或降级处理。不要记录口令、令牌、私钥、未脱敏个人数据或完整的不可信请求正文。多行不可信文本应先规范化或转义，避免伪造额外日志记录。

## 并发与关闭

可从多个工作线程写日志的部署，应使用模块提供的同步模式或在应用侧串行化写入。关闭顺序是：停止新日志生产者、等待异步队列排空、刷新输出、再释放日志对象；过早释放输出目标会导致丢失记录或悬挂引用。
