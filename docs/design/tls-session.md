# TLS 会话设计

## 用途

TLS 模块为基于字节流的连接提供握手、加密读写、证书校验和有序关闭。它可以与 TCP 或调用方实现的传输层组合；不负责 HTTP 语义、连接池策略、账户认证或证书自动签发。

## 对象边界

TLS 上下文保存共享配置，例如受信任根、证书、私钥、协议版本与验证策略。每条连接创建独立会话，负责握手状态、加密缓冲和关闭状态。上下文必须在所有会话释放后才能销毁；会话不得跨越其底层传输的生命周期。

## 客户端与服务端验证

客户端应启用证书链和主机名验证，并把目标服务器名称传给 TLS 配置。服务端应加载与监听地址匹配的证书和私钥；若需要双向 TLS，必须显式配置客户端证书验证。跳过验证只适用于受控测试环境，不能作为生产默认值。

## 驱动、读写与背压

非阻塞连接会在握手、读写和关闭时请求更多输入或输出空间。调用方应持续把网络输入喂给会话、及时发送待写密文，并按照返回状态重试；不能把“暂时无法推进”当作成功或永久错误。对明文、密文、握手次数和等待时间设置上限，避免慢速对端无限占用资源。

## 并发与关闭

一个会话由一个 I/O 执行流串行驱动。要关闭连接时，停止新的应用写入，尝试发送 TLS `close_notify`，处理剩余密文，并最终关闭底层传输。取消或网络中断时允许直接终止，但应用应将其记录为未完成的 TLS 关闭，而不是正常会话结束。
