# JSON 与 XSON 设计

## 选择格式

JSON 模块用于标准 JSON 互操作；XSON 在相同的基础数据模型上增加面向程序的数据表示能力。对外协议、配置文件和第三方系统交换数据时优先使用 JSON；仅在生产者和消费者都采用 XRT 扩展语义时使用 XSON。

## 读取与写入

两种格式都支持树形数据和流式处理。树形 API 适合随机访问、修改与再序列化；流式 API 适合大文件、网络输入和只处理部分字段的场景。流式事件中的文本、键和原始数字 token 可能借用输入缓冲区，跨回调保存前必须复制。

写入时应检查每一步的状态，并为输出设置容量或回调策略。验证、解析和序列化都不是零成本操作：Base64、转义字符串和深层嵌套可能需要临时内存，来自不可信来源的数据必须启用长度与深度限制。

## 数字与重复键

对象和整数映射中的重复键默认拒绝；应用可显式选择保留首项或末项。非负整数依次尝试 `int64` 与 `uint64`；超出 `uint64` 或低于 `int64` 范围时默认失败，可显式降级为 `double`。流式数字事件保留原始 token，方便上层接入 BigInt 或 Decimal，而无需改变底层数据模型。

## 所有权、错误与并发

树节点、解析器和写入器的所有权以创建它们的上下文为准；销毁上下文会使其拥有的节点失效。语法错误应包含可定位的输入信息，但调用方不应把错误文本作为稳定机器接口。可变的解析器和写入器不应由多个线程同时驱动；可完成构造且不再修改的树可由调用方按其自身同步策略共享。

## JSONL 与 XSONL 记录序列

JSONL/XSONL 将每个非空物理行解释为一个独立值，再按顺序汇总为拥有的
xvalue Array；数组记录保持嵌套。读取默认忽略空行和仅含 ASCII 空格、Tab、CR
的行，可通过 REJECT_EMPTY_LINES 改为空行报错。LF 与 CRLF 可以混用；空输入
返回空 Array，错误位置保持原始物理行号和零基记录下标。

单条值复用 JSON/XSON 语法、类型及所有权规则。跨记录累计预算在解析过程中
消耗，不因新行或重复键覆盖而重置。单条配置与整体字节/记录预算分别生效。

写出要求最外层为 Array，每条紧凑记录后追加 LF，拒绝 PRETTY；空 Array
产生空文本。内存读取失败会释放部分结果，回调写出不撤回已提交字节，
文件写出先完整序列化再原子替换。

完整接口与裁剪宏见 [JSONL](../api/jsonl.md) 和 [XSONL](../api/xsonl.md)。

## 不承担的职责

JSON/XSON 不提供模式治理、业务字段校验、权限判断或自动对象映射。这些规则应留在应用层，以避免把特定领域语义固化为通用数据格式行为。
