# JSON 与 XSON 设计

## 职责边界

JSON 是对外互操作格式，默认严格遵守 RFC 8259。XSON 是 `xvalue` 的可移植扩展
文本格式，用于内部快照和需要保留扩展类型的边界。所有严格 JSON 都必须是语义
不变的 XSON 子集，但 JSON 永远不会因为 XSON 存在而接受私有字面量。

HTTP、WebSocket 和其他协议层不会强制依赖 JSON/XSON DOM。调用方可以直接发送
已有正文，也可按需使用 writer；数据构建器是可选能力，不是协议传输的必经路径。

## 共享层

JSON 与 XSON 共享三块内部机制：

- 显式长度游标、UTF-8、字符串、数字、注释选项、深度和项目预算。
- 具有 Root/Frame/Key 状态的内存或 sink writer。
- 限额文件读取、原子替换和 I/O 原因链包装。

格式适配器各自负责公开配置、错误域、事件类型、DOM 映射和扩展标签。XSON 不通过
调用 JSON 公开 API 组装，JSON 也不知道 XSON 类型。共享机制只有一份实现，格式
契约仍可分别裁剪和演进。

## API 层次

- `Parse`、`Valid`、`Stringify` 和文件快捷函数覆盖一行式常用路径。
- `Read`、`Visit` 和 `Write` 暴露预算、语法策略、事件与 sink。
- `Writer*` 直接构造文本，不要求先创建 DOM。
- XSON 自定义标签是唯一类型扩展入口，不通过隐藏全局注册表耦合运行时。

API 不保留旧名称，不提供 `Ex`、`Ex2` 或兼容别名。合法根 `null` 返回
`xrtValueNull()`，失败返回空指针，错误表达不再含糊。

## 资源与错误

读取预算包含输入字节、字符串字节、值数量、单容器元素、解码字节和嵌套深度。
写出预算包含输出字节和嵌套深度。默认值有限，且配置必须由初始化函数建立，避免
零初始化结构因版本变化悄然获得无上限行为。

JSON 使用 `xrt.json`，XSON 使用 `xrt.xson`。语法错误记录零基字节偏移和一基
行列。文件错误在格式域建立稳定 I/O 错误，并通过 Cause 保存底层文件错误。
回调显式设置的新错误不会被格式层覆盖。

## 读取模型

共享 reader 直接产生事件，不先构建 DOM。DOM reader 是事件消费者，负责 Value
所有权、重复键策略和容器挂接。公开 visitor 是另一消费者，事件视图只借用到回调
返回。

严格 JSON 校验不需要为合法无转义输入分配。XSON 的 `bytes` 语义校验必须完成
Base64 解码上限检查，转义字符串也可能需要临时缓冲，因此 XSON `Valid` 不承诺
零分配。

对象和 int-map 的重复键默认拒绝，可显式保留首项或末项。超出 `int64` 的整数
默认失败，可显式降级为 `double`。数字事件始终保留原始 token，使更高层可以接入
BigInt 或 Decimal，而无需改变底层 DOM。

## XSON 类型系统

XSON 使用显式语法：Array `[]`、Object `{}`、IntMap `intmap{}`、Set `set[]`、
Bytes `bytes("Base64")`、Time `time("RFC3339")`、非有限浮点 `float("...")`。

旧版根据首元素猜测 List/Set 的规则使空容器和后续元素改变语义，已经删除。旧版
`class(Base64)` 直接保存结构体原始内存，不跨编译器、架构、字节序或版本，已经
删除。自定义数据只能通过带名称和字符串载荷的 tag 扩展，由应用定义稳定编码。

Pointer 和 Handle 没有默认可移植表示。写入自定义回调接收受保护的只读 Value
快照，返回标签和载荷；读取 DOM 回调把标签解码为一个拥有引用。未知标签默认失败。

## 写出模型

共享 writer 维护一个根值、固定大小容器帧和明确的 Key/Value 交替状态。任何状态、
预算、UTF-8、分配或 sink 错误都会把 writer 固化为失败终态。sink 和自定义编码
回调期间禁止重入，包括 Finish、Take 和 Free。

字符串和数字直接分段输出。XSON Bytes 每次读取 3 KiB 输入并写出 4 KiB Base64，
避免建立第二份完整编码文本。内存 writer 只持有最终文本和容器帧；sink writer 不
持有完整正文。

## 文件模型

文件层先按输入预算读取，再交给同一 reader。写出时先在内存完成整个序列化，只有
成功后才调用原子文件替换，因此格式错误、OOM 或不支持类型不会破坏旧文件。JSON
和 XSON 共用这一 I/O 实现，只提供不同的格式错误域和解析适配。

## 验证门槛

- GCC C11 `-Wall -Wextra -Werror` 和 TinyCC 都运行模块化测试。
- read/write/file 三个裁剪根都有独立单头测试。
- 读取和写出扫描所有稳定故障分配点，验证释放、恢复和输出大小不变性。
- 读写测试覆盖严格语法、扩展类型、事件、sink、回调错误与重入、文件原因链。
- 基准分别记录 DOM parse、无 DOM visit 和 DOM write，避免只看总吞吐掩盖回归来源。
