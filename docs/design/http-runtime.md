# HTTP 运行时设计

## 用途

核心 HTTP 运行时用于解析和生成 HTTP 消息，并为基于流的网络程序提供增量编解码能力。它适合实现代理、服务端、客户端适配层或自定义协议网关；完整的 HTTP 客户端、服务端和 WebSocket 产品能力由独立扩展库提供。

## 数据流与所有权

解码器按输入字节推进状态，并通过回调或结果对象交付起始行、头字段、正文分片和结束事件。事件中指向输入缓冲区的视图默认是借用数据：调用方如需在下一次喂入数据后保留它，必须复制到自己的存储。

编码器只根据调用方提供的消息数据写入输出缓冲区。调用方负责保证字段、正文和输出缓冲区在调用期间有效，并根据返回状态处理部分写入或需要更多空间的情况。

## 边界与限制

启用严格模式时，运行时会验证消息行、头字段、长度信息和分块边界。应用应在初始化配置中设定首行、头部、正文和缓冲区的上限；对来自网络的输入不能使用无界累积。解析成功只表示语法和配置约束满足，不代表业务层已经完成鉴权、路由或内容校验。

## 并发与错误

一个可变的解码器或编码器应由一个执行流串行驱动。多个连接可以各自持有实例并发运行。格式错误、超限、回调拒绝和内存不足必须作为失败处理；失败后应按对象 API 的要求重置或销毁实例，不能继续消费未定义状态。

## 选择扩展库

需要连接管理、路由、HTTP/2、WebSocket 或应用级超时策略时，请使用相应扩展库。核心运行时只提供稳定的消息编解码基础，不规定应用线程模型、事件循环或业务对象生命周期。
