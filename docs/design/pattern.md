# Pattern 设计

## 边界

Pattern 是受限结构化字节匹配器，不是路由系统或正则表达式。普通捕获可以
占据完整字段，也可以在同一字段中带固定前缀、固定后缀或两者；每字段只允许
一个非空捕获。这个边界仍可完全确定化，并让查询成本只取决于输入长度、
字段数和实际捕获数，而不在运行期遍历模式集合。

全部模式共享分隔符集合。这既允许 `/`、`.`、`/.` 等不同应用，又避免每条
模式具有不同字符分类规则造成的状态膨胀。分隔符是字节，不是 Unicode
码点，也不接受运行时回调。

## 编译结构

编译分为以下阶段：

1. 模式解析为精确分隔符、字面字段、普通捕获、前后缀捕获和尾捕获原子。
2. 原子插入逻辑 trie；高扇出节点在编译期自适应建立临时哈希索引，避免
   大批量注册退化为二次复杂度。
3. 字面字段与整字段捕获的候选集合被确定化为外层字段 DFA。
4. 只有包含前后缀捕获的外层状态才附加局部字节 DFA。局部 NFA 使用共享
   prefix trie，并让同前缀模式共享 suffix trie 和永久通配状态；模式数量
   增长不会复制同一活跃通配集合。精确字面量目标在编译期与局部 DFA 输出
   合并，保留全部后续 fallback。
5. 小扇出状态保存紧凑线性转移；高扇出字面字段使用低负载开放寻址表，
   局部字节 DFA 使用稀疏覆盖加通配默认边。
6. 热条目只保存 Rank、ID、值和捕获数；源文本、捕获名和回放信息分离为
   冷元数据。状态、转移、元数据和字符串池最终打包为一个只读分配。

确定化保留 `/a/b/c` 与 `/a/{x}/d` 的并行候选，因此 `/a/b/d` 不需要运行期
回溯即可命中第二条。

## 查询路径

匹配入口按分隔符数量选择一次扫描器：无分隔符、固定 `/`、单字节、2～4
字节小集合或 256 位 bitmap。模式开关不在逐字节循环中。

`Lookup` 只执行确定性选择。`Match` 在同一次选择扫描中用固定栈内数组记录
常见短路径的字段边界，获胜后按字段索引直接生成捕获视图；超长字段序列和
尾捕获才进入冷回放路径。它不会为全部候选维护捕获内容，也不需要第二次
扫描常见输入。有效查询不分配、不加锁，也不修改编译对象。

不含前后缀捕获的快照使用独立的短扫描器，逐字段循环中没有局部 DFA 分支，
也不为外层状态分配混合捕获根表。新增语法因此不会向既有 literal、整字段
捕获和 tail 工作负载收取逐字节成本。

## 更新路径

Builder 使用稳定代际 ID，并为每条模式保存自包含解析结果。修改 Builder
不会改变已发布快照。编译失败保留上一个成功快照和当前 Builder 内容，上层
可以修正模式后重试。

实现不采用 Base 加多层 Delta 的查询结构，因为其成本会随动态更新次数增长。
每次成功编译都生成单一紧凑快照，把更新成本留在查询热路径之外。

查询不会遍历模式集合，其算法成本由输入字节数和字段数决定。模式集合增大
仍可能通过缓存工作集间接影响实际纳秒数，因此仓库基准同时记录 1、500 和
10,000 条模式，而不把“大 O 不变”误写成硬件延迟绝对不变。

## 资源边界

配置限制单条模式字节、模式数量、每条捕获数、逻辑/外层/局部确定化状态数
和最终编译字节。遇到状态膨胀时编译明确失败，不退回逐模式或 NFA 扫描。
