# XRT 运行时架构

## 目标

XRT 将常见 C 基础设施组织成可独立启用的模块：调用者只引入实际使用的能力，并在不同平台上获得一致的所有权、错误和关闭语义。它不是应用框架，也不会接管应用的主循环、线程模型或内存策略。

## 分层

| 层 | 提供的能力 |
|---|---|
| 基础层 | 内存、字符串、正则、容器、编码、时间、路径和错误对象 |
| 运行时层 | 任务、Future、同步、定时器、文件、进程和日志 |
| 数据与安全层 | JSON/XSON、模板、随机数、密码学和 TLS |
| 传输层 | TCP/UDP、事件循环、DNS、HTTP 解析与协议辅助 |
| 应用扩展层 | 独立发布的 HTTP、WebSocket、邮件和 SSH 扩展 |

上层可以依赖下层公开 API；下层不会反向依赖应用协议。可选后端和系统能力通过配置选择，调用方不应依赖某个内部实现或目录布局。

## 公共契约

- 每个资源都由创建者、转移点或销毁函数明确所有权；借用的指针只在文档规定的作用域内有效。
- 可能失败的操作返回状态或错误信息，不能把部分成功当作完整结果使用。
- 可并发使用的对象会在模块文档中说明；未明确标为线程安全的可变对象应由调用方串行访问。
- `Close`、取消和析构可能触发回调或延迟回收。关闭前停止新的提交，并等待仍持有对象的任务完成。

## 集成方式

模块化模式使用 `include/` 和 `src/`，适合长期维护和细粒度依赖管理；单头模式使用 `single/xrt.h`，适合嵌入式或单项目交付。两种模式使用相同的公开 API，模块选择与编译开关见[特性选择](FEATURE_SELECTION.md)。

## 扩展边界

核心库不要求链接任何扩展库。`extlibs/` 中的扩展拥有各自的发布节奏、依赖和兼容性说明；使用它们时，应以扩展自身文档为准。核心库的产品边界见[范围说明](SCOPE.md)。
