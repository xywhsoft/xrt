## 导读

时间看似简单，坑却最深：浮点秒的精度丢失、时区的夏令时迷宫、"加一个月"到底是 30 天还是日历进位。XRT 的 time 模块用三个设计回答：**整数微秒主线**（`xtime` 即 int64 微秒——比较差值零浮点误差，与超时/截止体系无缝衔接）、**固定偏移时区**（`xrtTimeSplitAt(+8×3600)` 按偏移分解——无夏令时的复杂度，覆盖多数服务端场景）、**日历语义运算**（`xrtTimeAdd` 按月/日单位进位——8 月 31 日 +1 月 = 9 月 30 日，不是加 30×86400 秒）。

## 引入

三个经典 bug。bug 一：用 double 秒存时间——`0.1 + 0.2` 的浮点误差（第 10 章）在时间轴上放大成"定时器偶发提前或迟到一微秒"，与截止时间比较时随机翻转。bug 二：服务器按"本地时区"显示日志——部署到不同时区的节点日志时间对不上，跨节点事件的先后顺序无法重建——分布式排障的第一需求就倒在这里。bug 三：订阅"加一个月"用 30 天近似——1 月 31 日续费到 3 月 2 日，用户投诉与对账部门同时找上门。

三个 bug 的解药分别是：整数微秒（表示层消灭浮点）、UTC 存储 + 固定偏移展示（存储层消灭时区歧义）、日历进位（运算层消灭月长歧义）——每层一条纪律，纪律比 API 更值得记。time 模块的全部 API 都建立这三条纪律之上——理解纪律后，API 名字几乎自解释；反过来，只背 API 不懂纪律，坑区的每个事故都在等你。

## 概念

### 表示：整数微秒

`xtime` 是 int64 微秒（不是 double 秒、不是结构体）——这个选择的理由：**比较零误差**（定时器与截止时间的判定是热路径，浮点比较的边界翻转不可接受）、**差值即减法**（耗时测量 `t1 - t0` 直接得微秒数）、**跨度充足**（int64 微秒覆盖约 29 万年——从大爆炸到遥远未来都够用）。`xrtNow()` 取当前时刻、`xrtClock()` 取单调时钟（第 10 章 clock 范例用于耗时测量——单调钟不受系统时间跳变影响，测耗时永远用它）。

### 分解：UTC 与固定偏移

```diagram flow
- 存储与运算：一律 UTC 微秒——单一无歧义时间轴
- 展示分解：xrtTimeSplit 按 UTC；xrtTimeSplitAt(偏移秒) 按目标时区
- 固定偏移：+8×3600 即东八区——无 DST 查表、跨平台一致
- 人机分工：机器之间传微秒整数；只在最后一刻分解成人读格式
```

固定偏移时区是**有意的简化**（工程上叫"用可解释性换完备性"）：多数服务端场景（日志时间戳、报表日期）只需要一个固定偏移；完整时区库（IANA 数据库、夏令时规则）的复杂度换来的是每年两次的规则更新负担。需要复杂时区时在展示层接宿主的时区设施——存储层保持 UTC 微秒不动摇。

### 日历运算：进位语义

`xrtTimeAdd(时间, 数量, 单位, 出参)` 按日历语义进位：**月末截断**（8 月 31 日 +1 月 → 9 月 30 日，不是 10 月 1 日）、**闰年正确**（2 月 28 日 +1 年 → 次年 2 月 28 日，闰年则 29 日——按当年实际日历）。对比"秒数近似"（+30×86400 秒）的本质差异——近似法在 31 天月多算、在 2 月少算，全年漂移：日历月的长短是**人的约定**不是物理量——订阅续费、账单周期、日程提醒全部需要日历语义。物理时长（超时、间隔、节流）则用微秒加减——**两类运算不要混**：日历单位给人、微秒给机器。

### 格式化与解析（展示层的最后一站）

时间与文本的互转（ISO 8601 为主格式）与第 26 章严格语义同宗：解析要么整段合法要么失败、格式化按声明布局。第 34 章模板的 `{&path:%F}` 时间前缀用的正是这里的格式化引擎——展示格式在模板层声明、时间值始终保持微秒整数。


**刚才发生了什么。** ① `xrtNow()` 返回整数微秒——输出第一行就是存储形态（人不可读但机器最爱：可比较、可减、可序列化）。② `xrtTimeSplit` 按 UTC 分解为日历字段、格式化成 `2026-09-05 02:01:33.834602`——微秒精度保留。③ `xrtTimeSplitAt(+8×3600)` 同一时刻按东八区分解——`10:01:33`：**时刻没变，展示变了**，这就是"UTC 存储 + 偏移展示"的全部。④ `next_month` 比当前恰好多一个日历月——微秒差不是固定 30 天的整数倍，这正是月末进位语义的实证：日历月的长短随月份不同，加法按人的历法走。

**刚才发生了什么。** ① `xrtClock()` 单调时钟——NTP 校时、用户改系统时间都不影响它，**测耗时永远用它**（`xrtNow` 会被校时跳变污染：跨越一次 NTP 步进的耗时测量可能得到负数）。② 微秒差直接减法得到；换算秒是展示层的事（除以 1e6——第 26 章格式串也能做）。③ 实际值随调度浮动（约 10~15 毫秒，断言下限 10000µs），但单调性有保证——这正是基准测试（第 23 章对照实验）要的性质。

## 契约

- **整数微秒**：存储、传输、运算一律 `xtime` 微秒；浮点秒不进存储层。
- **UTC 主线**：机器之间传 UTC 微秒；分解展示按需带偏移；偏移是展示参数不是存储属性。
- **单调钟**：测耗时用 `xrtClock`（不受校时影响）；`xrtNow` 只用于"现在几点"。
- **日历进位**：`xrtTimeAdd` 月末截断、闰年正确；日历单位给人、微秒给机器，不混用。
- **格式化分工**：机器格式微秒整数；人读格式在展示层（模板前缀/格式串）声明。

### 从示例到工程：时间的三个宿主

**日志时间戳**：`xrtNow()` 的微秒整数直接进日志（第 38 章 JSON Sink 的 time 字段就是这个形态）——UTC 存储、查看时按查看者偏移分解（坑 1 的 good 完全体）。**超时与截止**：`xrtDeadlineAfter(微秒)` 族（第 61 章网络章的常客）吃的就是 xtime——整数微秒与截止体系无缝，这正是"表示层选整数"的分红。**业务周期**：订阅、账单、日程全部走 `xrtTimeAdd` 日历语义——月末截断规则写进产品文档（"1 月 31 日月付，2 月 28 日扣款"是明确行为不是 bug）。三宿主对应时间的三种身份：**时刻**（几点了）、**时长**（过了多久）、**周期**（下次什么时候）——每个身份有自己的正确工具，身份先于 API。

### 一个心智模型：时间的三层视图

把时间处理想成三层视图，大部分设计决策变得显然。**存储层**：UTC 微秒整数——唯一无歧义的表示，比较、传输、索引全部在这层。**运算层**：物理量（微秒加减——超时、节流、耗时）与日历量（TimeAdd 进位——周期、日程）两条轨道，按需求选轨不混轨。**展示层**：分解 + 格式化 + 时区偏移——全部是"渲染参数"，永不回流到存储。违反任何一层纪律的代价都在坑区有实例：存储层混时区（坑 1）、运算层混轨道（坑 2）、展示层提前分解（日志存了本地时间文本）。三层视图也解释了为什么 time 模块的 API 面这么小——每层只有两三个动作，复杂度被层的纪律吸收了。

### 时间测试的诀窍

时间相关代码的测试有个天然难题：`xrtNow` 每次不同。诀窍是**注入时刻**：业务函数接受 xtime 参数而不是内部调 Now——测试传固定时刻（2026-01-31 00:00:00 UTC 之类的边界日）、生产由调用方传 Now。这与第 11 章随机数的"种子注入"同构：不确定源全部在边界注入。耗时测量类逻辑（重试退避、节流窗口）同理：接受 xtime 参数，测试里手动推进"虚拟时钟"——第 22 章练习的调度器骨架用的正是这个技巧。

## 避坑

### 坑 1：本地时区存日志时间（存储层混入展示参数）

症状：多节点日志时间对不上；跨时区部署后"同一事件"的时间差几小时；夏令时切换日日志出现"重复的一小时"。

原因：存储层混入了展示层的时区——每台机器的"本地时间"是不同的展示参数。

```c bad
xtime Now = xrtNow();
xdatetime T;
xrtTimeSplitAt(Now, LocalOffset(), &T);   /* 按本地偏移分解后存字符串 */
SaveLog("%04d-%02d-%02d ...", T.Year, ...); /* 存的是"本地时间文本"——时区信息丢失 */
```

```c good
xtime Now = xrtNow();
SaveLog("%lld", (long long)Now);          /* 存 UTC 微秒整数 */
/* 展示时才分解：xrtTimeSplitAt(偏移按查看者)——时区是查看参数 */
```

### 坑 2：用秒数近似日历运算（两轨混用）

症状：订阅/账单周期在月末漂移——1 月 31 日 +30 天 = 3 月 2 日；用户侧显示"多扣两天"。

原因：日历月不是固定秒数——用 30×86400 近似"一个月"在 31 天月与 2 月都会错。

```c bad
xtime Next = Now + 30LL * 86400 * 1000000;   /* "加一个月" = 30 天近似 */
```

```c good
xtime Next;
xrtTimeAdd(Now, 1, XTIME_UNIT_MONTH, &Next);   /* 日历进位：1/31 + 1月 = 2/28 */
```

## 练习

### 基础：双时区对照（同一时刻两种展示）

取当前时刻，按 UTC 与 +8 偏移分别分解打印——两个时刻的微秒值相同、展示不同；再算两个展示的小时差验证偏移正确。

### 进阶：订阅续费计算器（日历语义的可视化）

实现 `next_billing(当前, 周期月数)`：日历加法进位；对 1 月 31 日开通的月付用户连续计算 12 个月的账单日，观察月末截断行为并输出说明。

### 挑战：耗时基准工具（单调钟 + 中位数）

用单调钟实现 `measure(函数, 次数)`：预热 N 次后正式计时、取中位数（第 10 章 Near 的容差思想用于判断两次测量是否"实质相同"）、输出微秒与人类可读两种格式。用它测第 23 章的数组 vs 链表遍历，数字应与该章对照实验同量级。
