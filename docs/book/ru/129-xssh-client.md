## Ориентация

Серия SSH завершается — детали предыдущих шести глав собираются здесь. `ssh_client` компонует ядро/потоковую сессию/динамические каналы поверх **предоставленного вызывающим `xnetstream`**: **не создаёт скрытый Engine, не блокирует Worker, не преаллоцирует каналы или буферы сообщений, не вводит вторую машину состояний** (четыре «не» — SSH-редакция «нет второй реализации»). Жизненный цикл соединения: после `ClientInit` таблица событий и указатель данных уходят прямо в `xrtNetStreamConnect` (или, на уже построенном потоке, `ClientAttach`) — с открытием TCP `ReadyTimeout` (умолчание 30 секунд) единообразно ограничивает обмен версиями → KEX → доверие хоста → аутентификацию; **событие Ready — единственная точка публикации SSH-пригодности**. Три точки взаимодействия: доверие хоста (по умолчанию отказ — после DEFER событие HostKey отдаёт право решения), аутентификация (событие Authenticate при NEED_MORE у провайдера), неизвестные расширения протокола (callback Packet сохраняет полную способность обработки). Слой удобства Dial (DNS/Happy-Eyeballs/тайм-аут/отмена) обрезается независимо — прокси и собственные транспорты идут через Attach без ограничений.

## Введение

Трудность «слоя финальной сборки» — **закрытие ответственностей**: всё состояние соединения (версия/KEX/аутентификация/каналы/переадресация) по главам деталей имеет своих хозяев; клиент нанизывает их в одно событийное целое — но поведенческие границы каждого слоя неизменны (ядро остаётся тем же ядром, окно тем же окном). Клей закрытия — **таблица событий** (конфигурационная структура events клиента): Ready/Error/Close/HostKey/Authenticate/Data/Drain/Global/Packet — вся поверхность взаимодействия приложения; изоморфна событийной цепочке HTTP-сервера главы 104.

**Двухслойное сцепление противодавления** стоит посмотреть сперва: при AGAIN TCP-очереди полный шифрованный пакет остаётся в единственном владении транспорта, а новые входы SSH приостанавливаются; callback-и LowWater/Drain сперва повторяют внутренний пакет, и **лишь после фиксации внутренней транзакции и действительного осушения TCP-очереди публикуется Drain клиента** — новые сообщения, отправленные приложением внутри Drain, не обгонят прежде удержанный пакет (гарантия порядка — корень корректности туннелей переадресации). OOM так же точен: провал внутреннего резервирования DATA ставит соединение на HOLD; после освобождения памяти — `PacketRetry` — «OOM не фиксирует полупакет».

## Понятия

### Соединение и бюджет тайм-аутов

```diagram flow
- Сборка: ConfigInit + ClientInit -> таблица событий уходит в NetStreamConnect (или Attach на готовом потоке)
- TCP открыт: привязка Worker (scratch каналов/управляющих сообщений подключается к пулу буферов только теперь)
- ReadyTimeout (умолчание 30с, микросекунды) покрывает: обмен версиями -> KEX -> доверие хоста -> аутентификацию
- Ready: SSH пригоден - стартовая точка каналов/переадресации
- Ошибка/тайм-аут: структурированная ошибка (XSSH_ERROR_TIMEOUT/XERR_TIMEOUT/домен) достигает Error/Close/всех ожидающих Future одновременно
- Сторона TCP: дедлайн DNS/установления - в xnetdialconfig.Timeout (управляется независимо)
```

### Три точки взаимодействия

- **Доверие хоста**: по умолчанию **отказ** — после возврата HostKey ядром DEFER приложение получает момент решения через событие `HostKey` и отвечает `xrtSshClientHostKeyAccept/Reject` (двухшаговое доверие глав 122/123 в клиентской интерактивной форме — событие не синхронное суждение внутри callback: можно сверить хранилище, спросить пользователя, проверить по внешнему каналу и решить асинхронно).
- **Аутентификация**: возврат провайдером NEED_MORE вызывает событие `Authenticate` — когда учётные данные готовы (спросили пользователя/взяли у агента), продолжает `xrtSshClientContinue` (асинхронный уст методов главы 124).
- **Аварийный выход Packet**: callback `Packet` исполняется до фиксации низлежащей read-транзакции — полная способность обработки неизвестных расширений протокола и собственных типов каналов (разбор переадресации главы 126 висит ровно здесь) — **клиент неизвестных сообщений не глотает**.

### Пути данных и управляющих сообщений

`xrtSshClientSend` — быстрый путь нагрузки: добавляется только SSH-кодирование пакета + один перенос владения в TCP-очередь (ноль транзитных копий). `xrtSshClientBuild` даёт растущее с нуля, переиспользуемое, с жёстким потолком непрерывное scratch для мутирующих управляющих сообщений (буфер построения собственных сообщений). Стандартные DATA/stderr сперва входят в staging канального I/O, после фиксации стреляет событие `Data` (приложение проверяет без копий или читает явно). **Глобальные ответы**: динамический ограниченный FIFO `GlobalReplies/ReplyReserve` в паре с событием Global (токен-корреляция — уже видели в главе 125).

### Каналы и финал жизненного цикла

`xrtSshClientChannelOpen` — **базовый вход для собственных типов каналов**: вызывающий пишет поля типа, клиент ведает динамической нумерацией/окнами/корреляцией ответов/фиксацией/откатом — классический session и helper direct-tcpip построены на нём (**вторая набор-состояний каналов не ведётся**). `ChannelFlush` строит из очереди отправки канала куски, совместно ограниченные «удалённым окном + max-packet + TCP-противодавлением» — слияние трёх бюджетных слоёв. Финал: `OwnsChannel` проверяет принадлежность (не отдать чужое соединение в очередь отправки); Drain/Abort идут по семантике главы 110.

## Контракты

- **Четыре «не»**: без скрытого Engine / без блокировки Worker / без преаллокации каналов и буферов сообщений / без второй машины состояний.
- **Сборка соединения**: таблица событий уходит в NetStreamConnect; готовый поток делает `ClientAttach` на Worker-владельце; scratch привязывается к пулу буферов Worker после открытия TCP.
- **Двухуровневый тайм-аут**: ReadyTimeout (умолчание 30с, ноль отключает) ведает версией→KEX→доверием→аутентификацией; Timeout у Dial ведает DNS/установлением — независимо.
- **Ready единственно**: состояние пригодности SSH публикуется только событием Ready; callback завершения Dial ≠ SSH готов.
- **Хост по умолчанию на отказ**: DEFER → событие HostKey → Accept/Reject решаются асинхронно.
- **Асинхронный уст аутентификации**: NEED_MORE → событие Authenticate → Continue.
- **Аварийный выход Packet**: исполняется до фиксации read-транзакции; полная способность для неизвестных расширений и собственных каналов; клиент неизвестных сообщений не глотает.
- **Пути отправки**: Send = быстрый путь без транзита; Build = переиспользуемый scratch; слияние трёх бюджетов в ChannelFlush.
- **Порядок Drain**: внутренние пакеты повторяются первыми; публикация лишь после фиксации транзакции и осушения очереди — новые сообщения не обгоняют.
- **Точность OOM**: полупакет не фиксируется; провал резервирования — HOLD; после освобождения PacketRetry.
- **Глобальные ответы**: динамический ограниченный FIFO + токен-коррелированное событие Global.

## Ловушки

### Ловушка 1: завершение Dial принято за готовность SSH

Симптом: в callback Dial сразу открывается канал — ошибка или падение; SSH ещё рукопожатается.

Причина: callback Dial означает лишь, что TCP поднялся; версия/KEX/доверие/аутентификация дальше — **Ready и есть сигнал готовности**.

```c bad
on_dial_done(...) {
	xrtSshClientChannelOpen(Client, "session", ...);  /* посреди рукопожатия: ошибка */
}
```

```c good
on_dial_done(...) { /* это только TCP - ждать Ready */ }
on_ready(...) {
	/* открывать каналы/слать запросы переадресации только здесь */
	xrtSshClientChannelOpen(Client, "session", ...);
}
```

### Ловушка 2: в событии HostKey забыли ответить (висит до тайм-аута)

Симптом: соединение застревает и в конце ReadyTimeout — событие никто не Accept/Reject-нул.

Причина: событие HostKey — точка решения, **требующая ответа** (отказ по умолчанию — защита от «не настроена политика доверия», а не «событие можно игнорировать»). После сверки хранилища/вопроса пользователю обязательно ответьте.

```c bad
on_host_key(...) {
	audit_log(Key);   /* записано, но не отвечено: соединение висит до тайм-аута */
}
```

```c good
on_host_key(...) {
	audit_log(Key);
	if ( known_hosts_check(Key) == TRUST ) {
		xrtSshClientHostKeyAccept(Client);
	} else {
		xrtSshClientHostKeyReject(Client);
	}
}
```

### Ловушка 3: бездумное употребление дефолтов бюджета каналов вокруг READY

Симптом: при целях в десятки тысяч конкурентности потолок 1024 каналов незаметно перехватывает — половина соединений не может открыть новые каналы; или наоборот — на встраиваемых целях нетронутые бюджеты давят память.

Причина: дефолты вроде `Channels.MaxChannels` — универсальные значения (контракт набора главы 125: «настраивать под нагрузку, на безграничный рост не полагаться») — параметры развёртывания не частное дело библиотеки.

```c bad
xrtSshClientConfigInit(&Config);   /* всё по умолчанию в продакшн */
```

```c good
xrtSshClientConfigInit(&Config);
Config.Channels.MaxChannels = my_model.channels;
Config.Channels.ReceiveWindow = my_model.window;
Config.GlobalReplyLimit = my_model.global_tokens;
/* объявить явно по модели нагрузки - бюджет есть контракт развёртывания */
```

## Упражнения

### Базовое: наблюдение машины состояний

Против реального SSH-сервера (локальный sshd или контейнер) напечатать последовательность событий целого соединения: Dial→(TCP)→версия→KEX→HostKey→аутентификация→Ready→канал→Close. Критерии приёмки: последовательность сходится с диаграммой этой главы; двухуровневые тайм-ауты срабатывают каждый независимо (эксперименты с короткими значениями).

### Продвинутое: асинхронное решение о доверии

В событии HostKey запустить асинхронную проверку (имитация внешней сверки с задержкой 200 мс) и затем Accept — проверка способности события решать асинхронно. Контраст с путём немедленного синхронного отказа. Критерии приёмки: тайминг Ready/Close обоих путей верен; соединение живёт на протяжении решения (без тайм-аута).

### Вызов: полноценный туннельный инструмент

Упражнение финальной сборки: Dial + аутентификация паролем + HostKey (интеграция known_hosts) + локальная переадресация (форма `-L`) + 3 конкурентных канала + грациозный Drain — пригодный мини ssh -L. Критерии приёмки: HTTP-запросы успешно ходят через туннель туда-обратно; три канала конкурентно без помех; Ctrl-C запускает Drain, вся цепочка выходит чисто (сверка бюджетов и ссылок).
