## Ориентация

`xset` — контейнер, который «спрашивает только, есть ли оно тут»: добавления дедуплицируют, проверка принадлежности O(1), объединение/пересечение/разность/симметрическая разность вычисляются за один шаг. Он делит с `xmap` хеш-фундамент и итерацию по вставке, но смысловой центр тяжести иной — отображение заботится «на что отображается ключ», множество — «принадлежит ли ключ». Белые списки портов межсетевого экрана, группы тегов пользователей, разности прав, кодирование, дедуплицированный подсчёт — всё это задачи множеств. Главба вдавливает различие двух форм API — **`Unit` для стековых дескрипторов** против **`Destroy` для результатов операций** — дисциплина, которую стоит установить первой в главе о множествах.

## Введение

Шлюз решает, какие порты пропускать: администратор включил `{80, 443, 8080}`, приложение запрашивает `{3000, 443, 8080}` — допущенное множество есть **пересечение** `{443, 8080}`, и главный образец главы — полная реализация именно этой сцены. На массивах: два вложенных цикла с дедупликацией, полтора десятка строк, квадратичная сложность, и «дедупликация» сама по себе магнит багов. На множествах: `Add` для загрузки, `Intersection` за шаг, итерация с печатью — три порции по две-три строки. Главное — семантика явная: в коде стоит само слово «пересечение», рецензенту не нужно реверс-инжинирить намерение из вложенных циклов.

Форма возврата операций множеств заслуживает отдельного внимания: `Intersection` / `Union` / `Difference` / `SymmetricDifference` возвращают **выделенный в куче новый множество** (указатель `xset*`) — результат живёт независимо от операндов, его можно продолжать обрабатывать или итерировать; цена — обязательный `xrtSetDestroy` по завершении. А множества «для загрузки» — стековые дескрипторы, уборка `xrtSetUnit`. Два вида объектов — две уборки; перепутать — утечка или висячий указатель; ловушка 1 занимается именно этим, а cleanup-сегмент образца, где обе уборки стоят рядом, — каноническая форма, которую стоит целиком унести в копилку.

### Изоморфизм с отображением

Фундамент множества — та же основа, что у `xmap`: хеш-локация, цепь порядка вставки, трёхчастная итерация (`Begin`/`Next`/`End`) — всё совпадает. Различий два: нет значения (элемент и есть ключ) и есть семейство операций алгебры множеств. Придя из главы 18, вам нужен только инкрементальный блок «алгебры» — две главы делят большую часть ловушек и контрактов (срок действия указателей итерации, запрет правок в середине).

### Алгебра множеств

| Операция | Результат | Типовой вопрос |
| --- | --- | --- |
| `Intersection` | элементы в обоих | запрошено ∩ включено = реально допущено |
| `Union` | объединение обоих | слияние двух групп тегов |
| `Difference` | в левом нет в правом | настроено − выполнено = к выполнению |
| `SymmetricDifference` | ровно в одном | сверка двух конфигураций |

Общий контракт всех четырёх: **возвращают новые выделенные в куче множества**, порядок итерации результата наследует порядок вставки **левого операнда**. Результаты могут цепочкой входить в следующую операцию — многошаговая политика «сперва объединить, потом пересечь» пишется по одной операции на строку естественно.

### Поток данных операций множеств

Одно вычисление политики — обычно несколько алгебр подряд; нарисованный поток данных нагляднее чтения кода:

```diagram flow
- Загрузка: две группы исходных ID каждая Add в своё множество (дедупликация достаётся бесплатно)
- Пересечение: запрошено ∩ включено - пропускается лишь то, чему обе стороны кивнули
- Разность: кандидаты - чёрный список - дополнительное отсечение из пересечения
- Вывод: итерация итогового множества в порядке вставки левого операнда, воспроизводимо построчно
```

Заметьте: продукт каждого шага — независимое кучевое множество; промежуточные результаты `Destroy`-ятся сразу по использовании, итоговый получает свой `Destroy` после итерации. Уборку цепочечных операций лучше писать рядом с операциями (вычислил — убрал), избегая списка «сперва всё посчитать, потом единообразно убрать» — последний на ошибочных путях пропускает Destroy чаще.

### Значимая семантика и сравнение

Элементы — **значения**: `Add` копирует байты элемента в слот, `sizeof(元素类型)` объявляется при `Init`. Равенство элементов — побайтовое равенство; структуры с набивкой сперва обнуляются (иначе одинаковое значение с разной набивкой судится неравным). Хранить указатели можно, но множество сравнивает значения указателей, а не объекты по адресу — «множество тождеств объектов» и «множество значений объектов» — разные вещи; нужно второе — берите бизнесовый ключ (скажем, ID) элементом.

### Итерация и запросы

`Has` судит принадлежность, `Remove` удаляет элемент, `Count` — публичное поле — три соглашения контейнера (глава 14) действуют дословно. Итерация выводит в порядке вставки и точно воспроизводится; образец `set_tour` дополнительно показывает обратную итерацию и обход в стиле посетителя (callback-форма) — обе того же корня, что и прямая трёхчастная.

Из репозиторного образца `examples/containers/set/main.c`:

```term
$ gcc -O1 -DXRT_MODULE_ALL -I single impl.c examples/containers/set/main.c -lws2_32 -liphlpapi
allowed port: 443
allowed port: 8080
```

**Что только что произошло.** (1) Два множества со стековыми дескрипторами, каждое `Init(sizeof(int))`, загружаются циклами `Add` — 3000 есть в запрошенном, но не во включённом; его судьба решена уже на пересечении. (2) `Intersection(&tRequested, &tEnabled)` возвращает кучевое множество `pAllowed` — заметьте, это указатель, другой вид объекта, нежели стековый дескриптор `tRequested`. (3) Итерация выводит 443, 8080 в порядке вставки **левого операнда** (запрошенного множества) — порядок результата воспроизводим и годится в тестовые утверждения. (4) Уборка — дисциплинарная сцена главы: `pAllowed` — результат операции, `Destroy`; `tRequested`/`tEnabled` — стековые дескрипторы, `Unit` — ни одну из двух уборок нельзя перепутать, и обе на месте в `goto cleanup` ошибочного пути.

### Вторая полная программа: полный тур по интерфейсу множества

Из `examples/containers/set_tour/main.c`, покрывая жизненный цикл, запросы, алгебру и два стиля обхода:

```embed path="examples/containers/set_tour/main.c" title="examples/containers/set_tour/main.c"
```

```term
$ gcc -O1 -DXRT_MODULE_ALL -I single -include xrt.h impl.c examples/containers/set_tour/main.c -lws2_32 -liphlpapi
set: lifecycle count=2 cap>=2 trim=1 clear=0
set: queries get-or-add new=0/1 has=1/0 remove=1
set: algebra union=4 diff=2 sym=2 subset/super/disjoint
set: rbegin order=3..1 visit=stopped
```

**Что только что произошло.** (1) Строка жизненного цикла: публичное поле `Count`, ёмкость `Reserve`/`Trim` (трёхчастный набор ёмкости главы 14 на множествах — те же имена и смыслы), `Clear` в ноль. (2) Строка запросов: у множеств тоже есть форма `GetOrAdd` (подтвердить существование и различить старое с новым), `Has` и `Remove` проверены парами успех/неудача. (3) Строка алгебры: счёт результатов объединения, разности и симметрической разности утверждается по одному, плюс суждения подмножество/надмножество/непересечение — проверка отношений не выделяет новое множество и возвращает булевы значения напрямую. (4) Строка обхода: обратная итерация (`3..1`) и посещение в callback-стиле (с возможной остановкой — `visit=stopped` доказывает семантику прерывания возвратом false) — два варианта трёхчастной, берите по сцене.

### От образцов к инженерии: три точки приземления множества

Белый список портов — «безопасность»; ещё две точки не менее часты. **Теги и группировки**: группа пользователей несёт несколько тегов, один тег покрывает нескольких пользователей — «пользователи с тегами A и B одновременно» — пересечение, «A без B» — разность; система тегов по существу — комбинаторика операций множеств. **Таблицы законных переходов автомата состояний**: пары «текущее состояние × вход → законно» делаются множеством, и проверка законности перед переходом — один `Has` — незаконные переходы табулируются на этапе проектирования, а не рассыпаны по цепочкам if. Три точки делят API главы; различие лишь в типе элемента и комбинациях операций — множество самый «бизнесовый по вкусу» контейнер тома 3, и выбирают его часто не ради производительности, а чтобы в коде стояли сами бизнесовые слова — пересечение, объединение, разность.

## Контракты

- **Две уборки**: стековые дескрипторы `Unit`; результаты операций и продукты `Create` `Destroy` — какая уборка у множества, зависит от того, как оно родилось.
- **Независимость результата**: пересечение и родня не зависят от выживания операндов; результат остаётся действительным и после уничтожения операндов.
- **Порядок результата**: результаты алгебры наследуют порядок вставки левого операнда; весь вывод итераций воспроизводим.
- **Равенство значений**: побайтовое равенство — равенство элементов; набивку структур обнулять сперва; элементы-указатели сравниваются по значениям указателей.
- **Дисциплина итерации**: та же, что у `xmap` — три части, указатели итерационного периода не покидают итерацию, запрет правок в середине.
- **Инженерные точки**: белые списки/группировки тегов/таблицы переходов — в коде множеств стоят сами бизнесовые слова.

### Привычка чтения кода множеств

Операции множеств укорачивают код, но делают «промежуточные продукты» невидимыми — три операции цепочкой в одной строке означают три временных множества, живущих в куче одновременно. Вырабатывайте привычку: увидев `Intersection`, про себя скажите «одно кучевое множество»; увидев цепочку — пересчитайте промежуточные. В паре со статистикой главы 6 сделайте проверку: прогоните логику, плотную по множествам, и посмотрите, пилообразная ли кривая активных байтов (пары выделение-освобождение), а не лестница (только вверх) — пила здорова, лестница течёт; это чтение на порядок быстрее построчной ревизии.

## Ловушки

### Ловушка 1: уборка результата операции через Unit

Симптом: утечка памяти (в статистике главы 6 объём утечки пропорционален числу операций) либо, наоборот, `Destroy` стекового дескриптора с падением.

Причина: `Unit` возвращает только хранилище, связанное со стековым дескриптором, и не освобождает кучевые объекты; `Intersection` и родня возвращают независимые кучевые множества — функции уборки взаимозаменяемыми не являются.

```c bad
xset* pAllowed = xrtSetIntersection(&tRequested, &tEnabled);
/* ... используем pAllowed ... */
xrtSetUnit(pAllowed);            /* Unit не освобождает кучевое множество - утечка */
```

```c good
xset* pAllowed = xrtSetIntersection(&tRequested, &tEnabled);
/* ... используем pAllowed ... */
xrtSetDestroy(pAllowed);          /* результат операции: Destroy */
xrtSetUnit(&tRequested);          /* стековый дескриптор: Unit */
xrtSetUnit(&tEnabled);
```

### Ловушка 2: не обнулённая набивка элементов-структур (баг-призрак, дрейфующий с компилятором)

Симптом: «явно равные элементы» то равны, то нет; во множестве появляются «повторные» элементы; поведение дрейфует с компилятором и уровнем оптимизации.

Причина: байты структуры включают вставленную компилятором набивку; две логически одинаковые структуры с разной набивкой побайтово неравны.

```c bad
typedef struct portspec { short Port; int Enabled; } portspec;   /* с набивкой */
portspec A; A.Port = 443; A.Enabled = 1;                          /* набивка не тронута */
xrtSetAdd(&tSet, &A);                                             /* входит во множество со случайной набивкой */
```

```c good
portspec A;
memset(&A, 0, sizeof(A));          /* сперва обнулить, потом присвоить - набивка детерминирована */
A.Port = 443; A.Enabled = 1;
xrtSetAdd(&tSet, &A);
```

## Упражнения

### Базовое: дедуплицированный подсчёт

Загрузите группу ID с повторами во множество, выведите `Count` и список дедуплицированных элементов; затем сравните объём кода и порядок вывода с «сортировкой-дедупликацией» массива из главы 14 (массивный способ выводит сортированно, множественный — в порядке вставки; придумайте по одному сценарию обслуживания на каждый порядок).

### Продвинутое: трёхслойная фильтрация прав (цепочечная комбинация алгебры)

Три группы ID (группа пользователей, таблица прав, чёрный список); пересечением и разностью вычислите итоговое множество «есть право и не в чёрном списке»; сделайте утверждения корректности на масштабе 1000 случайных ID на слой. Подсказка: результат пересечения продолжает входить в разность.

### Вызов: сверятель конфигураций (симметрическая разность + аннотация принадлежности)

Прочитайте две портовые конфигурации (можно захардкодить), выведите `SymmetricDifference` различающиеся порты с аннотацией «только в A / только в B» — подсказка: аннотация принадлежности требует до lookup-а в обоих исходных множествах. Критерии приёмки: на трёх конфигурациях с известными различиями вывод построчно совпадает с ожиданием; все результаты операций `Destroy`-нуты, статистика подтверждает ноль утечек.

## Шпаргалка

| Тема | Кратко |
| --- | --- |
| Загрузка | `Init(sizeof(元素))` + `Add` (дедупликация бесплатно); `Has`/`Remove`/`Count` читаются из публичного поля |
| Алгебра | пересечение/объединение/разность/симметрическая возвращают **кучевые множества** (уборка `Destroy`); порядок — от левого операнда |
| Суждение отношений | подмножество/надмножество/непересечение возвращают булевы напрямую — без выделений, без промежуточных множеств |
| Равенство значений | побайтовое; набивку структур обнулять сперва; элементы-указатели сравниваются по значению указателя |
| Итерация | трёхчастная + обратная + callback с прерыванием — три позы обхода, вывод весь воспроизводим |
| Отношение к map | тот же фундамент и дисциплина; множество = отображение без значений + семейство алгебры |
| Поток алгебры | каждый шаг живёт независимо; «вычислил — убрал», ошибочные пути не пропускают Destroy; промежуточные множества умирают по использовании |
| Правила отношений | пересечение = в обоих; разность = в левом; симметрическая = ровно в одном; порядок результата — всегда порядок вставки левого операнда |
