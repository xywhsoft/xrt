## Ориентация

Случайные возможности XRT делятся на четыре слоя, у каждого своё место: слой **Secure** идёт к источнику энтропии операционной системы (`xrtSecureRandom` — только для ключей и токенов); слой **глобального Rand** — потоколокальное умолчание; слой **Fast** ставит скорость вперёд, не безопасность; слой **экземпляров RNG** сеется явно и полностью воспроизводим (`xrng`). Глава проясняет выбор слоя и пришпиливает одну красную линию: **PCG и семейство Fast не криптографически стойки** — токены, ключи и nonce обязаны идти через слой Secure. Воспроизводимость на фиксированном сеянии — другая тема: снапшоты тестов и системы повторов стоят на «одно семя — одна последовательность».

## Введение

Два внешне противоречивых требования сосуществуют. В играх и симуляции вам нужна случайность **воспроизводимая** — тот же матч, тот же сейв при загрузке, последовательность случайных событий обязана совпадать, иначе запись-повтор и сетевая синхронизация отказывают целиком; в безопасности вам нужна случайность **непредсказуемая** — угаданный сессионный токен равен угнанному аккаунту. Эти два дела инженерно несут разные механизмы: первое — явно сеянный псевдослучайный генератор (одно семя — одна последовательность), второе — источник энтропии ОС (`xrtSecureRandom`).

Частая ошибка — смешивать их: посеять быстрый генератор временем и генерировать токены — время угадываемо, генератор предсказуем, два слоя защиты дают ноль. XRT режет этот класс ошибок явными именами: `Rand`/`FastRand`/`Rng` с первого взгляда статистические, `SecureRandom`/`SecureText` с первого взгляда охранные, а документация модуля прямо гласит «граница безопасности обязана использовать Secure». Имя есть документация — на ревью кода не нужно лезть в реализацию; одно имя функции завершает половину охранного аудита.

## Понятия

### Четырёхслойная система и выбор

```diagram flow
- Secure: xrtSecureRandom / SecureText, энтропия ОС — единственный легитимный источник ключей, токенов, nonce
- Глобальный Rand: xrtRand64 и др., потоколокальное умолчание — бизнес-выборки, демо, имитация нагрузки
- Fast: xrtFastRandSeed и др., скорость вперёд не безопасно — впрыск дрожания в горячих путях, графический шум
- Экземпляр RNG: xrng + посев, явное воспроизводимое состояние — снапшоты тестов, запись-повтор, параллельные независимые потоки
```

Выбор задаёт только два вопроса: **нужна непредсказуемость?** Да → Secure, конец. **Нужна воспроизводимость?** Да → экземпляр RNG (явное состояние, явное семя). Ни то ни другое → глобальный Rand ради удобства, Fast — для подтверждённых чувствительных к производительности горячих путей. Префиксы имён четырёх слоёв взаимооднозначны этим ответам — на ревью видно с первого взгляда.

Добавьте список-ощущение «какой слой для какого сценария»: генерация сессионных токенов → `SecureText`; броски выпадения в игре → экземпляр RNG (требование повтора); возмущение трафика в нагрузочном тестировании → глобальный Rand; шум графических частиц → Fast; временные имена файлов → `SecureText` или XID (глава 12); точки внедрения сбоев в тестах → экземпляр RNG (семя есть номер тест-кейса). Список растёт с проектом, но каждый новый пункт обязан отвечать на один из тех двух вопросов.

### Экземпляр RNG: явное состояние и номер потока

`xrng` — структура состояния, которую можно положить куда угодно: стековую переменную, поле структуры, кусок байтов в файле сохранения. `xrtRngSeed(&Rng, 种子, 流序号)` сеет (семя, номер потока — дословные токены ниже): **одно семя, разные номера потока дают взаимно независимые последовательности**. Этот второй параметр решает классическую ловушку: два генератора на одном семени дают полностью коррелированный вывод — когда сервер выдаёт каждой сессии по RNG, номер сессии как номер потока гарантирует нескоррелированность. Семейство генерации покрывает целые (`Rng32`/`Rng64`), плавающие (`RngReal`, [0,1)), ограниченные целые (`RngRangeClosed`, замкнуто-замкнутый интервал — бросок кости `1..6` включая 6), заполнение байт (`RngBytes`) и тасование на месте (`RngShuffle`, Фишер-Йетс).

### Глобальный слой и потоки

Глобальные функции вроде `xrtRand64` используют **потоколокальное** состояние — конкурентные вызовы из многих потоков без блокировок и без взаимных помех последовательностям. Слой подходит под «быстро дайте случайное число»; когда последовательность должна быть согласована между вызовами (одна и та же логика при перезапуске — тот же результат), возвращайтесь к экземпляру RNG. Семейство Fast (`xrtFastRandSeed` для посева, `xrtFastRand32` для выборки и др.) — сперва-скоростная реализация без охранных гарантий, для подтверждённых экстремально-производительных неохранных сценариев.

### Случайный текст и алфавит

`RandText` / `RandStringFrom` / `SecureText` генерируют случайные строки: можно задать набор символов (например, только однозначные `23456789abcdefghjkmnpqrstuvwxyz`) для приглашительных кодов, временных имён каталогов и сессионных токенов. Охранным сценариям соответствуют `SecureText` и `SecureStringFrom` — они стоят на `xrtSecureRandom`, и непредсказуемость случайного текста тождественна байтовой.

Пользовательский алфавит — не только красота: исключая похожие `0O1lI`, приглашительные коды перестают ошибочно переписываться пользователями; ограничиваясь URL-безопасным набором, токен входит прямо в ссылки и QR-коды. Длина генерации задаётся вызывающим, а неудача (источник энтропии недоступен) так же объявляется возвращаемым значением — неудачи на охранном пути никогда не глотаются молча.

### Инженерные применения воспроизводимости

У воспроизводимой случайности три частых места приземления. **Снапшоты тестов**: семя записывается в фикстуру теста, ассертится хеш сгенерированной последовательности (глава 12) против записанного отпечатка — регрессионное тестирование случайной логики из «на удачу» становится точным утверждением. **Запись-повтор**: хранится только семя и последовательность операций; при повторе генерационные вызовы исполняются заново, случайные события покадрово совпадают. **Внедрение сбоев**: RNG решает точки внедрения (в паре с FailAfter главы 6 для смешанных режимов отказов), семя — номер тест-кейса: повтор неудачного прогона не меняет результат. Общая дисциплина трёх мест: **порядок генерационных вызовов — тоже состояние** — пропустите один `Rng32` при воспроизведении, и всё после сдвинется.

### Чтение трёх классов утверждений случайных тестов

Перед прогоном примеров зафиксируем, как тестируется случайный код — оба примера ассертят из этих трёх классов. **Утверждения воспроизводимости**: одна и та же генерация дважды с одним семенем — результаты поэлементно равны (или равны хеш-отпечатки). **Утверждения ограниченности**: значения попадают в заявленный интервал, включая оба конца замкнутого интервала, каждый минимум по разу. **Утверждения распределения**: на больших выборках частоты близки к ожиданию (`Near` главы 10 по относительному отклонению). Три класса каждый на своём посту: воспроизводимость гарантирует определённость, ограниченность — семантику, распределение — качество; писав только один класс, вы упускаете дефекты соответствующего измерения.

## Примеры

### Полная программа: всё семейство явного RNG

Из примера репозитория `examples/math/random/main.c` — фиксированное семя, без глобального состояния, вывод полностью воспроизводим:


```term
$ gcc -O1 -DXRT_MODULE_ALL -I single impl.c examples/math/random/main.c -lws2_32 -liphlpapi
explicit: 4207372542
dice    : 6
real    : 0.219369470187
bytes   : 8641
shuffle : 2 1 6
```

**Что только что произошло.** (1) `xrng Rng` — локальное состояние на стеке: кто объявил, тот и держит; положить в структуру, по одному на сессию, сохранить в файле повтора — одна и та же форма. (2) `xrtRngSeed(&Rng, 2026, 7)`: семя 2026, номер потока 7; эти полсотни байт последовательности отныне полностью определены — любая машина в любое время даст эти пять строк вывода — краеугольный камень снапшотов тестов и записи-повтора. (3) Пять генерационных функций **последовательно продвигают одно состояние**: взятое раньше целое влияет на брошенную позже кость — воспроизводя последовательность, порядок вызовов тоже обязан совпадать. (4) `RngRangeClosed(&Rng, 1, 6)` — замкнуто-замкнутый интервал; броску кости больше не нужно `1 + x % 6` (двойная ловушка полузамкнутого интервала плюс смещение остатка). (5) `RngShuffle` — тасование на месте: массив всё тот же, порядок равномерно перемешан Фишером-Йетсом; «равномерно» не риторика — каждая перестановка равновероятна, и это объект проверки распределения в упражнениях главы.

## Контракты

- **Красная линия безопасности**: ключи, токены, пароли, nonce, временные имена ресурсов и вся граница безопасности **обязаны** использовать `xrtSecureRandom` / `SecureText`; `Rng`/`Rand`/`FastRand` — всё статистическое, заявлено вдвойне документацией и именованием.
- **Контракт воспроизводимости**: одно семя (с номером потока) и одна последовательность вызовов → один вывод, стабильно кроссплатформенно и межверсионно (согласованность `xrtMath` поддерживает снизу).
- **Независимые потоки**: много экземпляров на разных номерах потока взаимно независимы; одно семя и один поток = полностью коррелированная копия — перед параллельной симуляцией сверьте строки посева.
- **Потоки**: глобальный Rand потоколокален, конкурентность без блокировок; экземпляр RNG принадлежит области видимости, объявившей его, межпоточное разделение требует своей синхронизации.
- **Семантика интервалов**: `RngRangeClosed` замкнуто-замкнут (включая оба конца); самописное `x % n` несёт смещение остатка — не надо.
- **Порядок есть состояние**: воспроизводя последовательность, виды и порядок генерационных вызовов обязаны точно совпадать с записью.

## Ловушки

### Ловушка 1: генерация охранных токенов статистической случайностью

Симптомы: аудит безопасности помечает токены предсказуемыми; в принципе атакующему достаточно наблюдать немного выходов, чтобы восстановить внутреннее состояние и вычислить все последующие токены.

Причина: PCG и семейство Fast — статистические; воспроизводимость и непредсказуемость проектно противоположны — первая обрекает вторую.

```c bad
xrng Rng;
xrtRngSeed(&Rng, (uint64)time(NULL), 1);   /* время угадываемо */
xrtRngBytes(&Rng, Token, sizeof(Token));   /* PCG предсказуем — токен для вида */
```

```c good
uint8 Token[16];
if ( !xrtSecureRandom(Token, sizeof(Token)) ) {
	return false;                            /* отказ энтропии обрабатывается как отказ */
}
/* по завершении xrtSecureZero(Token, sizeof(Token)) (глава 5) */
```

### Ловушка 2: два RNG на одном семени

Симптомы: в параллельной симуляции множество «независимых» случайных потоков сильно коррелированы — порядки колод одинаковы, паттерны нагрузки синхронны, статистические выводы искажены.

Причина: одно семя и один номер потока дают **в точности одну** последовательность; «много экземпляров» само по себе не даёт «много последовательностей».

```c bad
for ( i = 0; i < 4; ++i ) {
	xrtRngSeed(&Workers[i].Rng, 2026, 1);  /* четыре воркера — одна последовательность */
}
```

```c good
for ( i = 0; i < 4; ++i ) {
	xrtRngSeed(&Workers[i].Rng, 2026, (uint64)i + 1u);  /* номера потока разделяют течения */
}
```

## Упражнения

### Базовое: снапшот воспроизведения

Возьмите десять целых подряд с фиксированным семенем и напечатайте; перегоните с другим номером потока, сравните — последовательности различны; верните исходное семя и перегоните, ассертя поэлементное совпадение с первым разом. Напоследок снимите отпечаток десятки через `Hash64` главы 12 — будущая регрессия этого теста сверяет одно 64-битное значение.

### Продвинутое: проверка распределения костей

Бросьте `RngRangeClosed(&Rng, 1, 6)` сто тысяч раз, просуммируйте частоты 1–6 и проверьте `Near` главы 10, что относительное отклонение каждой грани от ожидания (сто тысяч на шесть) меньше одного процента. Затем контроль: нарочно генерируйте через `1 + (int)(xrtRng32(&Rng) % 6)` и посмотрите, приемлемо ли отклонение всё ещё — прочувствуйте, является ли «смещение остатка» реальной проблемой в малых диапазонах, и запишите вывод.

### Вызов: скелет системы повторов

Спроектируйте минимальный повтор матча: семя открытия (с номером потока) и последовательность действий игрока сохраняются; «повтор» исполняет семя и действия заново, ассертя каждое случайное событие (каждое выпадение, каждый бросок) в поэлементном согласии с живой записью. Критерий приёмки: сейвы двух разных семён повторяются каждый самосогласованно и различно между собой; один и тот же сейв дважды даёт поэлементно одинаковый результат.

## Шпаргалка

| Тема | Краткая справка |
| --- | --- |
| Четыре слоя | Secure (энтропия) / глобальный Rand (потоколокальный) / Fast (скорость) / экземпляр RNG (воспроизводимость) |
| Красная линия | токены, ключи, nonce — только `SecureRandom` / `SecureText` |
| Посев | `RngSeed(&Rng, 种子, 流序号)`; разделение течений номером потока |
| Интервал | `RngRangeClosed` замкнуто-замкнут с концами; `x % n` отвергнуто |
| Воспроизведение | одно семя и порядок вызовов → один вывод; порядок вызовов — тоже состояние |
| Текст | `SecureStringFrom` генерирует токены из пользовательского алфавита; исключение похожих символов бережёт от ошибочного переписывания |
