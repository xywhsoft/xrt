## Ориентация

Время выглядит просто, но ямы глубже всех: потеря точности у секунд с плавающей точкой, лабиринт перехода на летнее время у поясов, «прибавить месяц» — это 30 дней или календарный перенос. Модуль time библиотеки XRT отвечает тремя решениями: **целочисленная микросекундная магистраль** (`xtime` — это int64 микросекунд: сравнение и разность без ошибок плавающей точки, бесшовный стык с системой тайм-аутов и дедлайнов), **фиксированные смещения поясов** (`xrtTimeSplitAt(+8×3600)` разлагает по смещению — без сложности летнего времени, покрывает большинство серверных сценариев) и **календарная семантика вычислений** (`xrtTimeAdd` переносит по единицам месяц/день: 31 августа + 1 месяц = 30 сентября, а не прибавление 30×86400 секунд).

## Введение

Три классических бага. Первый: время хранится в double-секундах — ошибка плавающей точки `0.1 + 0.2` (глава 10) растягивается на оси времени в «таймер изредка срабатывает на микросекунду раньше или позже» и случайно переворачивает сравнение с дедлайном. Второй: сервер показывает журналы в «местном поясе» — узлы в разных поясах дают нестыкующиеся метки, порядок межузловых событий не восстановить — первая потребность распределённой отладки падает здесь же. Третий: подписка «плюс месяц» приближена 30 днями — продление с 31 января попадает на 2 марта, и жалобы пользователей приходят вместе с отделом сверки.

Противоядия, соответственно: целые микросекунды (слой представления убивает плавающую точку), хранение в UTC + показ с фиксированным смещением (слой хранения убивает двусмысленность поясов), календарный перенос (слой вычислений убивает двусмысленность длины месяца) — по дисциплине на слой, и дисциплины стоят запоминания больше, чем API. Все функции модуля time стоят на этих трёх дисциплинах — поняв дисциплины, вы почти сами выводите имена API; наоборот, зубрёжка API без дисциплин оставляет каждую аварию зоны ловушек ждать вас.

## Понятия

### Представление: целые микросекунды

`xtime` — это int64 микросекунд (не double-секунды и не структура) — причины выбора: **сравнение без ошибок** (вердикты таймеров и дедлайнов — горячий путь; опрокидывание границы при сравнении плавающих недопустимо), **разность — просто вычитание** (измерение длительности `t1 - t0` сразу даёт микросекунды), **запас широты** (int64 микросекунд покрывает около 290 тысяч лет — от большого взрыва до далёкого будущего хватает). `xrtNow()` берёт текущий момент, `xrtClock()` — монотонные часы (образец clock главы 10 использует их для измерения длительности: монотонные часы не зависят от скачков системного времени; для хронометража — всегда они).

### Разложение: UTC и фиксированное смещение

```diagram flow
- Хранение и вычисления: всегда UTC-микросекунды - единая однозначная ось времени
- Разложение для показа: xrtTimeSplit по UTC; xrtTimeSplitAt(смещение_в_секундах) по целевому поясу
- Фиксированное смещение: +8×3600 - это UTC+8 - без таблиц летнего времени, кроссплатформенно согласованно
- Разделение человека и машины: машины обмениваются целыми микросекундами; разложение в читаемую форму - в последний момент
```

Фиксированное смещение пояса — **намеренное упрощение** (по-инженерному — «обмен полноты на объяснимость»): большинству серверных сценариев (метки журналов, даты отчётов) нужен один фиксированный сдвиг; полная библиотека поясов (база IANA, правила летнего времени) покупает свою сложность бременем обновления правил дважды в год. Когда нужны сложные пояса — подключайте на слое показа инфраструктуру поясов хоста; слой хранения остаётся на UTC-микросекундах непоколебимо.

### Календарная арифметика: семантика переноса

`xrtTimeAdd(时间, 数量, 单位, 出参)` (время, количество, единица, выходной параметр) переносит по календарной семантике: **усечение на конце месяца** (31 августа + 1 месяц → 30 сентября, а не 1 октября), **корректные високосные годы** (28 февраля + 1 год → 28 февраля следующего, в високосном — 29-е; по фактическому календарю года). Сравните принципиальную разницу с «приближением в секундах» (+30×86400): приближение завышает в 31-дневных месяцах и занижает в феврале, дрейфуя весь год — длина календарного месяца это **человеческое соглашение**, а не физическая величина; продления подписок, биллинговые циклы, напоминания в календаре — всем нужна календарная семантика. Физические длительности (тайм-ауты, интервалы, троттлинг) — это сложение и вычитание микросекунд — **два рода вычислений не смешивать**: календарные единицы — людям, микросекунды — машинам.

### Форматирование и разбор (последняя станция слоя показа)

Взаимные превращения времени и текста (ISO 8601 как основной формат) одной крови со строгой семантикой главы 26: разбор — либо весь вход легален, либо отказ; форматирование — по объявленной раскладке. Префикс времени `{&path:%F}` шаблонов главы 35 использует именно этот движок форматирования — формат показа объявляется на слое шаблона, значение времени всегда остаётся целым числом микросекунд.

### Полная программа: магистраль в четыре шага

Из образца репозитория `examples/time/basic/main.c` — текущий момент, разложение, смещение и календарное сложение одним заходом:

```embed path="examples/time/basic/main.c" title="examples/time/basic/main.c"
```

```term
$ gcc -O1 -DXRT_MODULE_ALL -I single impl.c examples/time/basic/main.c -lws2_32 -liphlpapi
unix_us=1788573693834602
utc=2026-09-05 02:01:33.834602
utc+8=2026-09-05 10:01:33
next_month=1791165693834602
```

**Что только что произошло.** (1) `xrtNow()` возвращает целое число микросекунд — первая строка вывода и есть форма хранения (человеку нечитаемо, машине милее всего: сравнимо, вычитаемо, сериализуемо). (2) `xrtTimeSplit` разлагает по UTC на календарные поля и форматирует в `2026-09-05 02:01:33.834602` — микросекундная точность сохранена. (3) `xrtTimeSplitAt(+8×3600)` разлагает тот же момент по поясу UTC+8 — `10:01:33`: **момент не изменился, показ изменился** — вот и всё «хранение в UTC + показ со смещением». (4) `next_month` ровно на один календарный месяц позже текущего — разность в микросекундах не кратна фиксированным 30 дням, это и есть эмпирическое доказательство семантики переноса на конце месяца: длина календарного месяца меняется от месяца к месяцу, сложение идёт по человеческому календарю.

### Полная программа: хронометраж монотонными часами

Из `examples/time/clock/main.c` — правильная поза измерения длительности:

```embed path="examples/time/clock/main.c" title="examples/time/clock/main.c"
```

```term
$ gcc -O1 -DXRT_MODULE_ALL -I single impl.c examples/time/clock/main.c -lws2_32 -liphlpapi
elapsed_us=14695
elapsed_s=0.014727
```

**Что только что произошло.** (1) `xrtClock()` — монотонные часы: коррекция NTP и смена системного времени пользователем на них не влияют, **для хронометража — всегда они** (`xrtNow` загрязняется скачками: измерение, пересёкшее шаг NTP, может выйти отрицательным). (2) Разность в микросекундах получается прямым вычитанием; перевод в секунды — дело слоя показа (деление на 1e6 — строки формата главы 26 тоже умеют). (3) Фактические значения плавают с планированием (около 10~15 мс, нижний порог утверждения 10000 мкс), но монотонность гарантирована — ровно то свойство, которое нужно бенчмаркам (контрольные эксперименты главы 23).

## Контракты

- **Целые микросекунды**: хранение, передача и вычисления — всегда `xtime`-микросекунды; плавающие секунды в слой хранения не входят.
- **Магистраль UTC**: машины обмениваются UTC-микросекундами; разложение для показа — со смещением по надобности; смещение — параметр показа, а не атрибут хранения.
- **Монотонные часы**: длительности измеряет `xrtClock` (не зависит от коррекции); `xrtNow` отвечает только «который час».
- **Календарный перенос**: `xrtTimeAdd` усекает на конце месяца, високосные годы по фактическому календарю; календарные единицы — людям, микросекунды — машинам, без смешивания.
- **Разделение форматирования**: машинный формат — целое число микросекунд; человеческий объявляется на слое показа (префикс шаблона/строка формата).

### От примеров к инженерии: три хозяина времени

**Метки журналов**: целое микросекунд `xrtNow()` идёт прямо в журнал (поле time JSON-Sink-а главы 39 — ровно эта форма) — хранение в UTC, при просмотре разложение по смещению смотрящего (хорошая форма ловушки 1 в полном виде).**Тайм-ауты и дедлайны**: семейство `xrtDeadlineAfter(微秒)` (микросекунды) (завсегдатай сетевых глав, глава 66) питается именно xtime — целые микросекунды бесшовно стыкуются с системой дедлайнов, и это дивиденд «целых на слое представления».**Бизнес-циклы**: подписки, биллинг и расписания — всё через календарную семантику `xrtTimeAdd`; правило усечения на конце месяца фиксируется в документации продукта («месячная подписка с 31 января списывается 28 февраля» — это определённое поведение, а не баг). Три хозяина отвечают трём ипостасям времени: **момент** (который час), **длительность** (сколько прошло), **цикл** (когда следующий) — у каждой ипостаси свой правильный инструмент, ипостась прежде API.

### Ментальная модель: трёхслойный взгляд на время

Представьте обработку времени тремя слоями — и большинство проектных решений станет очевидным. **Слой хранения**: целое UTC-микросекунд — единственное однозначное представление; сравнение, передача, индексация живут здесь. **Слой вычислений**: две колеи — физические величины (сложение/вычитание микросекунд: тайм-ауты, троттлинг, длительности) и календарные величины (перенос TimeAdd: циклы, расписания); колея выбирается по потребности, смешение колей запрещено. **Слой показа**: разложение + форматирование + смещение пояса — всё это «параметры рендеринга», которые никогда не текут обратно в хранение. Цена нарушения дисциплины любого слоя имеет экземпляр в зоне ловушек: смешение поясов в хранении (ловушка 1), смешение колей в вычислениях (ловушка 2), преждевременное разложение в показе (журнал хранит текст местного времени). Трёхслойный взгляд объясняет и то, почему поверхность API модуля time так мала — на каждом слое два-три действия, сложность поглощена дисциплиной слоёв.

### Приём тестирования времени

У кода со временем врождённая проблема тестирования: `xrtNow` каждый раз разный. Приём — **инъекция момента**: бизнес-функция принимает параметр xtime вместо внутреннего вызова Now — тесты передают фиксированные моменты (граничные дни вроде 2026-01-31 00:00:00 UTC), продакшен передаёт Now от вызывающего. Это изоморф «инъекции семени» случайных чисел главы 11: все источники недетерминированности внедряются на границе. Логика измерения длительности (бэкофф повторов, окна троттлинга) — так же: принимает параметр xtime, а в тестах вы вручную продвигаете «виртуальные часы» — скелет планировщика из упражнений главы 22 использует именно этот приём.

## Ловушки

### Ловушка 1: хранение времени журналов в местном поясе (параметры показа протекли в хранение)

Симптом: метки журналов разных узлов не сходятся; после развёртывания в разных поясах «одно и то же событие» расходится на часы; в день перехода на летнее время в журнале «повторяющийся час».

Причина: слой хранения впитал пояс слоя показа — «местное время» каждой машины это разные параметры показа.

```c bad
xtime Now = xrtNow();
xdatetime T;
xrtTimeSplitAt(Now, LocalOffset(), &T);   /* разложили по местному смещению и храним строку */
SaveLog("%04d-%02d-%02d ...", T.Year, ...); /* хранится "текст местного времени" - информация о поясе потеряна */
```

```c good
xtime Now = xrtNow();
SaveLog("%lld", (long long)Now);          /* храним целое UTC-микросекунд */
/* разложение только при показе: xrtTimeSplitAt(смещение по смотрящему) - пояс это параметр просмотра */
```

### Ловушка 2: приближение календарных вычислений секундами (смешение двух колей)

Симптом: циклы подписок/биллинга дрейфуют на концах месяцев — 31 января + 30 дней = 2 марта; на стороне пользователя «списали лишние два дня».

Причина: календарный месяц — не фиксированное число секунд; приближение «месяца» величиной 30×86400 ошибается и в 31-дневных месяцах, и в феврале.

```c bad
xtime Next = Now + 30LL * 86400 * 1000000;   /* "плюс месяц" = приближение в 30 дней */
```

```c good
xtime Next;
xrtTimeAdd(Now, 1, XTIME_UNIT_MONTH, &Next);   /* календарный перенос: 31.01 + 1 месяц = 28.02 */
```

## Упражнения

### Базовое: контраст двух поясов (один момент, два показа)

Возьмите текущий момент; разложите и напечатайте его по UTC и по смещению +8 — микросекундное значение у двух показов одно; затем посчитайте разницу в часах и проверьте смещение.

### Продвинутое: калькулятор продления подписки (календарная семантика наглядно)

Реализуйте `next_billing(当前, 周期月数)` (текущий, число месяцев цикла): сложение с календарным переносом; для месячной подписки, начатой 31 января, посчитайте двенадцать последовательных дат биллинга, наблюдайте усечение на конце месяца и выведите пояснение.

### Вызов: инструмент хронометража (монотонные часы + медиана)

Реализуйте `measure(函数, 次数)` (функция, число прогонов) на монотонных часах: разогрев N раз, затем официальный замер, медиана (идея допуска Near из главы 10 решает, «существенно ли одинаковы» два замера), вывод в микросекундах и в человекочитаемом виде. Измерьте им обход массива против списка из главы 23 — цифры должны быть того же порядка, что в экспериментах той главы.
