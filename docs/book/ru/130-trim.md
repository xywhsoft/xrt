## Ориентация

Глава 129 показала, как сборка компилирует комбинации обрезки; эта глава — о том, **как обрезка объявляется и как проверяется, что размер действительно уменьшился**. Три блока: **модель позитивного выбора** (`XRT_MODULE_*` объявляет только корневые модули, замыкание зависимостей разворачивается автоматически — «пользователю не нужно знать, от каких внутренних возможностей модуль зависит сейчас, и не следует копировать таблицу зависимостей»); **семантика исключения ALL+EXCLUDE** (`XRT_MODULE_ALL`+`XRT_EXCLUDE_MEMORY_DEBUG` — точное выражение «всё минус диагностика»; явные корневые модули приоритетнее исключений); **принцип гранулярности** (один публичный модуль = одна небольшая группа возможностей с общим состоянием/зависимостями/сценарием — без макросов на функцию и без общего рубильника; новая возможность сначала отвечает на три вопроса «можно ли независимо тестировать/обрезать/описать владение»). **Проверка размера**: профили `config/size_profiles.json` (каждый профиль — suite + таблица запрета `forbid_symbols`) с `tools/measure_size.py` — профиль core запрещает любые символы семейств регулярных выражений/сжатия/сети/протоколов — **обрезка — это не заявление, а проверенный факт**.

## Введение

Встраиваемая цель не вмещает всю библиотеку? Отрежьте ненужное — звучит просто, но у исторических реализаций три болезни: **рукописные таблицы зависимостей** (пользователь сам перечисляет все нужные макросы — внутренняя зависимость меняется, и у всех пользователей копии ломаются); **неявная полнота** (без выбора даём всё — «минимальная программа» тайно везёт TLS); **ложная гранулярность** (макросы на функцию — взрыв, которым никто не пользуется; или один общий макрос — обрезка превращается во всё-или-ничего). Три лекарства XRT: разворачивание замыкания (объявляем корень, разворачиваем зависимости — таблица ведётся в одном месте, внутри библиотеки); **без выбора = только Core** («когда не определён ни один XRT_MODULE_*, предоставляется только свободный от возможностей контракт Core» — минимальная интеграция предсказуема, новые модули незаметно не увеличивают существующие программы); **три вопроса гранулярности** (независимое тестирование/независимая обрезка/независимо описываемое владение — всё три выполнены, только тогда новый модуль).

Дизайн `forbid_symbols` заслуживает акцента: профиль размера — не просто «собрать этот suite», он ещё **утверждает, что в артефакте нет чужих символов**: если в линковке профиля core всплывает символ семейства TLS (зависимость втащена по ошибке), measure падает сразу. Ошибки обрезки вскрываются на шлюзе, а не когда бинарник в проде уже располнел.

## Понятия

### Позитивный выбор и замыкание

```diagram flow
- Объявление: #define XRT_MODULE_STRING_SPLIT (корневой модуль) -> #include "xrt.h"
- Разворот: features.h разворачивает замыкание по манифесту - базовый string + split приезжают сами
  - пользователь не копирует таблицу зависимостей; эволюция внутренних зависимостей пользователю невидима
- Единица реализации: XRT_IMPLEMENTATION определяет ровно одна трансляция
- Согласованность: при модульной линковке все TU используют одинаковый набор модулей
```

**Дисциплина тайминга**: макросы выбора обязаны быть определены до первого include `xrt.h`/`features.h` — define после include недействителен (развёртывание уже произошло).

### Семантика ALL и EXCLUDE

`XRT_MODULE_ALL`: для хозяев/компиляторов/отладочных инструментов, которым нужна полная среда исполнения. `XRT_EXCLUDE_MEMORY_DEBUG`: ALL минус отладка памяти (исключаются сразу memory_debug и memory_debug_report, остаётся memory_stats) — точное выражение «полная продакшн-функциональность без инвазивной диагностики». **Правило приоритета**: EXCLUDE подавляет только неявный выбор ALL; **явно определённые корневые модули всё равно побеждают** (ALL+EXCLUDE_X+явный MODULE_X = X входит). **Совет по умолчанию** (буквально из контракта): «обычным приложениям не следует по умолчанию выбирать все модули».

Семантику комбинации ALL+EXCLUDE запомните одним выводом: `XRT_MODULE_ALL` неявно выбирает все модули манифеста; `XRT_EXCLUDE_MEMORY_DEBUG` убирает из неявного множества два диагностических модуля — в этот момент артефакт = всё минус диагностика; затем явный `#define XRT_MODULE_MEMORY_DEBUG` — явный корневой модуль **добавляется обратно**, перекрывая исключение (порядок трёх слоёв: явное > неявное ALL > исключение EXCLUDE). Этот приоритет позволяет сосуществовать «всё минус одно» и «точечно по имени» — хозяин подстраивает модуль за модулем поверх ALL, не теряя удобства умолчания.

### Принцип гранулярности: три вопроса о модуле

Один публичный модуль = одна небольшая группа возможностей с **общим состоянием, общими зависимостями, общим сценарием**. Антипримеры: макрос на функцию (взрыв макросов)/один рубильник на семейство (всё-или-ничего). Семейство Queue и сетевое семейство — положительные образцы: база Queue/SPSC/MPSC/MPMC/ожидание/отмена/Select/мост к корутинам выбираются по отдельности; Engine сети/каждый бэкенд/TCP/UDP/синхронизация/Future/DNS/прокси/TLS образуют свои замыкания. **Новая публичная возможность сначала через три вопроса**: можно ли тестировать независимо? обрезать независимо? описать владение независимо? — всё да, тогда новый модуль; существующий общий макрос не расширять (механизм, не дающий гранулярности деградировать).

### Профили размера и запрет символов

```diagram flow
- Профиль: каждая запись size_profiles.json - {name, suite, forbid_symbols}
  - профиль core запрещает префиксы движка регулярных выражений, внутренние префиксы сжатия (частные символы regex/сжатия)
  и префиксы публичных символов семейств сеть/HTTP/WebSocket/TLS
- Измерение: measure_size.py компилирует по профилю -> записывает базовую линию среды (платформа/компилятор/оптимизация/stripped)
  -> утверждает нулевое появление запрещённых символов -> отчёт о размерах (с базовой линией, против межсредовых ложных сравнений)
- Шлюз: появление любого запрещённого символа - провал; ошибочно притянутая зависимость вскрывается на месте
```

Смысл **базовой линии среды**: размеры бинарников несравнимы между компиляторами/уровнями оптимизации/платформами — отчёт записывает семь элементов `platform/machine/compiler_family/compiler_version/arch/optimization/stripped`, сравнение трендов идёт только внутри одной линии (пролог метода измерения главы 135).

## Примеры

### Первая полная программа: минимальная интеграция Core

Программа ниже из `examples/core/version_limits` — работа под свободным от возможностей контрактом Core:


```term
$ gcc -O1 -I single -include xrt.h impl.c examples/core/version_limits/main.c -lws2_32 -liphlpapi
version=2.0.0-dev
limits: depth=128 entries=100000 input=268435456
```

**Что только что произошло.** (1) В строке компиляции **нет XRT_MODULE_ALL** — без выбора = только Core: запрос версии и ресурсные границы — часть контракта Core (структурированные ошибки/слот ошибки туда же), а построение ошибки с printf — отдельный выбор `XRT_MODULE_ERROR_FORMAT` — минимальная программа не везёт форматный рантайм (пример из самого контракта). (2) Сравните со строкой главы 129 (с ALL): **один пример — две формы интеграции** — ALL — беспечная форма учебника, без выбора — фактическое заявление минимальной интеграции. (3) Угол размера: артефакт этой формы и есть профиль размера core — запрет символов профиля утверждает, что в нём нет ни одного символа regex/сжатия/сети.

### Вторая полная программа: минимальная интеграция с заменой распределителя

Вторая программа из `examples/core/allocator_tour` — подключение хозяина внутри замыкания Core:

```embed path="examples/core/allocator_tour/main.c" title="examples/core/allocator_tour/main.c"
```

```term
$ gcc -O1 -I single -include xrt.h impl.c examples/core/allocator_tour/main.c -lws2_32 -liphlpapi
allocator: swap -> at-family alloc/calloc/dup/realloc ok
allocator: locked after first alloc -> swap rejected ok
```

**Что только что произошло.** (1) Та же минимальная форма без ALL — `xrtSetAllocator` часть грани памяти Core (глава 5). (2) **Обрезочный смысл блокировки после первого распределения**: встраивающий хозяин (глава 134) меняет распределитель на входе в main — дальше все распределения библиотеки идут хозяину; блокировка гарантирует, что в сценариях многих модулей/многих TU его уже не сменить (стабильность интеграции). (3) Обрезка + замена распределителя — стандартная поза встраиваемой интеграции: малый размер + память под управлением хозяина — два примера вместе дают полный портрет минимальной интеграции.

### Против обрезочных взглядов хозяев-языков (проектное наблюдение)

Проблема обрезки существует и в мире хозяев-языков (инстанциация шаблонов C++, feature-гейтинг Rust); сопоставление проясняет выбор. **Rust features**: Cargo.toml объявляет фичи + замыкания зависимостей — модель почти изоморфна (позитивный выбор + разворот замыкания); отличие в том, что assert на forbid_symbols у XRT (проверка на уровне артефакта) строже большинства экосистем. **Шаблоны C++**: «обрезка» происходит автоматически по инстанциации — нулевая стоимость объявления, но результат непредсказуем (расползание инстанциаций) и непроверяем (эквивалента «запрещённых символов» нет). XRT выбирает явное объявление + утверждение артефакта: лишняя строка макроса покупает «что отрезано» как проверяемый факт — во встраиваемой поставке эта определённость дороже удобства.

## Контракты

- **Позитивный выбор**: XRT_MODULE_* объявляет корневые модули; замыкание разворачивается по манифесту; пользователь не копирует таблицу зависимостей.
- **Тайминг**: макросы выбора до первого include; XRT_IMPLEMENTATION ровно в одной TU; набор TU на линковке согласован.
- **Семантика без выбора**: только свободный от возможностей контракт Core — новые модули незаметно не увеличивают существующие программы.
- **Семантика EXCLUDE**: подавляет неявный выбор ALL; явные корни побеждают; исключение MEMORY_DEBUG забирает report, оставляет stats.
- **Три вопроса гранулярности**: независимое тестирование/независимая обрезка/независимо описываемое владение — всё три, только тогда модуль.
- **Образцы гранулярности**: восемь частей Queue и сетевое семейство по пунктам — без макросов на функцию и без рубильника.
- **Профили размера**: {name, suite, forbid_symbols}; появление запрещённого символа — провал шлюза.
- **Базовая линия среды**: семь элементов (платформа/машина/семейство компилятора/версия/архитектура/оптимизация/strip) — тренды сравниваются только внутри одной линии.
- **Совет**: обычным приложениям не ALL по умолчанию — ALL для хозяев/инструментов.

## Ловушки

### Ловушка 1: define макросов модуля после include

Симптом: API модуля невидимы (компилятор сообщает «не объявлено») — хотя define точно был.

Причина: развёртывание происходит при первом include; последующие define не действуют задним числом. Макросы обязаны стоять до всякого include xrt.h/features.h (ключ -D в командной строке или самая верхушка файла).

```c bad
#include "xrt.h"                 /* include вперёд: развёртывание Core уже зафиксировано */
#define XRT_MODULE_QUEUE         /* поздний выбор: недействителен */
```

```c good
#define XRT_MODULE_QUEUE         /* объявление наверху */
#define XRT_IMPLEMENTATION
#include "xrt.h"
```

### Ловушка 2: копирование таблицы зависимостей (ручной список всех макросов)

Симптом: после обновления библиотеки сборка ломается — внутренние зависимости изменились, ваша копия устарела.

Причина: замыкание зависимостей — частное дело библиотеки — контракт прямо говорит «таблицу зависимостей копировать не следует». Объявляйте только нужный корень (STRING_SPLIT, а не STRING + внутренняя комбинация STRING_SPLIT).

```c bad
/* «замыкание», переписанное руками */
#define XRT_MODULE_STRING
#define MY_SPLIT_LEGACY_PATCH /* ручная заплата, копирующая старую зависимость */
```

```c good
#define XRT_MODULE_STRING_SPLIT  /* объявить только корень - замыкание развернётся внутри библиотеки */
```

### Ловушка 3: сравнение размеров между средами

Симптом: «это изменение раздуло бинарник на 30%» — сверились с базой: в прошлый раз gcc, в этот tcc.

Причина: размеры несравнимы между компиляторами/уровнями оптимизации/strip; семиэлементная базовая линия measure_size существует ровно против этого. Сравнение трендов — только в одной линии (тот же профиль, та же среда), или вместо абсолютных размеров — запрет символов.

```c good
/* сверить семь элементов базовой линии отчёта и только потом сравнивать; шлюз размера - forbid_symbols (от среды не зависит) */
```

## Упражнения

### Базовое: сравнение трёх форм интеграции

Один и тот же пример собрать без выбора / `MODULE_STRING_SPLIT` / `MODULE_ALL` — сравнить таблицы символов (nm/findstr) и размеры. Критерии приёмки: наборы символов трёх форм строго растут; в форме без выбора ноль не-Core символов.

### Продвинутое: проверка семантики EXCLUDE

Собрать с `MODULE_ALL`+`XRT_EXCLUDE_MEMORY_DEBUG` — подтвердить, что API отладки памяти отсутствуют, а stats на месте; затем добавить явный `XRT_MODULE_MEMORY_DEBUG` — подтвердить приоритет явного (отладочные API возвращаются). Критерии приёмки: все три проверки символов сходятся с контрактом.

### Вызов: собственный профиль размера

Написать новый профиль для цели «только контейнеры + строки»: suite фиксирует корневые модули, forbid_symbols перечисляет символы сетевых/протокольных семейств — прогнать measure_size. Затем намеренно втащить неверную зависимость в suite — наблюдать провал запрета. Критерии приёмки: чистый профиль весь зелёный; профиль с ошибкой проваливается на запрещённом символе (ошибка называет символ по имени).
