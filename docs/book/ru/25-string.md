## Ориентация

Том 4 начинается со строк. Текстовая философия XRT — полное воплощение конвенции представлений главы 3: **где можно обойтись без выделения памяти — обходимся** — Trim, Cut, сравнение без учёта регистра лишь переносят пары `(指针, 长度)` (указатель, длина), а распределение откладывается до момента, когда новая память действительно нужна; **когда распределение назрело — используем построитель** — цепочка дописываний даёт суммарное копирование O(n), а не O(n²) у Concat; **продукты всегда владеющие** — возвращается `str`, освобождение через `xrtFree`, бесшовно согласовано с конвенцией главы 5. Глава выстраивает три слоя в прогрессию «конвейер представлений → построитель → шпаргалка по полному семейству»: поиск, редактирование, разрезание и форматирование собраны в шпаргалке за один проход.

## Введение

Функция обработки URL должна сделать пять вещей: срезать краевые пробелы, разрезать путь и запрос по `?`, сравнить путь в нижнем регистре, удалить из запроса некоторые символы и наконец приклеить префикс. Учебниковый подход делает `strdup` на каждом шаге — пять шагов, пять распределений, пять освобождений и пять цепочек очистки на пути отказа. Но всмотритесь: первые четыре шага **вообще не требуют новой памяти** — обрезка пробелов лишь сдвигает указатели к середине, разрез лишь делит одно представление на два, для сравнения без учёта регистра есть специализированный вариант IgnoreCase, удаление символов может писаться в стековый буфер вызывающего. И только последний шаг — приклейка префикса — действительно требует распределения.

В этом отправная точка конвейера представлений: отделить «оперировать над текстом» от «порождать новый текст» — первое стоит нескольких сложений и вычитаний указателей, второе ужато до минимума. На горячих путях (код, исполняющийся на каждый запрос) это быстрее «копии на каждом шаге» на порядок — не потому, что алгоритм умнее, а потому, что **лишних распределений просто нет**.

## Понятия

### Слой 1: конвейер представлений (без распределений)

```diagram flow
- Trim: срезает краевые пробелы - лишь сдвигает указатели, исходные байты нетронуты
- Cut: режет на два по первому разделителю - обе части представления; ненужную передаёте NULL в выходной параметр
- FilterTo: удаляет байты множества - пишет в буфер вызывающего, при нехватке ёмкости - отказ
- Concat: склеивает два представления - первое настоящее распределение конвейера, продукт владеющий
```

Дисциплина дизайна конвейера: **чем позже распределение, тем лучше**. Каждый нераспределяющий шаг сохраняет выбор для последующих шагов (вырезанное представление можно резать снова, фильтровать снова, сравнивать снова); как только распределение произошло, все дальнейшие операции идут по копии. Критерий, нужно ли распределение на шаге, прост: является ли множество выходных байтов собственным подотрезком входа (Trim, Cut, срез подстроки — решается без распределений) или требуется пересборка (склейка, замена, фильтрация — распределять или пользоваться буфером вызывающего)?

### Слой 2: построитель (склейка за O(n))

Не собирайте цепочку `Concat` из трёх и более сегментов — каждый Concat порождает новый промежуточный буфер, n сегментов дают суммарное копирование O(n²). Построитель `xstrbuf` наращивает внутренний буфер удвоением (та же стратегия, что у контейнеров главы 15), поэтому цепочка дописываний копирует суммарно O(n). Семантика передачи у `Take` изоморфна контейнеру buffer (глава 15): владение буфером переходит напрямую, построитель обнуляется и переиспользуется. Построитель умеет и `AppendRepeat` (повторное дописывание — генератор разделителей и отступов), и форматированное дописывание.

### Слой 3: шпаргалка по полному семейству

| Семейство | Функции | Примечания |
| --- | --- | --- |
| Поиск | `xrtStrFind` / `CaseFind` / `RFind` | возвращают позицию; промах — `XRT_NPOS` |
| Байтовый уровень | Any / Byte поиск | найти любой байт из множества |
| Префикс/суффикс | `xrtStrStarts` / `Ends` / `CutPrefix` / `CutSuffix` | проверки и усечение представления, у каждой есть Case-вариант |
| Редактирование | `Insert` / `Remove` / `Replace` | владеющие продукты |
| Разрезание | `xrtStrSplit` / `Cut` итеративно | Split идёт в обратный вызов; Cut режет в цикле |
| Склейка | `Join` / `Repeat` / `Dup` | владеющие продукты |
| Регистр | `xrtStrUpper` / `Lower` (включая вариант To в буфер вызывающего) / сравнения семейства Case | без учёта регистра — специализированные функции Case |
| Обрезка | `Trim` / `TrimLeft` / `TrimRight` / `Pad` / усечение | обрезка без распределений; Pad требует буфер |
| Измерение | `Length` / `IsEmpty` / проверка пробельности | прямое чтение представления |
| Расстояние | `xrtUtf8Distance` / `xrtUtf8Similarity` | расстояние редактирования по скалярам Unicode (семейство наборов символов, глава 27) |
| Glob | `xrtStrGlob` | сопоставление в стиле glob `*?` |
| Форматирование | `xrtFormat` / `FormatV` | правила printf, владеющий продукт |

Два столбца заслуживают отдельного упоминания: **семейство Case** (`CaseFind`, `CaseEqual`, `CaseStarts` и другие) выполняет сравнение без учёта регистра за один вызов — на два распределения меньше, чем «сперва ToLower обе копии, потом сравнить»; **расстояние/сходство** (`xrtUtf8Distance`/`xrtUtf8Similarity` семейства наборов символов, счёт по скалярам Unicode) дают нечёткому сопоставлению готовый ответ — пример distance демонстрирует чтение «расстояние редактирования 2, сходство 0.6».

### Разделение труда со стандартной библиотекой C

Почему бы просто не взять `strstr`/`strdup`? Три жёстких довода: стандартные функции предполагают нулевое завершение (двоично-безопасные сценарии выбывают сразу), пути отказа не сообщаются (`strdup` при OOM возвращает лишь NULL без диагностики), владение продуктом не оговорено (кто распределил, тот освобождает — чистая договорённость). Строковое семейство XRT полностью ходит на `(视图, 长度)` (представление, длина) как на валюту, на `bool` плюс слот ошибки, на владеющие продукты с `xrtFree` — все три пункта суть конвенции тома 1, воплощённые в текстовом слое.

## Примеры

### Полная программа: конвейер из четырёх шагов одним духом

Из образца репозитория `examples/string/basic/main.c`:

```embed path="examples/string/basic/main.c" title="examples/string/basic/main.c"
```

```term
$ gcc -O1 -DXRT_MODULE_ALL -I single impl.c examples/string/basic/main.c -lws2_32 -liphlpapi
alpha.txt
```

**Что только что произошло.** (1) `xrtStrTrim` возвращает **подпредставление** исходной строки — два указателя сходятся к середине, ни один исходный байт не тронут, распределений нет. (2) `xrtStrCut` режет по первому `/`: `Name` получает передний сегмент `alpha`, задний не нужен, поэтому второй выходной параметр принимает `NULL` — ненужные продукты просто не принимаются, удобная конвенция Cut. (3) `FilterTo` вычищает `-` и `_` из представления, остальное пишет **в стековый буфер вызывающего** — даже на шаге «нужна перезаписываемая память» право распределения остаётся у вызывающего (при нехватке ёмкости — отказ, а не тихое распределение за спиной). (4) Первое и единственное распределение в куче происходит в `Concat` при приклейке `.txt` — продукт владеющий, освобождение через `xrtFree`. Три шага из четырёх без распределений — полная демонстрация принципа «распределять как можно позже».

### Полная программа: построитель и передача владения

Из `examples/string/builder/main.c`:

```embed path="examples/string/builder/main.c" title="examples/string/builder/main.c"
```

```term
$ gcc -O1 -DXRT_MODULE_ALL -I single impl.c examples/string/builder/main.c -lws2_32 -liphlpapi
items=ababab
```

**Что только что произошло.** (1) `xrtStrBufInit` открывает дело со стековым дескриптором — внутренний буфер построителя растёт по потребности (стратегия удвоения); между двумя дописываниями `items=` и `ab`×3 нет промежуточных продуктов. (2) `AppendRepeat` — специализированный вход для повторного дописывания: потребности вида «один сегмент n раз» (разделители, отступы, заполнение) не требуют цикла от вас. (3) `Take` передаёт **владение** буфером вызывающему: без копии, без разделения; построитель возвращается в пустое состояние и готов к переиспользованию — семантика, полностью изоморфная `xrtBufferTake` главы 15; ритм «накопить — собрать — взять» главы 15 дословно действует и в мире строк. (4) На пути отказа `xrtStrBufFree` возвращает построитель — три конвенции контейнеров работают здесь как обычно.

## Контракты

- **Представления в приоритете**: обрезка, разрезание, проверки префикса/суффикса — без распределений; выходы-собственные-подотрезки — всегда представления.
- **Владеющие продукты**: Concat/Join/Dup/Replace/Format возвращают `str`, ровно одно освобождение `xrtFree`.
- **Дисциплина построителя**: три сегмента и больше — `xstrbuf`; после передачи `Take` построитель обнулён и переиспользуется; на пути отказа — `Free`.
- **Семейство Case**: без учёта регистра — специализированные `CaseFind`/`CaseEqual`, без «сперва преобразовать, потом сравнить».
- **Семантика промаха**: поиск возвращает `XRT_NPOS`, проверка — `== XRT_NPOS` (дисциплина сигнальных значений главы 3).
- **Двоичная безопасность**: все функции ходят на валюте `(视图, 长度)` (представление, длина); содержимое может содержать нулевые байты.

### От примеров к инженерии: три хозяина строк

Параллельно трём хозяевам контейнеров (глава 23) у строк в инженерии три типовых хозяина. **Запросный временный текст**: конвейер представлений плюс стековый буфер, ноль распределений на всём пути — набор для обработки URL и разбора заголовков, кода, исполняющегося на каждый запрос. **Накапливаемый вывод**: построитель висит на контексте обработки, дописывает через множество обратных вызовов и один раз забирает в конце — стандартная форма строк журнала, строк отчётов, вывода сериализации. **Долгоживущие поля**: разобранные поля, обязанные пережить запрос (элементы конфигурации, ключи кеша), уходят в контейнеры владеющими продуктами Dup/Join — владение с этого момента принадлежит той структуре, которой управляет контейнер. Три хозяина отвечают трём ступеням «ноль распределений, позднее распределение, владение» и сверяются с языком памяти главы 5 с одного взгляда.

### Одна привычка: сперва спросите, не подстрока ли выход

Перед любой текстовой функцией спросите: **выход — собственный подотрезок входа?** Да — возвращайте представление, ноль распределений (мир Trim/Cut/Slice); нет, но содержимое ограничено — пишите в буфер вызывающего (FilterTo/семейство To); нужна открытая длина — владеющий продукт или построитель. Эта привычка трёх вопросов отсекает большую часть расточительства «Dup на всякий случай» и большую часть аварий «возврат висячего представления» — самая ценная фраза, которую стоит унести из главы.

## Ловушки

### Ловушка 1: склейка многих сегментов цепочкой Concat

Симптом: функции, собирающие URL, SQL или строки журнала, на длинных входах замедляются всё сильнее; профилировщик показывает горячие точки в memcpy и аллокаторе.

Причина: n сегментов Concat каждый раз копируют всё накопленное — суммарное копирование O(n²); плюс n распределений и n освобождений промежуточных строк.

```c bad
str s = xrtStrDupView(Prefix);
s = xrtStrConcat((xstrview){ s, strlen(s) }, Host);   /* копирует всё накопленное */
s = xrtStrConcat((xstrview){ s, strlen(s) }, Path);   /* и ещё раз всё */
s = xrtStrConcat((xstrview){ s, strlen(s) }, Query);  /* и снова - O(n²) уже предрешено */
```

```c good
xstrbuf tBuf;
xrtStrBufInit(&tBuf);
xrtStrBufAppend(&tBuf, Prefix);
xrtStrBufAppend(&tBuf, Host);
xrtStrBufAppend(&tBuf, Path);
xrtStrBufAppend(&tBuf, Query);
str s = xrtStrBufTake(&tBuf);     /* одна передача владения, суммарное копирование O(n) */
```

### Ловушка 2: представление, пережившее источник

Симптом: та же семья, что ловушка 3 главы 3 — «результат обработки», возвращённый функцией, у вызывающего изредка превращается в мусор или пустой сегмент.

Причина: представления, порождённые Trim/Cut, — заимствования исходной памяти; когда такое представление сохраняют в структуру, возвращают наверх или передают между потоками, источник может быть уже освобождён или переиспользован.

```c bad
xstrview getName(const char* sRaw)
{
	xstrview Text = xrtStrTrim((xstrview){ sRaw, strlen(sRaw) });
	xstrview Name;
	xrtStrCut(Text, XRT_STR_LITERAL("/"), &Name, NULL);
	return Name;   /* Name указывает внутрь sRaw - висячий, как только вызывающий сменит sRaw */
}
```

```c good
str getName(const char* sRaw)
{
	xstrview Text = xrtStrTrim((xstrview){ sRaw, strlen(sRaw) });
	xstrview Name;
	xrtStrCut(Text, XRT_STR_LITERAL("/"), &Name, NULL);
	return xrtStrDupView(Name);   /* чтобы жить долго - владейте собственной копией */
}
```

## Упражнения

### Базовое: воспроизвести конвейер

Воспроизведите четырёхшаговый конвейер главного примера с выводом `alpha.txt`; затем смените вход на `"  x/y/z  "` (два разделителя), сперва в столбик вычислите, какой сегмент возьмёт Cut, потом запустите и сверьте.

### Продвинутое: парсер строки запроса

Цикл Cut плюс Find плюс CaseEqual для разбора `?a=1&b=2&c=3`: вырезайте каждую пару ключ-значение, сопоставляйте имена ключей без учёта регистра, вычищайте `%` из значений — с единственным распределением в самом конце, при сборке вывода. Подсказка: подать задний сегмент Cut снова на вход Cut — это итеративное разрезание.

### Вызов: сборщик строк журнала

Реализуйте структурную строку журнала на построителе: метка времени, уровень, модуль, сообщение и несколько пар ключ-значение (значения — строки или целые). Требования: цепочка дописываний без промежуточных продуктов; разделители и отступы полей — через `AppendRepeat`; вся строка забирается одним `Take`. Критерии приёмки: сборка 1000 строк журнала требует числа распределений порядка числа строк (а не произведения на число полей); формат вывода фиксирован и записываем в утверждение.

## Шпаргалка

| Тема | Кратко |
| --- | --- |
| Конвейер представлений | Trim/Cut/префикс-суффикс без распределений; распределение отложено до Concat |
| Построитель | три сегмента и больше — `xstrbuf`; `Take` передаёт для переиспользования; суммарное копирование O(n) |
| Поиск | Find/CaseFind/RFind; промах — `XRT_NPOS`; проверка `== XRT_NPOS` |
| Редактирование | Insert/Remove/Replace, владеющие продукты |
| Разрезание | Cut режет итеративно / SplitInit+SplitNext перебирает по элементам курсором |
| Регистр | специализированные функции семейства Case, без «сперва преобразовать» |
| Нечёткость | xrtUtf8Distance — расстояние редактирования / сходство; глоб-шаблоны через xrtStrGlob |
| Владение | представления заимствуют и не владеют; владеющие продукты — ровно один `xrtFree` |
