## Ориентация

Главы 63–70 решили «как данные утекают»: адреса, порты, буферы, DNS, TCP, UDP, прокси. Эта глава добавляет вторую половину картины — **увидеть себя**: какие сетевые карты у этой машины, какие адреса висят на каждой, как называется петлевой интерфейс, каков предпочтительный адрес машины. Эта информация незаменима в четырёх сценариях: стартовые журналы, печатающие сетевое окружение; административные диагностические страницы с данными узла; выбор адреса привязки на многосетевых машинах; и идентификатор scope, который обязаны нести IPv6 link-local адреса. Их формы на нативных API печально фрагментированы — GUID адаптеров Windows, `if_nametoindex` POSIX, разные системы имён на платформах — XRT стягивает их в маленький модуль без зависимостей от движка: ни Socket, ни потоков, ни DNS; свободно сочетается с любым транспортным слоем.

## Введение

Предположим, вы пишете стартовый поток распределённого сервиса. Эксплуатация требует, чтобы каждый стартовый журнал нёс «имя хоста + локальный адрес + аппаратный идентификатор», чтобы узел мгновенно находился среди тысяч строк; админ-эндпоинт `/health` показывает тот же набор; на многосетевой машине конфиг даёт имя интерфейса `eth0`, и вам нужен его индекс для IPv6-мультикаста; и та классическая ошибка — `fe80::1` не соединяется, потому что link-local адрес полон только в форме `fe80::1%3` (3 — индекс интерфейса).

По отдельности эти потребности несложны; вместе — межплатформенное болото: «имя» интерфейса Windows — GUID, отображаемое имя — «Ethernet»; каноническое имя Linux — `eth0`; петлевой интерфейс на двух сторонах называется совершенно по-разному. Аппаратные адреса на Windows берутся через `GetAdaptersAddresses`, на POSIX — через `ioctl`, и длина не обязательно 6 байт. Собственный сток стоит по ветке на каждую платформу, а модуль интерфейсов XRT уже сделал эту работу: один вызов даёт согласованную структуру-снимок, имя и индекс конвертируются в обе стороны, локальная тройка (адрес/аппаратура/имя хоста) — по три удобных формы на каждую.

## Понятия

### Снимок интерфейсов: одно распределение, все виды заимствованы

`xrtNetInterfaces` создаёт **согласованный снимок** текущих интерфейсов и адресов системы: одно распределение XRT вмещает массив интерфейсов, массив адресов, имена и аппаратные адреса; после этого все поля — заимствованные представления.

```diagram flow
- Перечисление: xrtNetInterfaces(&List) — один системный запрос строит снимок
- Чтение: Items[i].Name / Addresses[j] — всё заимствовано из хранилища снимка
- Освобождение: xrtNetInterfacesFree(&List) — возврат всего хранилища и обнуление структуры
```

Ценность снимка — **согласованность**: добавление/удаление интерфейсов в процессе перечисления не рассинхронизирует записи; цена — моментальный срез без подписки на изменения. Метаданные на интерфейс: `IPv4Index`/`IPv6Index` (Windows ведёт раздельно; POSIX обычно одинаково), битовые `Flags`, `Mtu`, виды `Name` (каноническое) и `DisplayName` (отображаемое), сырые байты `HardwareAddress`, массив `Addresses` — каждый адрес с `PrefixLength` (0..32 для IPv4, 0..128 для IPv6; `XNET_INTERFACE_PREFIX_UNKNOWN`, когда платформа не может сказать).

Две дисциплины использования: порядок интерфейсов и адресов решает ОС — **не считайте порядок идентичностью**; после освобождения виды умирают мгновенно — все чтения обязаны предшествовать `Free`.

### Флаги: стабильное межплатформенное пересечение

`Flags` открывают только шесть флагов, стабильно наблюдаемых на всех платформах: `UP` (в сети), `RUNNING` (работает), `LOOPBACK` (петля), `BROADCAST` (широковещание), `POINT_TO_POINT` (точка-точка), `MULTICAST` (поддержка мультикаста). Флаг без надёжного источника на некоторой платформе остаётся невыставленным — **невыставленный ≠ возможности нет**, лишь платформа не видит. «Можно ли вступить в мультикаст-группу» читает `MULTICAST`; «петля ли это» — `LOOPBACK`; каждое — одно битовое И.

### Имена и индексы: конвертация в обе стороны

У интерфейсов две системы идентичности. **Индекс** — ключ мира ядра (IPv6 scope и управление членством мультикаста используют его); **имя** — ключ мира людей (в конфигах пишут его):

- `xrtNetInterfaceIndex(名称, 族)` возвращает индекс; нулевой индекс — не результат; промах сообщает `XERR_NOT_FOUND`.
- `xrtNetInterfaceName(索引, 族, 缓冲, 容量)` выводит каноническое имя в обратную сторону, возвращая нужную длину; пустой буфер сначала меряет, недостаточный безопасно усекает, дополняет нулём и возвращает полную нужную длину — то же двухчастное соглашение, что у текстовых API главы 63.

Различия имён поглощаются модулем: на Windows каноническое имя — системное имя адаптера (вида GUID), отображаемое — псевдоним интерфейса; на POSIX оба — `if_name`. `Index` принимает и каноническое, и отображаемое имя; запрос с `UNSPEC` предпочитает IPv6-индекс, откатываясь на IPv4.

### Локальная тройка: три уровня

Диагностический набор «имя хоста, локальный адрес, аппаратный адрес» имеет три уровня использования, и API делится по уровням:

| Уровень | Адрес | Аппаратура | Имя хоста | Сценарии |
| --- | --- | --- | --- | --- |
| Структура/байты | `xrtNetLocalAddress` | `xrtNetLocalHardware` | `xrtNetHostName` | Продолжение в бинарной форме (соединения, сравнения) |
| Двухчастный текст | `xrtNetLocalAddressText` | `xrtNetLocalHardwareText` | — (HostName уже текст) | Фиксированные буферы, среды без распределений |
| String-удобство | `xrtNetLocalAddressString` | `xrtNetLocalHardwareString` | `xrtNetHostNameString` | Стартовые журналы и диагностические страницы одним махом |

Выбор `xrtNetLocalAddress` — **детерминированный запрос предпочтения**: последовательно предпочитаются `UP`, `RUNNING`, не-петля, не-link-local интерфейсы; при равенстве `UNSPEC` предпочитает IPv6. Он подходит стартовым журналам и отчётам узла, но **не публичный исходящий адрес и не маршрут по умолчанию** — для точного выбора обходите `xrtNetInterfaces` и решайте сами. Текст аппаратного адреса — компактный HEX в верхнем регистре без разделителей (MAC 6 байт — 12 символов); для двоеточий и иных форматов показа читайте сырые байты и форматируйте сами. Уровень String возвращает строки, освобождаемые `xrtFree`; проверка на пустоту и есть обработка ошибки (семантика запроса — ошибка потока не ставится).

### Нежданный подарок: разбор IPv6 scope

С включённым модулем `xrtNetAddrParse` и `xrtNetAddrParseEndpoint` главы 63 принимают одновременно **числовой scope и scope-имя интерфейса**: разбираются и `fe80::1%3`, и `fe80::1%eth0`; можно и `[fe80::1%eth0]:8080`. Результат разбора хранит только стабильный числовой индекс интерфейса; текстовый вывод (`xrtNetAddrText`) сохраняет каноническую форму без системных запросов — имена меняются с конфигурацией системы, индекс — постоянно сравнимая идентичность.

Вывод зависит от машины, поэтому ожидаемый вывод в заголовке примера — описание, а не фиксированный текст.

Любой провал идёт через единый `Cleanup` с ненулевым возвратом — «осмотр», записанный как цепочка «упал — дальше не идём», читается куда лучше россыпи if.

**Что только что произошло.** Контракт уровня String проявляется здесь: возврат `str` (освобождение `xrtFree`), `NULL` означает недоступность **без установки ошибки потока** — проверка на пустоту и есть вся обработка ошибок. Отсутствие адреса или имени хоста считается аномалией среды с возвратом 1, тогда как аппаратный адрес в чисто петлевой среде (контейнеры, VM без карт) может законно отсутствовать — печатается `unavailable`, и работа продолжается. Освобождение трёх строк собрано в конце — даже промежуточная неудача освобождает всё через `xrtFree`: `xrtFree(NULL)` — отсутствие операции, построчные проверки не нужны.

## Контракты

- **Владение снимком**: `Interfaces` владеет всем хранилищем одним распределением; виды полей только заимствуют; `InterfacesFree` возвращает и обнуляет структуру, вызываем повторно на пустом списке; неудача не меняет выход.
- **Порядок не гарантирован**: порядок интерфейсов и адресов решает ОС и не может служить стабильной идентичностью; идентичность — индекс (число) и каноническое имя.
- **Имя/индекс**: нулевой индекс — не результат; `Index` принимает каноническое и отображаемое имена, `UNSPEC` предпочитает IPv6-индекс; `Name` следует двухчастному соглашению текстовых API (мерить → писать; нехватка безопасно усекается и возвращает полную нужную длину).
- **Границы уровня удобства**: `LocalAddress` — детерминированный запрос предпочтения (UP/RUNNING/не-петля/не-link-local, UNSPEC предпочитает IPv6) — не публичный исходящий, не маршрут по умолчанию, не замена политике прослушивания и адреса-источника; точный выбор — обход `Interfaces`.
- **Текстовый уровень**: текст аппаратного адреса — компактный HEX верхнего регистра; уровень String возвращает `xrtFree`-освобождаемые строки, `NULL` значит недоступность, ошибка потока не ставится (семантика запроса).
- **Ошибки**: неудачи сообщаются через `xrtGetError()` — `XERR_NOT_FOUND` (интерфейс/адрес/аппаратура отсутствуют), `XERR_IO` (сбой системного перечисления), `XERR_RANGE` + `XNET_ERROR_BUFFER` (нехватка буфера), домен `xrt.net`.
- **Зависимости и обрезка**: `XRT_MODULE_NET_INTERFACE` зависит только от базового слоя сетевых адресов — без Socket, Engine, потоков, DNS и контейнеров; `XRT_MODULE_NET_INTERFACE_TEXT` — отдельный тонкий слой с HEX-кодированием.

## Ловушки

### Ловушка 1: LocalAddress как публичный исходящий или адрес привязки

Симптомы: сервис недостижим в многосетевых/NAT-средах — «локальный адрес» в журнале принадлежит какому-то интрасетевому интерфейсу, а не адресу, достижимому пиром; или после привязки к нему сервис недоступен извне контейнера.

Причина: `xrtNetLocalAddress` — **выбор предпочтения** (предпочитает онлайнные, работающие, не-петлевые, не-link-local unicast-адреса); он не знает таблицу маршрутизации и тем более публичный исходящий за NAT. Использовать его как «внешне достижимый адрес» или единственный адрес привязки — значит принять диагностическую информацию за решение о маршрутизации.

```c bad
xnetaddr Addr;
xrtNetLocalAddress(&Addr, XNET_FAMILY_UNSPEC);
/* напрямую регистрируем Addr как «адрес, по которому пир ко мне подключится» */
register_service(xrtNetAddrText(&Addr, ...));
```

```c good
/* Диагностический показ — LocalAddress; внешняя регистрация — конфигурация или живой замер;
   многосетевая привязка — обход снимка и собственное решение */
xnetinterfacelist List;
if ( xrtNetInterfaces(&List) ) {
	for ( size_t i = 0; i < List.Count; i++ ) {
		const xnetinterface* pIf = &List.Items[i];
		if ( (pIf->Flags & XNET_INTERFACE_UP) == 0 ) {
			continue;
		}
		/* отбор по бизнес-правилам: семейство, префикс, мультикаст... */
	}
	xrtNetInterfacesFree(&List);
}
```

### Ловушка 2: заимствованные виды после освобождения снимка

Симптомы: редкие падения или мусорные байты — обычно в коде «кэширующем данные интерфейсов».

Причина: `Items[i].Name.Data`, `Addresses[j]`, `HardwareAddress.Data` — всё указывает во внутреннее хранилище снимка; после `xrtNetInterfacesFree` все они повисают. Снимок — моментальный срез со семантикой значения, а не долго удерживаемый объект.

```c bad
xnetinterfacelist List;
xrtNetInterfaces(&List);
const xstrview Name = List.Items[0].Name;   /* заимствованный вид */
const xnetinterfaceaddress* Addrs = List.Items[0].Addresses;
xrtNetInterfacesFree(&List);                /* хранилище возвращено */
printf("%.*s\n", (int)Name.Size, Name.Data); /* повисшее чтение */
```

```c good
xnetinterfacelist List;
if ( xrtNetInterfaces(&List) ) {
	for ( size_t i = 0; i < List.Count; i++ ) {
		const xnetinterface* pIf = &List.Items[i];
		printf("%.*s\n", (int)pIf->Name.Size, pIf->Name.Data);
		/* информацию, которую надо сохранить, копируйте в собственное хранилище прямо сейчас */
	}
	xrtNetInterfacesFree(&List);
}
```

### Ловушка 3: длина аппаратного адреса зашита в 6 байт

Симптомы: обрезанные буферы или неверные длины на платформах с 8-байтовыми EUI-64 или некоторыми виртуальными интерфейсами.

Причина: 6 байт MAC-48 — лишь «типичное значение»; контракт модуля прямо говорит, что `LocalHardware` возвращает **требуемое число байт** и не зашивает длину; `Size` вида `HardwareAddress` тоже решает система.

```c bad
uint8 Mac[6];
if ( xrtNetLocalHardware(Mac, sizeof(Mac)) == 0 ) {
	/* предположение 6 байт: более длинные адреса молча усекаются */
}
```

```c good
size_t iNeed = xrtNetLocalHardware(NULL, 0u);   /* сначала меряем */
if ( (iNeed == 0u) || (iNeed > 16u) ) {
	return 1;
}
uint8 Hardware[16];
size_t iSize = xrtNetLocalHardware(Hardware, iNeed);
/* только iSize == iNeed — полный адрес; длина HEX-текста 2*iSize */
```

## Упражнения

### Базовое: отчёт по петлевому интерфейсу

Перечислите снимок, найдите интерфейс с `XNET_INTERFACE_LOOPBACK` во `Flags` и напечатайте его имя, двухстековые индексы и все адреса. Критерий приёмки: по одному запуску на Windows и Linux (подойдёт и WSL), обе стороны корректно печатают данные петли; после освобождения снимка программа нормально завершается.

### Продвинутое: селектор сетевой карты для мультикаста

Напишите функцию `uint32 pick_multicast_iface(void)`: обходя снимок, выберите интерфейс «в сети, с мультикастом, не петля, с максимальным MTU», верните его IPv6-индекс или 0 при отсутствии. Подсказка: проверяйте во `Flags` одновременно `XNET_INTERFACE_UP` и `XNET_INTERFACE_MULTICAST`; петлю исключайте по `XNET_INTERFACE_LOOPBACK`; не забудьте `InterfacesFree` перед возвратом.

### Вызов: диагностическая страница узла

Реализуйте `print_diagnostics(void)`: одним махом печатайте имя хоста (`HostName` двухчастно), локальный адрес (`LocalAddressText` двухчастно, семейство `UNSPEC`), аппаратный адрес (`LocalHardware` сырыми байтами, самостоятельно форматируя в HEX верхнего регистра с двоеточиями, как `00:E0:4C:7D:7E:66`), общее число интерфейсов и адресов (из снимка). Критерий приёмки: весь вывод без единой утечки (сверка со статистикой распределений главы 6); отсутствие аппаратного адреса печатает `hardware: unavailable`, а не падение; два возврата каждого двухчастного вызова сверены построчно.

## Шпаргалка

| Тема | Краткая справка |
| --- | --- |
| Снимок | `Interfaces` владеет всем одним распределением; виды заимствованы; `InterfacesFree` обнуляет и повторяем; порядок — не идентичность |
| Метаданные интерфейса | двухстековые индексы / Flags / Mtu / Name+DisplayName / HardwareAddress / Addresses+PrefixLength |
| Флаги | `UP` `RUNNING` `LOOPBACK` `BROADCAST` `POINT_TO_POINT` `MULTICAST`; невыставленный ≠ возможности нет |
| Имя↔индекс | `InterfaceIndex` (имя → индекс, 0 = неудача) / `InterfaceName` (индекс → имя, двухчастно); UNSPEC предпочитает IPv6 |
| Локальная тройка | адрес (запрос предпочтения, не публичный исходящий) / аппаратура (длина варьируется) / имя хоста (локальная метка, не DNS-имя) |
| Три уровня | выход-параметр (продолжить в бинарном) → Text двухчастный (без распределений) → String (журналы одним махом, xrtFree + проверка на пустоту) |
| Текст аппаратуры | HEX верхнего регистра без разделителей (6 байт = 12 символов); форматы показа — сами |
| IPv6 scope | с включённым модулем разбираются и `fe80::1%3`, и `fe80::1%eth0`; хранится стабильный числовой индекс |
| Ошибки | NOT_FOUND (интерфейс/адрес/аппаратура) / IO (перечисление) / RANGE+BUFFER (нехватка буфера), домен `xrt.net` |
| Обрезка | `XRT_MODULE_NET_INTERFACE` без зависимостей от движка; слой TEXT отдельно добавляет HEX |
