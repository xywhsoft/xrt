## 导读

池是第 5 章分配器的"批发放电商"：等大对象按**槽**分配——页满自动加页、释放即时进 LIFO 空闲表、下一次分配拿到的是**最近释放**的槽（缓存还热）。连接对象、帧结构、消息头这类"同一种东西成千上万个"的场景，池把分配成本从"系统调用级"压到"空闲表弹出一个指针"，同时消除了等大分配天然的碎片问题——槽永远不会因为大小不齐而散布。本章讲固定池 `xpool` 的完整生命周期（分页、LIFO 复用、两种标记回收）与变长池（大小混杂的场景），并用第 6 章统计验证池化收益——`pooled` 与 `backing` 的比值曲线在池化后是什么形状，跑一遍就有直觉。

## 引入

一个网关服务维护十万条连接，每条连接对象 48 字节。逐个 `xrtMalloc/xrtFree`：每次断连重连都过系统分配器，碎片慢慢累积，第 6 章统计里 `backing` 次数随流量线性上涨。换成固定池：连接对象从槽里取、还回槽里——分配与释放都是指针操作；系统调用只发生在"加页"那一瞬间（一页约 64KB，装 256 个 48 字节的槽之后才有下一页）。流量再大，`backing` 曲线是台阶状：每 256 次分配才跳一格。这就是池的全部价值——**把分配的粒度从对象级提到页级**。

什么时候不该用池？对象大小五花八门（用变长池或直接堆）、对象数量极少（池的管理成本大于收益）、生命周期极短且整齐（第 7 章 arena 更合适——池解决"频繁取放"，arena 解决"一起回收"，两者是不同问题的答案，常被混淆却从不可互换）。这段"什么时候不用"与前面的"什么时候用"同样重要：池的正确使用从正确的"不用"开始。

## 概念

### 固定池模型

```diagram flow
- 初始化：按对象大小+对齐建池，每页容量自动计算（约 64KB/页）
- 分配：Alloc/Calloc 从空闲表取槽；表空则加页
- 释放：Free 即时入 LIFO 空闲表——下次分配拿到最近释放的槽
- 收尾：Trim 归还空页 / Reset 全量清空 / Unit 销毁
```

LIFO 复用不是实现细节，是**缓存友好的设计决策**：最近释放的槽大概率还在各级缓存里，复用它比取一个久未触碰的槽更快——示例会实证 `pReused == pReleased`。`Owns` 判断指针是否属于本池——防御外来指针混入释放（把堆指针 Free 给池是未定义行为，Owns 是那道安检门）。

### 两种标记回收

逐个 Free 在批量处理场景是浪费——一千个对象逐个还，不如标记后一次处理。池提供两个方向：**Sweep 保留标记、回收未标记**（批量处理器标记"还要的"，其余一扫而空——缓存逐出、请求结束清理）；**FreeMarked 释放标记、保留其余**（引用计数归零者被标记后放回——与第 3 章引用计数配合的半自动回收）。两个方向覆盖了"留少数删多数"与"删少数留多数"两种形态，选方向看哪边标记更少。

### 变长池与池化统计

变长池（`memory_pool` 范例演示）处理大小混杂的分配：内部按尺寸分桶，小分配走桶、大分配直通。第 6 章 `xmemstats` 的 `pooled`（池化命中）与 `backing`（系统调用）两列就是池化效果的可观测面——池化良好的服务，业务分配次数远大于 backing，且曲线呈台阶状（加页时刻）。容量规划与内存预算也在这一步落地：`live/peak` 告诉你池的实际水位。

### 页与归还

`SetRetain` 设定 `Reset` 后保留多少空页（应对突发流量的预热）；`Trim` 主动归还空页（内存紧张期）；`Create`/`CreateLayout` 堆创建形态可显式指定每页槽数（对齐你的业务批量）。页的生命周期归池——你从不直接碰页，只通过槽接口进出。

### 池与第 5 章分配器的关系

池不是分配器的替代品，是它上面的批发层。最灵活的组合方式正是第 5 章的分配器替换：把自定义分配器实现成按大小路由到对应池，整个程序的分配行为就在一处收口——这正是内核 `memory_stats` 里 pooled 计数的来源（第 6 章示例的 48 字节命中尺寸类缓存，就是内核内建的小对象池在工作）。业务侧自建池则更直接：连接池、帧池、消息池各管各的等大对象。两条路线不冲突：内核池兜底通用小对象，业务池承载领域对象。

### 对象构造与槽的分工

池只管槽的取放，不管对象的构造与析构——从池里拿到的槽内容是未定义的（Calloc 版本除外，零初始化）。取放与构造的标准配对是：`Alloc` 拿槽、业务初始化构造对象；析构对象、`Free` 还槽。需要析构回调的批量场景用 `Visit` 遍历活动对象逐个收尾，再 Reset/Trim 批量回收——遍历收尾、批量回收、页管理这三步是池化对象生命周期管理的完整闭环，第 66 章连接表会用到它的完全体。

## 契约

- **等大槽**：固定池按 `Init` 时的大小+对齐分槽；不同大小各自建池或改用变长池。
- **LIFO 复用**：释放的槽即时回空闲表，下次分配优先复用最近释放者。
- **安检**：`Owns` 判指针归属；外来指针不得进池的 Free。
- **标记方向**：留少删多数用 Sweep；删少留多数用 FreeMarked——按标记少的一边选。
- **页管理**：`SetRetain` 预热空页、`Trim` 归还、`Reset` 全清；页归池管，业务只碰槽。
- **统计对账**：池化效果用第 6 章 `pooled/backing` 验证；水位用 `live/peak` 规划容量。

### 从示例到工程：池的三个宿主

池句柄的宿主位置决定它的角色。**服务级常驻池**：挂在服务对象上，启动时按容量规划预热（`Reserve` 语义的池版本是预分配首页），运行期只做槽取放——十万连接的网关，连接池就是这种形态。**请求级短命池**：一批处理内创建、批末 Reset 留 Retain 页、彻底结束时 Unit——配合第 7 章 arena 分工（池管对象取放、arena 管临时片段）。**全进程批发层**：第 5 章分配器替换接池——业务代码无感知，分配行为整体池化。三种宿主对池的配置侧重不同：常驻池重容量规划与水位监控、短命池重 Retain/Trim 节奏、批发层重大小分布统计。

## 避坑

### 坑 1：把堆指针 Free 给池

症状：空闲表被外来指针污染，后续分配返回野指针——崩溃点在完全无关的代码里，是最难追的一类事故。

原因：池的 Free 只是"把槽挂回空闲表"，它不校验指针来源（校验有成本，热路径不背）；混入的堆指针下次被当槽分配出去。

```c bad
ptr pObject = xrtMalloc(64);        /* 堆分配 */
/* ... 混乱的代码之后 ... */
xrtPoolFree(&tPool, pObject);        /* 堆指针进池——空闲表被污染 */
```

```c good
ptr pObject = xrtMalloc(64);
/* 不确定来源就先问池 */
if ( xrtPoolOwns(&tPool, pObject) ) {
	xrtPoolFree(&tPool, pObject);
} else {
	xrtFree(pObject);                /* 归还给正确的所有者 */
}
```

### 坑 2：Reset 后继续用之前拿到的槽指针

症状：批量处理后访问旧对象指针，读到新数据或已归还页的内容——"幽灵数据"。

原因：`Reset`/`Sweep`/`Trim` 都是**批量回收**语义，一次性作废全部（或未标记的）槽——此前发出的槽指针全部过期。

```c bad
connection* pConn = xrtPoolAlloc(&tPool);   /* 拿到槽 */
ProcessRequest(pConn);
xrtPoolReset(&tPool);                        /* 批量回收：pConn 已过期 */
Reply(pConn);                                /* 幽灵访问 */
```

```c good
connection* pConn = xrtPoolAlloc(&tPool);
ProcessRequest(pConn);
Reply(pConn);                 /* 用完再回收——指针有效期止于回收点 */
xrtPoolFree(&tPool, pConn);   /* 或交给标记回收在批次边界统一处理 */
```

## 练习

### 基础：LIFO 复现实证

分配 10 个槽，释放第 3 个后立刻分配——断言新地址等于被释放地址；再释放 3 个连续槽，观察复用顺序（后释放的先回来）；最后用 `Visit` 清点活动对象数应为 10-3-1+1（按你的操作序列推一遍再验证）。

### 进阶：请求批处理器（标记回收实战）

用"分配处理 + Sweep 标记回收"实现一批请求：处理过程中存活请求逐个 Mark，批次结束 Sweep 一次性回收未标记者；输出回收数与 `live` 水位。提示：Sweep 方向适合"多数请求完成、少数挂起跨批"的形态。

### 挑战：池化前后对账（用数字证明池的价值）

写一个十万次"取连接-还连接"的模拟：先用裸 `xrtMalloc/xrtFree` 跑一遍、再用固定池跑一遍，两遍都用第 6 章统计记录 `backing` 次数与耗时。验收标准：池化版 backing 次数呈台阶（约每 256 次分配一跳）、耗时显著低于裸堆版；两张对照表随练习输出。

## 速查

| 知识点 | 速查 |
| --- | --- |
| 固定池 | 等大槽 + 分页增长（约 64KB/页）+ LIFO 空闲表复用，槽永不碎片化 |

| 安检 | `Owns` 判归属；外来指针禁止进 Free——混入即空闲表污染 |
| 标记回收 | Sweep 留标记删其余 / FreeMarked 删标记留其余 |
| 页管理 | `SetRetain` 预热、`Trim` 归还空页、`Reset` 全清 |
| 变长池 | 尺寸分桶 + 大块直通；大小混杂负载的池化 |
| 对账工具 | 第 6 章 `pooled/backing` 台阶曲线 + `live/peak` 水位 |
| 与 arena 分工 | 池管"频繁取放"；arena 管"一起回收"；两者常在同一个服务里并肩 |
| 三宿主 | 服务常驻池 / 请求短命池 / 分配器批发层——配置侧重各不同 |
| 构造配对 | Alloc 拿槽→业务构造；析构→还槽；批量用 Visit 收尾 |
