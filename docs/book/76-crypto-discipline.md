## 导读

第 73～75 章给了你全部算法原语——但真实世界里被攻破的系统，绝大多数不是算法被解，而是**系统层误用**：密钥进了日志、比较函数泄漏时序、随机源不对、协议组合自创。本章是前三章的"使用说明书"，也是卷八从原语走向证书与 TLS 前的纪律总结。四个主题：**常量时间纪律**（为什么比较 MAC 必须不早退）、**密钥生命周期**（生成—使用—存储—销毁四段各自的规则与 API）、**随机源纪律**（安全随机与普通随机的分界）、**组合纪律**（不发明协议、失败单一、上下文绑定）。压轴示例 `crypto/session` 把前三章原语组装成一次完整临时会话——它就是 TLS 1.3 的骨架缩微版，第 80 章的握手在它之上只是加上了证书与状态机。

## 引入

看三段真实事故的抽象。其一：某服务的会话令牌校验用 `memcmp`——攻击者测量响应时间，逐字节试出合法令牌：第一个字节对了响应慢几十纳秒，一百万次请求把令牌完整"摸"出来。其二：开发者用 `memset` 清除密钥后释放内存——编译器判定该内存"再无读取"而把清零整个删除，密钥明文留在堆里被后续分配读走。其三：两个模块各自生成"随机"挑战值，用的是可预测的普通随机源——攻击者预测输出，认证形同虚设。

三起事故的共同点：**算法全对，调用全错**。密码学 API 的安全性只在"正确使用"的上下文里成立——`xrtConstTimeEqual`、`xrtSecureZero`、`xrtSecureRandom` 这三个不起眼的函数，就是 XRT 为这三类事故准备的出口。本章把它们与更大的"组合图景"一起讲清楚。

## 概念

### 三层失效模型：误用发生在哪一层

把安全系统想成三层，攻击者永远挑最软的那层：

```diagram flow
- 算法层：AES/SHA/曲线的数学强度——本卷原语已保证，最难成为短板
- 协议层：字段顺序、状态机、上下文绑定、失败路径——自创协议的高发事故区
- 系统层：密钥存放、随机来源、比较方式、日志内容——本章的主战场
```

一个实用自查法：**每写一行密码相关代码，问"这行打破哪一层"**。`memcmp` 比较密文打破系统层；"验证失败但继续处理"打破协议层；选 MD5 打破算法层。三层里算法层最不可能出错（用对 API 即可），所以工程师的注意力应该反过来分配——系统层最多、协议层次之、算法层最少。本章避坑清单全部来自系统层。

### 常量时间纪律：比较也是一种攻击面

`memcmp(Left, Right, N)` 在**第一个不同字节处提前返回**——这个"快"就是漏洞：比较耗时与公共前缀长度成正比，攻击者远程计时即可逐字节恢复秘密（令牌、MAC、密钥）。`xrtConstTimeEqual(Left, Right, N)` 逐位累积差异、最后统一判定，**运行时间只与 N 有关**。两条精确边界：它不隐藏 N 本身（长度公开）；它也不等于完整侧信道防护（功耗、缓存是另一维度）——但在"远程计时"这个最现实的攻击面上，它是必需品。适用对象：MAC/标签比较、令牌比较、共享秘密比较、密文指纹比较——**一切有一侧是秘密的比较**。比较两侧全公开的数据（文件校验、缓存键）用 `memcmp` 即可，常量时间不是免费的性能。

### 密钥生命周期四段

```diagram state
生成 -> 使用: 来源合规（随机源/KDF/交换），永不硬编码
使用 -> 存储: 最小驻留（栈/专用结构），永不入日志与转储
存储 -> 销毁: 离开作用域立即清除
销毁 -> 终态: xrtSecureZero 或专用 Clear，覆盖全部副本
```

- **生成**：对称密钥与私钥一律来自 `xrtSecureRandom`（下一节）或 KDF 派生；测试向量的固定密钥必须像示例那样标注"仅复现用"。
- **使用**：密钥只住在栈缓冲或专用状态结构（`xaesgcm` 的密钥日程、`xed25519key` 的展开态）；**不复制到别的缓冲**——每多一份副本，销毁面就大一分。
- **存储**：密钥**永不**进日志（第 37 章的 Logger 也一样）、不进错误消息、不进交换文件的持久结构（这超出 `xrtSecureZero` 能力——契约原文明确它只覆盖调用给出的区间，编译器寄存器副本、崩溃转储、OS 交换需要系统级措施：mlock、关闭转储、全盘加密）。
- **销毁**：`xrtSecureZero` 用 volatile 写清零，普通 `memset` 可能被编译器按死存储删除（开头的第二起事故）；带状态对象用专属 `Clear`/`KeyClear`（它知道结构里所有敏感角落）。**成功路径与错误路径都要清**——本章示例的 cleanup 段就是模板。

### 随机源纪律：两种随机不可混用

XRT 把随机分成两个世界：普通随机（第 11 章，`xrtFastRandSeed` 播种的序列——快、可种子、可复现）用于测试数据、负载分布、洗牌；**安全随机**（`xrtSecureRandom`）用于一切密钥、令牌、盐、nonce——平台 CSPRNG（Windows CNG、Linux getrandom），不可种子、不可预测。分界的试金石：**这个值被预测会造成安全后果吗？**是就用安全随机——哪怕它慢两个数量级。反向规则同样重要：安全随机不用于可复现场景（测试向量、基准数据）——不是为了性能，而是确定性输出根本不是它的承诺。密码模块通过独立的 `RANDOM_SECURE` 特性依赖随机源（第 73 章裁剪表），文件与网络模块复用基础随机时不会拖入密码算法——这条边界让"随机源的严肃性"与"模块的轻量性"并存。

### 组合纪律：别发明协议

有了原语，最大的诱惑是"自己拼一个加密协议"——四条替代方案与一条铁律：

- **先找现成协议**：传输安全直接用第 80 章的 TLS；令牌用 HMAC 或签名；文件加密用 AEAD 单记录。自创协议的每个决定（字段序、握手状态机、失败语义）都要重新踩一遍业界踩过的坑。
- **失败必须单一**：验证失败即失败——没有"降级继续"、没有"警告但放行"。降级攻击（迫使双方回落到弱参数）利用的就是"失败后继续"的路径。
- **上下文绑定**：派生密钥用 `info` 绑定用途（第 73 章）、加密记录用 AAD 绑定序号与版本（第 74 章）、握手摘要绑定全部握手消息（第 80 章）——**每一层都要把自己"是谁、第几条"写进认证范围**，攻击者才无法把一段合法密文挪到另一个位置重放。
- **临时密钥优先**：能用会话临时密钥就不用长期密钥——泄露半径决定事故大小。TLS 1.3 的前向保密就是这条纪律的极致：每个连接全新 x25519 密钥对，长期私钥只签握手不参与加密。

## 契约

- **常量时间**：`xrtConstTimeEqual` 运行时间只与长度参数成正比；不隐藏长度、非完整侧信道防护；一切"一侧为秘密"的比较必须使用。
- **安全清零**：`xrtSecureZero` volatile 写、不被死存储删除；只覆盖调用给出的区间——编译器寄存器副本、日志、交换文件、崩溃转储需要系统级措施；带状态对象用专属 `Clear`/`KeyClear`。
- **随机源**：安全用途（密钥/盐/nonce/令牌）一律 `xrtSecureRandom`；可复现用途（测试/基准）一律普通随机；密码模块经独立 `RANDOM_SECURE` 特性依赖安全随机。
- **密钥不入非易失记录**：日志、错误消息、异常报告、调试打印零密钥内容——十六进制转储密钥的"调试便利"就是泄露事故。
- **失败单一**：验证失败即失败，无降级继续；错误路径与成功路径执行相同的敏感材料清理。
- **上下文绑定**：KDF 的 info、AEAD 的 AAD、握手的 Transcript 各自绑定用途/序号/身份——密文与它的语境不可分离。
- **临时密钥**：每会话全新密钥对（前向保密）；长期密钥只签名不加密数据。
- **组合优先级**：现成协议 > 标准原语组合 > 自创协议；自创协议的每一步都需要安全评审。

## 避坑

### 坑 1：用 memcmp 比较秘密

症状：远程计时攻击逐字节恢复令牌/MAC——响应时间随公共前缀长度变化，攻击者每字节几千次请求即可锁定。

原因：`memcmp` 在首个不同字节提前返回。功能测试完全正常（结果对），安全属性完全缺失（时序泄漏）。

```c bad
uint8 Mac[XRT_SHA256_SIZE];
xrtHmacSha256(Key, sizeof(Key), Body, iSize, Mac);
if ( memcmp(Mac, SentMac, sizeof(Mac)) == 0 ) {
	accept();   /* 计时侧信道：前缀正确时返回更慢 */
}
```

```c good
uint8 Mac[XRT_SHA256_SIZE];
xrtHmacSha256(Key, sizeof(Key), Body, iSize, Mac);
if ( xrtConstTimeEqual(Mac, SentMac, sizeof(Mac)) ) {
	accept();   /* 耗时只与长度有关，无前缀信息 */
}
```

### 坑 2：用 memset 清密钥

症状：内存审计发现密钥明文残留在已释放内存中；反汇编发现清零代码根本不存在。

原因：编译器看到"memset 之后无读取"，按死存储优化把清零删除——C 标准允许，因为 memset 后的值在抽象机上确实无人使用。

```c bad
void handle_key(uint8* pKey, size_t iSize) {
	use(pKey, iSize);
	memset(pKey, 0, iSize);   /* 被 DSE 优化删除 */
}
```

```c good
void handle_key(uint8* pKey, size_t iSize) {
	use(pKey, iSize);
	xrtSecureZero(pKey, iSize);   /* volatile 写，优化器不可删除 */
}
```

### 坑 3：调试日志打印密钥/令牌

症状：日志收集平台（及其全部下游：检索、备份、三方分析）拿到了生产密钥；轮换密钥的应急响应要花一整晚——日志不可撤回。

原因：开发期"看一眼密钥对不对"的调试打印进了默认日志级别，发布时没人记得删。密钥一旦进入日志系统就完成了不可控扩散。

```c bad
/* 排障时的"顺手一打" */
log_debug("key=%02x%02x... nonce=%02x%02x...",
	Key[0], Key[1], Nonce[0], Nonce[1]);
```

```c good
/* 只打印密钥的存在性与长度，永不打印内容 */
log_debug("key ready: %zu bytes, nonce ready: %zu bytes",
	iKeySize, iNonceSize);
/* 真需要核对时打印密钥的摘要指纹（如 SHA-256 前 8 字节），
   而不是密钥本身 */
```

## 练习

### 基础：计时对比实验

构造两对 32 字节缓冲：一对完全相同、一对仅最后一字节不同。分别用 `memcmp` 与 `xrtConstTimeEqual` 循环比较一千万次并计时，输出四组耗时。验收标准：`memcmp` 在"前 31 字节相同"时明显快于"首字节即异"；`xrtConstTimeEqual` 两组耗时统计上无法区分。

### 进阶：给现有代码做一次密钥审计

回到你第 74 章练习写的记录流通道，逐行标注每类敏感材料（密钥/nonce/明文）的生成、使用、清理位置，检查：有没有用普通随机生成安全值？有没有 memcmp 比较秘密？cleanup 是否覆盖成功路径？修复全部问题并记录修改点。验收标准：审计清单覆盖三层失效模型的系统层全部条目。

### 挑战：把会话示例升级为双向多记录

扩展 `crypto/session`：支持任意条记录的收发——维护 64 位记录序号，nonce 由序号填充（计数器法），AAD 绑定"方向 + 序号"（双向各有独立计数）；最后一条消息后双方主动销毁会话（清密钥并打印 `session destroyed`）。攻击实验：截获第 3 条记录重放——`Open` 必须失败；乱序投递——必须失败。验收标准：正反各 10 条记录全部往返成功；全部敏感材料在销毁段被清零（第 6 章统计对照）。

## 速查

| 知识点 | 速查 |
| --- | --- |
| 三层失效 | 算法层（最难破）< 协议层 < 系统层（最常破）——注意力反向分配 |
| 常量时间 | `xrtConstTimeEqual` 只与长度相关；秘密比较必用；不隐藏长度、非全侧信道 |
| 安全清零 | `xrtSecureZero` volatile 写防 DSE；只覆盖给定区间；状态对象用 `Clear`/`KeyClear` |
| 随机分界 | 安全值（密钥/盐/nonce/令牌）→ `xrtSecureRandom`；可复现值 → 普通随机 |
| 密钥生命周期 | 生成（合规来源）→ 使用（最小驻留）→ 存储（不入日志/转储）→ 销毁（SecureZero） |
| 失败单一 | 验证失败即失败；无降级继续；错误路径同样清理 |
| 上下文绑定 | KDF info 绑用途 / AAD 绑序号与版本 / Transcript 绑身份 |
| 临时密钥 | 每会话全新密钥对；前向保密；长期密钥只签不加密 |
| 组合优先级 | 现成协议 > 标准组合 > 自创；session 示例是标准组合的模板 |
| 会话骨架 | KeyPair → Shared → HKDF(Transcript) → AEAD(AAD=序号) → SecureZero 全清 |
