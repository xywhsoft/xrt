# 主线开发与历史分支整合

2026-11-08 用户明确要求：已经完成历史分支整合，后续默认直接在
`D:/GIT/xrt` 的 `master` 开发；没有特殊技术必要时，不再建立开发分支或独立
工作树，避免额外合并成本。本约定取代此前“每线程 codex/* 分支、单一整合者”
的默认开发方式。用户最新明确指令优先。

## 默认开发位置与提交

- 默认工作目录为 `D:/GIT/xrt`，分支为 `master`。每次开始工作先核对实际分支、
  HEAD 和未提交范围，使用明确的工作目录执行命令。
- 已合入主线的历史分支不再作为开发入口。只有明确的技术隔离需要、外部流程
  要求或用户明确要求时才使用分支，并说明具体原因。
- 每个经过验证的阶段性功能单独提交，只暂存本任务的明确路径。保留其他线程
  的源码、暂存内容和未提交文件，不代为 stash、reset、清理或提交。
- 多线程共享工作树、索引和引用；同一文件或 Git 写操作需要串行，提交前再次
  核对待提交范围。观察到并发变动时保留现场，先解决实际冲突。
- 单头文件、features 和 API 索引从规范源码重新生成，不拼接生成结果。
- 测试必须在实际主线源码上运行；旧分支结果只能作为带源身份的历史证据。
  记录失败、跳过和未完成验收，不用跳过检查制造全绿结果。

## 历史未提交工作迁移

先记录源工作树的 HEAD、修改路径和文件哈希，备份未提交文件以及需要保留的
忽略文件、测试日志和夹具。逐文件确认主线目标的基准内容；有双方修改时按
行为整合，不整文件覆盖另一线程的成果。派生文件重新生成，并在主线回归。
只有源码和必要证据均已验证保留后，才可归档旧工作树；不清理其他线程工作。

## 远端发布

迁移、测试或本地提交本身不授权远端推送。只有用户明确要求发布/同步远端时
才执行发布；发布前获取最新引用，确认包含所有已发布历史，重新验证后普通
推送。遇到非快进拒绝时获取并整合双方历史，禁止强推、force-with-lease、
强制 refspec 或通过 API 覆盖主线。需要 PR 的外部流程属于可说明的分支例外。

- `github`：`https://github.com/xywhsoft/xrt.git`，用于 GitHub/PR/Actions。
- `origin`：`https://gitee.com/xywhsoft/xrt`，主线镜像。
- 已授权的双远端发布完成后核对 `master`、`github/master`、`origin/master`
  的 SHA 和祖先关系；本地新增且尚未授权发布的提交允许领先远端。
- GitHub 主线保护及禁止强制推送规则继续适用。

根目录 `AGENTS.md` 依据现有忽略规则作为本地代理提示。本文件是版本化的共同
规则来源，历史记录保留在 Git 中。
