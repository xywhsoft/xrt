# 发布支持

本页说明发布产物的验证边界。公开头文件、模块清单和自动化测试共同构成当前版本的可交付范围；示例能编译不等同于目标平台已经完成运行验证。

## 发布前检查

发布候选应从干净的输出目录完成：构建模块化库、生成并校验单头包、运行对应平台的测试，以及复核[第三方组件](THIRD_PARTY.md)的许可证。具体命令和产物位置见[构建与发布](BUILD.md)。

跨编译只能证明声明、编译和链接闭包。涉及文件通知、网络后端、TLS、进程或高并发取消的改动，应在目标系统上执行真实收发、关闭和资源回收测试。

## io_uring 门禁

GitHub 托管 Linux runner 可能因 seccomp 禁用 io_uring；在这类环境中，相关检查只保留编译与链接证据。需要 io_uring 的发布候选必须在支持该功能的真实 Linux 内核上运行网络、TLS、取消、超时和关闭测试。显式选择 io_uring 时不得把其他后端的结果当作等价运行证据。

核心与 xhttp 的模块清单当前没有 `developing` 状态的 io_uring 节点。若未来出现待验证节点，应在本节以 `- \`模块名\`` 的形式列出，并在完成真实运行验证后更新清单和本页。

## 平台与后端选择

平台相关能力按模块和构建配置提供。应用在启用可选后端前，应先检查[特性选择](FEATURE_SELECTION.md)中的编译条件，并在实际部署平台上执行自己的集成测试。应用层 HTTP、WebSocket 等扩展能力由其各自发布包维护，不自动成为核心库的兼容性承诺。
