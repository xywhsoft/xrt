# 类型容器共同契约

`xtypedarray`、`xtypedstack`、`xtypedlist`、`xtypedtree`、`xtypedset` 和 `xtypeddict` 在
不同底层数据结构之上共享同一套运行时值契约。本页只定义共同边界；连续存储、后进先出、稀疏
整数键、有序泛型键、唯一值和文本键等特有行为由各模块文档定义。

## 分层与类型身份

类型容器借用不可变 `xrttype` 描述，并通过 `xrtType*Value` 驱动值生命周期。普通 C 容器不
携带引用计数或对象身份；需要弱引用、循环回收和宿主对象时，由 `runtime_object` 把容器作为
对象负载组合起来。

涉及两个类型容器的操作要求元素类型描述指针相同。相同 ID、名称、大小或操作表不足以证明
两个描述的生命周期 ABI 及私有上下文可互换。XRT 内建类型和宿主注册类型应使用进程期
规范描述。

## 所有权

| 操作类别 | 来源和结果 |
| --- | --- |
| `Set`、`Add`、`Push`、`Insert` | 复制来源值；容器拥有新值，来源仍由调用方拥有。 |
| `SetTake` | 失败原子地移动外部值；成功后来源恢复为空值。 |
| `Take`、`Pop` | 移动容器值到已初始化的外部输出；成功后容器不再拥有该值。 |
| `Remove`、`Clear`、`Unit` | 对每个仍被容器拥有的值执行一次 `Drop`。 |
| `Clone`、`Merge`、集合代数 | 深复制值，不共享隐藏的值所有权。 |

所有接受完整类型值地址的复制和查询 API，都允许外部值或同一容器中准确的活动值槽。指向
容器结构、底层元数据、备用容量、分配填充或值槽中间的地址会在读取或修改前拒绝。移动输出和
移动来源必须完全位于容器拥有的内存之外。

## 失败原子性

分配、值初始化、复制或移动失败时，公开可见的元素、键、顺序和所有权保持不变。多步操作先在
独立工作存储上完成，再一次提交；失败清理只销毁本次成功构造的值，并保留下层错误作为原因。
OOM 的最终错误类别始终为 `XERR_MEMORY`。

`Take` 类 API 要求类型移动操作遵守自身失败原子契约：返回失败时不得改变来源或输出。类型
实现若违反该契约，容器无法从任意用户副作用中恢复。

## 回调重入

元素类型的 `Init`、`Copy`、`Move`、`Drop`、`Compare`、`Hash` 和 `Trace` 中，只要该回调
适用于当前容器，同一容器的全部公开 API 都会拒绝并设置 `XERR_STATE`。这包括看似无副作用的
`Count`、`Get` 和迭代启动，也包括 `Unit`、`Destroy` 和结构修改。

门禁只作用于当前容器，不持有操作系统锁、不分配内存，也不阻止回调使用其他容器。统一拒绝
读写重入可避免借用地址逃逸、递归回调、当前值被销毁以及错误状态被内部操作覆盖。

## 借用与迭代

`Get`、`At` 和 `IterNext` 返回借用地址，调用方不得释放，也不得延长到对应容器或元素生命
周期之外。数组的数量或容量变化可能使全部元素地址失效；列表、集合和字典的独立节点地址在
对应元素删除前稳定。

外置迭代器保存结构版本。任何成功改变结构的操作，包括事务合并的最终提交，都会使旧迭代器
失效；下一次推进返回空并设置 `XERR_STATE`。即使提交后的版本数值偶然等于提交前，目标容器
也会生成新的非零版本。自然到达末尾不设置错误，提前停止必须调用对应 `IterEnd`。

## 线程与验证矩阵

同一容器不提供内建并发读写同步；跨线程共享时由调用方保护。不同容器可以并行使用。回调
门禁是生命周期安全规则，不是线程锁。

每个类型容器的发布测试应同时覆盖：

| 维度 | 必须验证的边界 |
| --- | --- |
| 生命周期 | 初始化、复制、移动、销毁各一次且所有权守恒。 |
| 失败 | 分配及用户回调逐点失败后内容和所有权不变。 |
| 别名 | 准确活动槽可复制，部分重叠和内部移动地址被拒绝。 |
| 重入 | 每一种适用用户回调都不能调用同一容器 API。 |
| 迭代 | 修改、合并和清理后旧迭代器可靠失效。 |
| 对象图 | 重复槽形成准确边数，自环在失去外部根后可回收。 |
| 构建 | GCC、TCC、原生、x86、模块化、单头文件和裁剪守卫。 |

## 历史资产

共同契约继承旧版 `dev/ver1/lib/typed_container.h` 的类型生命周期、克隆、合并、集合代数和对象
图能力，也保留 `dev/ver1/test/test_typed_container.h` 与 `test_typed_special.c` 中已经验证的
基础行为。新版测试在这些边界上继续增加失败原子性、内部别名、回调重入、迭代版本、OOM、
32 位和单头文件矩阵，而不是重新发明一套未经验证的容器行为。

旧版每个容器重复的引用计数、堆所有权模式和动态值旁路不属于共同容器职责，分别由对象层、
值层和显式创建/销毁 API 承担。
