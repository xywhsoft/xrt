# XRT 通用运行时对象模型

## 状态与目标

本设计记录 `xruntime` 可独立提供给 C 宿主、插件系统、反射框架和解释器的类型与对象原语。
该体系已从 XRT 核心拆分为显式选择的扩展库，本文约束扩展的稳定模型与实现边界。

模型需要统一表达具有身份的对象、强弱生命周期、动态值、类型化容器、异步结果和
不可达强引用环。它不包含任何具体语言语法、代码生成格式、符号注册表或仓库同步逻辑。

## 统一堆实体

凡是具有独立身份、可以拥有其他运行时对象强引用的实体，都可以建模为 `xrtobject`：

- 应用对象和 native-backed 实例由负载的 `Drop` 释放资源。
- 共享容器作为独立节点，只由容器节点追踪一次元素引用。
- callable 环境、异步状态和生成器状态使用同一对象生命周期契约。
- `xvalue` 继续表达协议数据、动态参数和通用边界值；对象通过显式接口装箱。

引用计数负责正常的确定性析构。`xrtobjectgraph` 只在宿主建立安全点后收集不可达强引用
环，不能用全局锁假定任意负载可在并发修改时被安全读取。

## 类型与追踪

每一种对象或类型化值都使用进程期稳定的 `xrttype`。实例的 `Init`、`Drop` 和 `Trace`
必须服从同一份所有权描述：

- `Init` 建立全部拥有型槽的空状态。
- `Drop` 释放当前拥有的强引用和 native 资源。
- `Trace` 对每个实际强引用槽调用一次访问器。
- 弱引用、借用缓存、代码入口和类型描述不参与强引用追踪。

`runtime_field` 提供名称、类型、偏移和只读事实，供反射、诊断和序列化复用。对象图热
路径只调用实例 `Trace`，不解析反射表，也不猜测对象负载布局。

## 类型转换

类型关系和具体值转换必须分开：

- `xrtTypeCanWiden` 只判断来源类型的全部有效值能否被目标无损表示。
- `xrtTypeCanConvert` 查询 Exact、Widen 或 Explicit 模式下是否存在转换路径。
- `xrtTypeConvert` 转换具体类型槽，失败时保持已初始化目标不变。
- `xrtValueConvertTo` 转换动态 Value 标量，使用相同的模式语义。
- `xrtValueToTyped` 把动态值解码为新初始化的类型化值，不参与重载排序。

格式化直接使用 `xrtTypeFormat`；只有调用方需要拥有型文本时才使用
`xrtTypeToString`，避免为诊断创建多层中间字符串。

## Future 与任务

Future 不保存宿主专用追踪回调。需要跨异步边界持有对象时：

1. 异步状态创建为已跟踪 `xrtobject`。
2. 任务参数销毁回调释放状态对象引用。
3. 队列、运行作业或 continuation 在受理期间持有强引用。
4. 状态对象的 `Trace` 枚举仍然活跃的参数、局部值和错误状态。
5. 任务终结后释放作业引用；只剩不可达环时由对象图收集。

Future 成功值使用明确的拥有型结果和析构回调；失败保留完整 `xerror` 原因链，不能降级
成只可展示的文本。

## 弱引用与外部根

弱引用使用 `xrtweak`，锁定成功后取得普通强引用。所谓 pin 只是宿主持有的显式强引用，
不需要第二套全局注册表。

宿主必须在对象字段和异步状态停止变化后调用收集。拥有型栈槽会通过引用计数自动成为
根；确实只借用对象的槽由 `xrtObjectGraphCollectRoots` 显式枚举。动态 Value 槽使用
`xrtObjectGraphCollectValueRoots` 统一报告，避免共享外壳或 COW backing 隐藏内部对象边。

## 错误与复杂度

追踪失败、类型操作失败和 OOM 使用结构化 `xerror` 并保留 Cause。收集函数不能把失败
伪装成“收集了零个对象”。诊断结果通过 `xrtobjectgraphresult` 返回，不混用负数、全局
整数和错误码。

对象地址索引和边遍历必须保持 `O(N + E)` 目标。发布前至少覆盖自环、双对象环、共享
容器、深图、宽图、重复引用槽、弱引用过期、借用根、追踪失败、OOM 和并发安全点边界。

## 发布结论

- C 宿主、动态调用、对象、对象图、Future、弱引用和动态字段均有独立示例与回归。
- `xvalue` 负责协议和动态边界，类型化容器负责拥有型 C ABI 值，runtime value 只提供
  对象、callable、Future 与弱引用桥接；三者不再维护相互竞争的隐式装箱入口。
- `runtime_core`、`runtime_full` 体积 profile，以及 `runtime_core`、
  `runtime_containers`、`runtime_graph` 性能 profile 随扩展维护。
- XRT 核心清单和 `single/xrt.h` 不包含 xruntime 模块；只有选择扩展产物时才承担代码量。
- 动态字段、对象图和通用 callable 属于语言无关的 xruntime 契约；具体语言语法、符号表、
  代码生成、异常展开和标准库类封装由语言适配层负责。

xruntime 静态库和动态库以“裁剪后的 XRT 闭包 + xruntime”作为一个发布单元，从而允许
扩展实现复用核心内部快速路径，同时不把 `__xrt*` 实现符号升级为跨动态库稳定 ABI。
