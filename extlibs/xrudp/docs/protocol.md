# XRUDP001 协议草案

状态：开发中，尚未冻结或发布。新增功能可以在首次发布前修订本草案及测试向量；
一旦冻结，其他实现依照相同规范互通。未来协议大版本采用不同标识，不做兼容、转换或降级。

## 报文

所有整数大端；不得将 C 结构体直接复制到线上。每个 UDP 数据报只放一个报文，
上限 1200 字节（包含 48 字节头部与 DATA 的 16 字节认证标签）；路径可要求更小。
不依赖 IP 分片。尾随数据、未知类型、非零保留位、长度不匹配均拒绝。

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | 固定 ASCII 标识 XRUDP001 |
| 8 | 1 | HELLO=1、RETRY=2、HANDSHAKE=3、DATA=4 |
| 9 | 1 | 保留，必须为零 |
| 10 | 2 | 负载长度；DATA 包括认证标签 |
| 12 | 4 | 密钥代；握手报文为零，DATA 从一开始 |
| 16 | 16 | 非零连接/会合标识；不作为认证凭据 |
| 32 | 8 | 非零包号，方向内单调递增，不因换钥归零 |
| 40 | 8 | 保留，必须为零 |
| 48 | 可变 | 负载 |

DATA 的完整头部必须参与 AEAD 认证。握手自身依据固定 Noise 配置保护，
协议、双方角色、连接上下文和接收限制必须绑定握手。未完成握手前不交付业务数据。
报文解码器只检查结构；其输出不表示身份、真实性或连接状态已经有效。

数据保护固定为 ChaCha20-Poly1305；nonce 为四个零字节拼接包号的 64 位小端表示，
完整 48 字节头部为 AAD。握手 Split 后的两个方向密钥独立，不允许复用同一个密钥。
包号 UINT64_MAX 留给 Noise REKEY，DATA 在达到这个包号前必须建立新会话。
每个方向密钥最多发送 2^24 包；应用可以设置更低上限，不允许提高。

换钥使用 Noise REKEY：以当前密钥、最大 nonce、空 AAD 加密 32 字节全零，
取输出的前 32 字节为新密钥。密钥代递增，包号不归零。下一代首包的标签验证成功后
接收方才提交新密钥，保留至多一代旧密钥供有界乱序宽限期使用。
接收方可靠地发送 KEY_CONFIRM；发送方收到该代的已认证确认前不能再次更新密钥。
旧确认不能确认新代，未来代确认是已认证的协议错误。重复发送新代数据即可恢复
丢失的首个换钥包，不需要可单独丢失的切换命令。协议驱动负责宽限期退休旧钥与确认重传。
轮换不是当前密钥泄露后的恢复机制；后者需要新的可信握手。

低层 CipherOpen 提交的是密码层防重放状态，不发送 ACK。连接层必须在完整验证流状态、
额度及资源受理后才发送可靠接收 ACK；不能把 CipherOpen 成功当作业务或缓存受理成功。
CipherOpen 在认证前遇到报文格式错误统一返回 AUTH_FAILED；只有标签验证通过后才报告
重复、过旧或解密后协议错误。连接层不能凭伪造的重复包号发送确认、认为路径活跃或更新地址。
解密后的帧数量等协议硬上限违规属于已认证 MALFORMED；本地输出容量不足单独返回 LIMIT。

## DATA 帧

解密后按 type:u8、flags:u8、length:u16、body:length 读取帧。
单包最多 64 帧；整个负载先完成结构验证，连接层再验证状态和资源，最后才交付事件。
无法验证的包不推进防重放或业务状态。

| 类型 | 编号 | body |
| --- | --- | --- |
| PADDING | 0 | 全零字节 |
| PING | 1 | 空 |
| ACK | 2 | delay_us:u32、count:u16、保留零:u16、count 个[first:u64,last:u64]闭区间 |
| STREAM | 3 | stream:u32、offset:u64、数据；flags=1 表示 FIN |
| RESET | 4 | stream:u32、final_offset:u64、reason:u32 |
| MAX_DATA | 5 | 累计连接接收额度:u64 |
| MAX_STREAM_DATA | 6 | stream:u32、累计接收额度:u64 |
| MAX_STREAMS | 7 | 累计可开流数:u32 |
| DATAGRAM | 8 | channel:u32、sequence:u64、数据；flags=1 表示按序号去旧 |
| CLOSE | 9 | reason:u32，不带任意文本 |
| PATH_CHALLENGE / RESPONSE | 10 / 11 | 16 字节挑战值 |
| KEY_CONFIRM | 12 | 已接收密钥代:u32 |
| OPEN | 13 | stream:u32、接收额度:u64、kind:u8、priority:u8、weight:u16 |

帧 flags 除明确列出的位外必须为零。流/通道 ID 不为零；流偏移和数据长度相加不得溢出。
OPEN 的 kind 为 0（字节流）或 1（消息）；priority 为 0..3；weight 不为零。
可靠消息使用字节流上的 u32 长度前缀，不建立第二套可靠性核心。
不可靠消息无分片；非序号模式 sequence 必须为零，序号模式必须大于零。
消息的待发期限使用本地单调时间，不发送需要两端时钟同步的绝对期限。

ACK 最多 32 个区间，包号从一开始，区间按最大包号降序排列，禁止相交或相邻。
相邻区间必须合并，形成唯一表示。连接层额外验证 ACK 没有确认未发出的包。
ACK 只表示传输接收，不能替代业务收据。

接收确认历史最多保留 32 个按降序排列的连续区间，超过时只保留最新区间。
合并相邻区间；未列出的包不是负确认。发送 ACK 后保留历史，以便 ACK 丢失后重发。
确认延迟从所报告最大包号的首次受理时间计算，以微秒饱和到 u32。
ACK-only 包仍可纳入历史，但不能触发 ACK 反馈循环；触发策略由连接驱动控制。
只有流状态、额度和资源受理均成功的包才登记到确认历史。密码层重复不能直接视为已受理；
重发 ACK 前先检查受理历史。已淘汰的旧区间可以不再确认，发送端通过新包号重传未确认数据。

## 防重放

每个接收方向使用固定 1024 位窗口。Check 不修改状态；认证成功并通过必要验证后
Accept 才滑动和标记。巨大包号跳跃的工作量仍有固定上限。重复包或窗口外旧包不交付。
重传可靠数据使用新包号，因此旧报文超出窗口不会让可靠流永久产生缺口。
不得依据未认证包号推进窗口；不会跨不同连接或不同接收方向共享窗口。

## 固定握手组件

仅使用 Noise_IK_25519_ChaChaPoly_SHA256，不协商模式，不降级。
发起方预先可信绑定接收方静态公钥。接收方必须提供可信 pin 或有界、只读的授权回调；
同时提供时二者必须通过。未验证的消息不能触发授权回调。回调不得重入或销毁当前对象。
临时私钥由系统安全随机源生成；确定性临时密钥仅存在于内部测试入口，不作为公共 API。

两条 Noise 消息的长度分别为 96+参数长度和 48+参数长度，参数最多 256 字节。
握手参数只承载协议/权限元数据，不允许作为应用请求执行。接收的参数直到 Noise 完成才可取出。
完整头部、会话连接 ID、角色和应用域的绑定由连接驱动规范化为双方相同的 Prologue。
原始 Noise 组件不自动构造这项绑定，也不负责 Cookie 或线路重传。

读写均先在候选状态上执行，失败清理候选秘密并保留原对象。
成功生成的握手报文由驱动缓存原始字节供重发，不重复调用 Write 推进密码状态。
Split 后立即清理静态私钥副本、临时私钥和握手密码状态；方向密钥只允许转交给一个包保护器，
转交成功即清理原副本，避免相同密钥创建多个从一开始的包号域。
Noise 完成后，接收方仍须验证发起方的最终持钥确认才能发布业务连接。
连接驱动必须保证业务事件在身份、参数、授权与最终确认全部通过后才交付。

## 恢复时间计算

全部时间使用单调微秒。初始 RTT 默认 333ms，初始方差为其一半；定时器粒度下限 1ms。
RTT 样本来自本端发送到收到有效 ACK 的实测间隔；零间隔按 1us 处理，不能相信对端自报 RTT。
首样本直接设置最小值、平滑值与方差。后续最小 RTT 取原始样本最小值，
ACK 延迟最多采信本端配置值（协议上限 25ms），且扣除后不能低于观测最小 RTT。
平滑 RTT 按 7/8 旧值 + 1/8 调整样本；方差按 3/4 旧值 + 1/4 绝对差。

PTO 为平滑 RTT + max(4*方差,1ms) + 最大 ACK 延迟，再做指数退避。
丢失时间阈值为 ceil(9/8*max(最近 RTT,平滑 RTT))，至少 1ms。
整数运算不能溢出或生成零超时；不可表示的期限饱和至 UINT64_MAX。
驱动仍必须以有限的握手、空闲、关闭截止约束连接，不能将饱和期限当作无限存活。
只有有效确认取得真实进展才清零退避；重复/伪造确认不延长连接寿命。
这些公式参考 RFC 9002；实际丢包判定、ACK 合法性和网络发送调度仍由后续恢复核心实现。

## 无状态地址 cookie

Token 固定 40 字节：8 字节大端服务器单调微秒签发时间，后接 32 字节 HMAC-SHA256。
MAC 输入依次为 ASCII 域 XRUDP001/address-cookie（无终止符）、16 字节非零端点域、
32 字节规范初始探测摘要、23 字节规范源地址、8 字节签发时间。
规范地址为 family:u8（4/6）、port:u16、zone:u32、address:16；所有整数大端。
IPv4 地址只占前四字节，尾十二字节与 zone 为零；IPv6 包含接口作用域。
摘要必须绑定客户端连接 ID、目标身份与其他重要探测字段，不能只摘要任意填充字节。

验证器先验证 HMAC，再检查时间；未来签发时间或超过配置寿命的有效 token 视为超时。
最大寿命固定 30 秒，可收紧，不可放宽。期间可接受一代旧服务器密钥供轮换；
服务器重启使用全新随机密钥。地址、端口、接口作用域、端点域或探测内容变化均需重新挑战。
Cookie 不认证身份，也不是一次性业务凭据；不能替代最终持钥确认和应用授权。
算法不分配、不访问网络；实际端点必须先限制响应放大、CPU、每地址速率和总状态数量。
