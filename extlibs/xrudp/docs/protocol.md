# XRUDP001 协议草案

状态：开发中，尚未冻结或发布。新增功能可以在首次发布前修订本草案及测试向量；
一旦冻结，其他实现依照相同规范互通。未来协议大版本采用不同标识，不做兼容、转换或降级。

## 报文

所有整数大端；不得将 C 结构体直接复制到线上。每个 UDP 数据报只放一个报文，
上限 1200 字节（包含 48 字节头部与 DATA 的 16 字节认证标签）；路径可要求更小。
不依赖 IP 分片。尾随数据、未知类型、非零保留位、长度不匹配均拒绝。

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | 固定 ASCII 标识 XRUDP001 |
| 8 | 1 | HELLO=1、RETRY=2、HANDSHAKE=3、DATA=4 |
| 9 | 1 | 保留，必须为零 |
| 10 | 2 | 负载长度；DATA 包括认证标签 |
| 12 | 4 | 密钥代；握手报文为零，DATA 从一开始 |
| 16 | 16 | 非零连接/会合标识；不作为认证凭据 |
| 32 | 8 | 非零包号，方向内单调递增，不因换钥归零 |
| 40 | 8 | 保留，必须为零 |
| 48 | 可变 | 负载 |

DATA 的完整头部必须参与 AEAD 认证。握手自身依据固定 Noise 配置保护，
协议、双方角色、连接上下文和接收限制必须绑定握手。未完成握手前不交付业务数据。
报文解码器只检查结构；其输出不表示身份、真实性或连接状态已经有效。

数据保护固定为 ChaCha20-Poly1305；nonce 为四个零字节拼接包号的 64 位小端表示，
完整 48 字节头部为 AAD。握手 Split 后的两个方向密钥独立，不允许复用同一个密钥。
包号 UINT64_MAX 留给 Noise REKEY，DATA 在达到这个包号前必须建立新会话。
每个方向密钥最多发送 2^24 包；应用可以设置更低上限，不允许提高。

换钥使用 Noise REKEY：以当前密钥、最大 nonce、空 AAD 加密 32 字节全零，
取输出的前 32 字节为新密钥。密钥代递增，包号不归零。下一代首包的标签验证成功后
接收方才提交新密钥，保留至多一代旧密钥供有界乱序宽限期使用。
接收方可靠地发送 KEY_CONFIRM；发送方收到该代的已认证确认前不能再次更新密钥。
旧确认不能确认新代，未来代确认是已认证的协议错误。重复发送新代数据即可恢复
丢失的首个换钥包，不需要可单独丢失的切换命令。协议驱动负责宽限期退休旧钥与确认重传。
轮换不是当前密钥泄露后的恢复机制；后者需要新的可信握手。

低层 CipherOpen 提交的是密码层防重放状态，不发送 ACK。连接层必须在完整验证流状态、
额度及资源受理后才发送可靠接收 ACK；不能把 CipherOpen 成功当作业务或缓存受理成功。
CipherOpen 在认证前遇到报文格式错误统一返回 AUTH_FAILED；只有标签验证通过后才报告
重复、过旧或解密后协议错误。连接层不能凭伪造的重复包号发送确认、认为路径活跃或更新地址。
解密后的帧数量等协议硬上限违规属于已认证 MALFORMED；本地输出容量不足单独返回 LIMIT。

## DATA 帧

解密后按 type:u8、flags:u8、length:u16、body:length 读取帧。
单包最多 64 帧；整个负载先完成结构验证，连接层再验证状态和资源，最后才交付事件。
认证或结构验证失败的包不推进防重放或业务状态。密码层成功后仍需完整连接状态预检；
已认证的连接协议违规直接终结，不能因为部分帧合法而交付数据或确认。

| 类型 | 编号 | body |
| --- | --- | --- |
| PADDING | 0 | 全零字节 |
| PING | 1 | 空 |
| ACK | 2 | delay_us:u32、count:u16、保留零:u16、count 个[first:u64,last:u64]闭区间 |
| STREAM | 3 | stream:u32、offset:u64、数据；flags=1 表示 FIN |
| RESET | 4 | stream:u32、final_offset:u64、reason:u32 |
| MAX_DATA | 5 | 累计连接接收额度:u64 |
| MAX_STREAM_DATA | 6 | stream:u32、累计接收额度:u64 |
| MAX_STREAMS | 7 | 累计可开流数:u32 |
| DATAGRAM | 8 | channel:u32、sequence:u64、数据；flags=1 表示按序号去旧 |
| CLOSE | 9 | reason:u32，不带任意文本 |
| PATH_CHALLENGE / RESPONSE | 10 / 11 | 16 字节挑战值 |
| KEY_CONFIRM | 12 | 已接收密钥代:u32 |
| OPEN | 13 | stream:u32、接收额度:u64、kind:u8、priority:u8、weight:u16 |

帧 flags 除明确列出的位外必须为零。流/通道 ID 不为零；流偏移和数据长度相加不得溢出。
OPEN 的 kind 为 0（字节流）或 1（消息）；priority 为 0..3；weight 不为零。
可靠消息使用字节流上的 u32 长度前缀，不建立第二套可靠性核心。
不可靠消息无分片；非序号模式 sequence 必须为零，序号模式必须大于零。
消息的待发期限使用本地单调时间，不发送需要两端时钟同步的绝对期限。

ACK 最多 32 个区间，包号从一开始，区间按最大包号降序排列，禁止相交或相邻。
相邻区间必须合并，形成唯一表示。连接层额外验证 ACK 没有确认未发出的包。
ACK 只表示传输接收，不能替代业务收据。

接收确认历史最多保留 32 个按降序排列的连续区间，超过时只保留最新区间。
合并相邻区间；未列出的包不是负确认。发送 ACK 后保留历史，以便 ACK 丢失后重发。
确认延迟从所报告最大包号的首次受理时间计算，以微秒饱和到 u32。
ACK-only 包仍可纳入历史，但不能触发 ACK 反馈循环；触发策略由连接驱动控制。
只有流状态、额度和资源受理均成功的包才登记到确认历史。密码层重复不能直接视为已受理；
重发 ACK 前先检查受理历史。已淘汰的旧区间可以不再确认，发送端通过新包号重传未确认数据。

## 可靠流接收与额度

接收半部使用固定容量数据环及逐字节存在位图，容量为 256B..1MiB 的二次幂，默认 64KiB。
构造后不按片段分配；恶意小片段不能增加元数据数量。外层先查询实际分配大小，
保留端点/连接预算后再构造，不能仅依赖单流上限防止多流耗尽内存。
按顺序消费连续数据，缺口返回待等，只有已知最终偏移且消费完才报告 EOF。

公布的 MAX_STREAM_DATA 为累计绝对额度，初始可以为零。读取释放物理窗口，
但不隐式扩大对端权限；驱动显式扩大额度并重发最新值，额度不超过消费偏移加容量。
连接总流控按各流最高偏移之和计费，包括乱序缺口，不能仅按实际收到的有效载荷计费。
未消费的重叠数据必须逐字节一致；已消费旧内容不再保存，仅忽略迟到重复。

FIN 与 RESET 约定唯一最终偏移，不得低于已观察最高偏移或超过已公布额度；
后续数据不能超过最终偏移。RESET 将未消费的逻辑偏移（含缺口）一次性计为消费，
清理缓冲明文；重复 RESET 不重复归还额度，改变最终偏移/原因视为违规。
干净 EOF 已消费后收到匹配 RESET 不改变已经完成的结果。
所有单帧预检先完成再修改数据，失败不部分填充缺口。
同包 STREAM 批次最多 64 帧，编码长度总和不超过一个受保护 UDP 数据报的负载容量。
纯预检覆盖跨帧重叠及最终偏移，按各流最高偏移相对既有水位的差额合计连接额度；
只有全批通过才写入任何流，失败不返回部分额度或部分数据。批次不产生回调或分配。
连接仍须统一预检 ACK、OPEN、RESET、其他控制帧及权限/生命周期，全部受理后才登记 ACK。

## 可靠流发送与副本确认

发送半部固定容量 256B..1MiB，默认 64KiB。数据被复制到有界环，确认前保留；
应用写入可以只接收可用前缀，入队成功不表示业务成功或远端已收到。
累计字节偏移不回绕；公布的远端额度仅可单调扩大。发送最高偏移增量用于连接总额度，
重复副本不得重复扣除。即使有高偏移已发送，也不能确认仍未发送的中间空洞。

每个数据字节独立标识已发送、已确认及待发状态，固定分层位图定位待发位置，
不随包/片段数量分配元数据。丢失使尚未确认的范围重新可发；新包号承载重传副本。
任意副本被确认即确认逻辑字节，其他副本之后丢失不会复活该字节。
只有连续前缀确认后才回收环空间；乱序已确认尾部仍留在固定预算内。

FIN 固定在停止写入时的最终偏移，可以单独重传；FIN 被确认不表示前面的缺口已确认。
发送半部完成须同时满足 FIN 确认及所有内容确认。PTO 可以探测仍在途的最旧未确认范围，
但只能由恢复驱动授权，仍受探测次数、pacing 与拥塞预算限制。
取消立即清空明文与位图，旧包引用由驱动排空后才能销毁对象。
此缓冲不拥有包号，不自行解析对端 ACK；只有经发送记录验证的最终包事件能解析为字节反馈。

## 双向字节流会话配置

完整握手后的默认双向字节流 ID 为 1，无需另一条 OPEN；占用双方各一个开流额度。
会话核心的 StreamCapacity=N（1..64），Local.MaxStreams<=N；默认 N=1。
构造时预留 2*N-1 对固定接收/发送环：默认流一对，本端/对端各 N-1 个额外流槽。
所有流共用密码器、包号、ACK、发送记录、连接额度与 NewReno/pacing，不各建拥塞连接。
消息类型、游戏 DATAGRAM 与路径迁移尚未启用，不以结构编码器已识别帧作为功能完成的依据。

额外流由可信握手角色分配：发起方依次 3,5,7…，响应方依次 2,4,6…。
ordinal=id/2+1，默认流在双方均占 ordinal 1；MAX_STREAMS 是累计最大 ordinal，
上限 2^31，不是当前活跃数。ID 从不复用；退休一条对端发起的流后可靠公布递增额度。
流槽可按完成顺序复用，长期占用较小 ID 不阻止另一槽反复开流和退休。
接纳新 OPEN 要求 ordinal 连续；同包可乱序排列多个连续 OPEN，STREAM 可先于其 OPEN。
较早 OPEN 丢失时，尚未接纳的后续 OPEN/STREAM 返回暂时背压，整包不提交、不 ACK；
发送方按原内容使用新包号重传，不能期待同一加密包重新进入业务提交。
密码层已认证的新密钥代仍可单独确认，不能因此错误确认尚未接纳的包。
所有较小 ordinal 均已开过，已不存在的较小 ID 因而确定为退休流；晚到内容不重开、不再次计费。
不保存随连接寿命增长的墓碑列表；固定槽与累计水位足以区分未来开流和退休流。

本端优先级 0..3、权重 1..16；对端线上权重虽为非零 uint16，调度服务上限仍裁为 16。
采用有界亏额轮转，量子为 1200*min(weight,16)*(4-priority) 字节；仅 UDP 受理成功后
按整包线路字节扣除，空闲流不积攒无限额度。最早未发送 OPEN 优先，避免主动制造 ordinal 缺口。
RESET 只取消本端发送半部，最终偏移取实际最高发送位置，不把未发送缓存收取为对端额度。
取消半部忽略后续流额度，不以未使用的额度反复刷新有用进展截止。
退休要求发送 FIN/RESET 已确认、接收 EOF 已消费或已 RESET、OPEN 已确认且全部包副本引用排空。
退休默认流 1 被拒绝；半部对象清除明文与位图后无分配重启，旧包事件不可能落入新流槽。
核心通过固定合并事件提供对端开流、读写就绪、发送完成、EOF 与退休就绪，不在事务中回调。
RETIRE_READY 在两半结束、OPEN 确认且所有旧包引用排空时发出；若之后发送流额度控制包
重新持有引用，清除尚未提取的提示，待引用再次排空时重新提示。应用仍须重检当前状态。
原生 PeerStream* API 提供额外流操作；StreamChanged 同时覆盖额外流和默认流 1。
每次通知在进入应用前提取最多 8 条提示，批次间隔至少 1ms；回调中新建提示在后续批次交付。
应用回调可回收流、读写或关闭/释放自有句柄；已退休 ID 的旧批次提示丢弃，关闭后停止余下派发。
Changed 继续提供默认流提示，并在对端累计开流额度增长时给出 STREAMS_READY；
本端槽退休及该额度提示均可用来重试 Open，不靠轮询等候。活跃流状态仅限所有者查询，
关闭后高级流操作返回 CLOSED，不再访问 Engine；连接整体保留不可变的关闭统计快照。

会话拥有固定接收/发送环、最多 256 个普通包位置和额外 32 个恢复位置，以及同等有界的
引用/最终事件空间。构造前查询包含密码器的总逻辑字节并预留；构造失败不接管密码器。
所有操作由一个所有者串行执行，处理输入、维护、读写、取消和销毁不再分配。
输出回调必须复制后才返回受理成功，不可重入或销毁会话；暂时背压/内存不足不消耗
逻辑发送额度、不授予确认、不创建发送记录，后续使用新包号重试而不会复用 nonce。

ACK、STREAM、RESET、额度及控制状态在完整预检后统一提交，不逐帧提前回调。
同包重叠 ACK 不重复完成，流偏移、FIN 和 RESET 在整个包内一致；连接额度按最高偏移
增量核算，RESET 消费缺口一次归还连接额度。读取自动扩大本配置的滑动接收额度，
最新额度在丢包/ACK 丢失后重发至确认。零额度仍允许偏移零的空 FIN。

每次维护最多受理 8 个输出包，真实 PTO 只授予 2 个探测且不宣布全部在途丢失。
ACK-only 按本地间隔限速；只对受理历史里的 eliciting 重复包重新触发 ACK，避免 ACK-of-ACK。
512B 数据报可以只编码最新的一部分 ACK 区间，为控制和数据保留空间；遗漏不是负确认。
所有 eliciting 控制、数据和探测共享 NewReno/pacing，不允许游戏/控制绕过在途硬上限。
每个 eliciting 输出携带当前接收密钥代确认；新代输入可触发受拥塞管理的确认 PING，
确认或其 ACK 丢失由 PTO 恢复，旧接收密钥宽限为 3 个基础 PTO，收紧在 1..60 秒内。

新受理的认证包才刷新空闲，重复/过旧/伪造包不会续命。另设 1 秒..10 分钟的有用进展截止，
默认 30 秒；有待确认数据/FIN/额度时启用，只有真实数据、最终大小、额度或其确认取得进展
才延长。单纯 PING/探测 ACK 只可清零网络 PTO 退避，不能无限延长卡住的应用工作。
不带时间参数的本地读写在空闲后首次产生工作时，于下一次 Poll/Input 观察到当前时间后
启动一次进度截止，不沿用上次空闲维护的旧时间；后续本地操作不能借此重新计时。
维护返回下一次单调微秒截止，调用方在该时刻以及读写/接收后驱动；时钟倒退拒绝，
到 UINT64_MAX 终结，饱和值不表示无限存活。底层包保护使用不分配诊断的 AEAD 尝试入口，
坏标签作为不可信流量丢弃；本地输出容量不足和认证后的协议错误分别处理。

## 密码层防重放窗口

每个接收方向使用固定 1024 位窗口。Check 不修改状态；认证成功并通过必要验证后
Accept 才滑动和标记。巨大包号跳跃的工作量仍有固定上限。重复包或窗口外旧包不交付。
重传可靠数据使用新包号，因此旧报文超出窗口不会让可靠流永久产生缺口。
不得依据未认证包号推进窗口；不会跨不同连接或不同接收方向共享窗口。

## 固定握手组件

仅使用 Noise_IK_25519_ChaChaPoly_SHA256，不协商模式，不降级。
发起方预先可信绑定接收方静态公钥。接收方必须提供可信 pin 或有界、只读的授权回调；
同时提供时二者必须通过。未验证的消息不能触发授权回调。回调不得重入或销毁当前对象。
临时私钥由系统安全随机源生成；确定性临时密钥仅存在于内部测试入口，不作为公共 API。

两条 Noise 消息的长度分别为 96+参数长度和 48+参数长度，参数最多 256 字节。
握手参数只承载协议/权限元数据，不允许作为应用请求执行。接收的参数直到 Noise 完成才可取出。
完整头部、会话连接 ID、角色和应用域的绑定由连接驱动规范化为双方相同的 Prologue。
原始 Noise 组件不自动构造这项绑定，也不负责 Cookie 或线路重传。

读写均先在候选状态上执行，失败清理候选秘密并保留原对象。
成功生成的握手报文由驱动缓存原始字节供重发，不重复调用 Write 推进密码状态。
Split 后立即清理静态私钥副本、临时私钥和握手密码状态；方向密钥只允许转交给一个包保护器，
转交成功即清理原副本，避免相同密钥创建多个从一开始的包号域。
Noise 完成后，接收方仍须验证发起方的最终持钥确认才能发布业务连接。
连接驱动必须保证业务事件在身份、参数、授权与最终确认全部通过后才交付。

## 固定线上握手配置

握手头仍为通用 48B，非 DATA 的 key_epoch=0。初始 scope 为非零公开监听/协调 ID。
HELLO（PN=1，目标 scope）负载固定 96B：client_id:16、目标静态公钥:32、随机 nonce:16、
应用上下文:32。ID/nonce 均不为零；客户端 ID 不与 scope 相同。上下文可为全零，
mdo 则应使用已授权协调通道下发的上下文并在监听侧要求精确匹配。

HELLO 摘要为完整规范 HELLO 报文的 SHA256。RETRY（PN=1，目标 client_id）负载 88B：
server_id:16、HELLO 摘要:32、地址 cookie:40。server_id 为 SHA256 的前 16 字节，
输入为 ASCII XRUDP001/server-id（不含终止符）、HELLO 摘要、cookie；禁止零值与 ID 冲突。
cookie 的原有 HMAC 同时绑定 scope、HELLO 摘要、源地址和签发时间。
RETRY 仅 136B，不放大初始 144B HELLO；监听端仍须先应用每地址/端点 CPU 与响应配额。

客户端向 server_id 发送 HANDSHAKE（PN=1）：HELLO 负载 96B、cookie 40B、Noise 第一飞行
128B，共 312B。接收侧先查现有 CID，再验证 cookie、上下文与派生 server_id，最后才允许
预留状态并执行 DH，不能让有效 cookie 重复创建同一活动连接。
Noise Prologue 固定为 ASCII XRUDP001/IK/prologue（无终止符）+ scope:16 + HELLO 负载:96
+ server_id:16，共 148B；角色和方向由固定 IK 模式定义。应用上下文、公钥与两个连接 ID
因此参与认证，不能只存在于未认证的外部元数据里。
服务端第二 HANDSHAKE（PN=2，目标 client_id）仅带 Noise 第二飞行 80B，共 128B。

Noise 加密参数固定 32B，大端：connection_credit:u64、stream_credit:u32、max_streams:u32、
idle_timeout_ms:u32、max_ack_delay_us:u32、datagram_size:u32、保留零:u32。
初始连接额度至多 64MiB，流额度至多 1MiB，流数 1..1024，空闲截止 1s..1h，
ACK 延迟至多 25ms，数据报上限 512..1200B；本地实际分配仍受更严格的全局预算约束。
双方公布独立接收额度，不将对端参数当成本端可以无限分配的配置。

Noise 派生完成仍不发布业务连接。客户端首次 DATA（epoch=1、PN=1）仅含 PING 和
KEY_CONFIRM(1)；服务端验证后首次 DATA（epoch=1、PN=1）依次含 PING、KEY_CONFIRM(1)、
ACK(delay=0,range=[1,1])。提前 STREAM 或任何其他证明形状拒绝，且不交付应用数据。
客户端验证该回复后建立；服务端先验证客户端证明并排队回复后才向应用发布。
业务包从 PN=2 开始，连接接收历史与发送退休前缀必须初始化为证明占用的 PN=1。
发送窗口可从可信本地退休水位构造；ACK 只覆盖该前缀时没有新完成或 RTT，
ACK 同时覆盖前缀及新业务包时，只完成实际保留的新包，不能把旧证明当作新的进展。

各阶段重传缓存完全相同的原始报文，不能再次推进 Noise 或重新加密另一份 PN=1 内容。
发送间隔从 250ms 指数增长至 2s；每阶段至多 16 次，总截止默认 10s、可选 1..60s，
不会因重复输入延长。Cookie 最多 30s，超长断链应在外层创建全新握手，而不是续签旧 Cookie。
已建立服务端短期保留最终回复供丢失恢复，转交密钥不会销毁该缓存；端点必须有限退休。
只有认证后才能判定协议违规，本地输出容量不足不能充当认证依据。

## 恢复时间计算

全部时间使用单调微秒。初始 RTT 默认 333ms，初始方差为其一半；定时器粒度下限 1ms。
RTT 样本来自本端发送到收到有效 ACK 的实测间隔；零间隔按 1us 处理，不能相信对端自报 RTT。
首样本直接设置最小值、平滑值与方差。后续最小 RTT 取原始样本最小值，
ACK 延迟最多采信本端配置值（协议上限 25ms），且扣除后不能低于观测最小 RTT。
平滑 RTT 按 7/8 旧值 + 1/8 调整样本；方差按 3/4 旧值 + 1/4 绝对差。

PTO 为平滑 RTT + max(4*方差,1ms) + 最大 ACK 延迟，再做指数退避。
丢失时间阈值为 ceil(9/8*max(最近 RTT,平滑 RTT))，至少 1ms。
整数运算不能溢出或生成零超时；不可表示的期限饱和至 UINT64_MAX。
驱动仍必须以有限的握手、空闲、关闭截止约束连接，不能将饱和期限当作无限存活。
只有有效确认取得真实进展才清零退避；重复/伪造确认不延长连接寿命。
这些公式参考 [RFC 9002](https://www.rfc-editor.org/rfc/rfc9002.html)。

## 发送记录与丢失事件

发送端记录实际送交 UDP 的每个 DATA 包，含 ACK-only，包号严格递增；发送失败可以留空洞。
有界环形历史的普通容量默认 256、上限 4096，额外保留 32 个 PTO 探测位置；
不能先发送再发现记录空间不足。未来 ACK 或覆盖当前保留区间内未发空洞的 ACK 整包拒绝，
不得部分完成。已退休的旧历史不再授予完成/字节额度；不将未知旧历史误判为新进展。

每个包只交付一次 ACKED、LOST、EXPIRED 或 CANCELLED 最终事件，携带原始数字标识；
声明丢失后迟到的 ACK 不再次交付完成。可靠数据由上层使用新包号重传并按流偏移去重。
ACK-eliciting 及包含 PADDING 的包均计入在途字节，不可靠游戏消息也占用拥塞预算。
仅 ACK-only 元数据可按保守寿命退休且不引发拥塞丢失；不得形成 ACK-of-ACK。

包丢失阈值为最大已确认包号领先至少 3，或该包位于最大已确认包之前且发送时间超过
RTT 组件计算的时间阈值。PTO 触发本身不把全部在途数据判丢。重复 ACK 不重新提供 RTT 样本；
只有最大 ACK 包仍为新确认且包含新确认的 ACK-eliciting 包时才采样。
处理事件输出不足时无状态变更，所有包/标识仍由原有所有者持有。
发送记录提供无副作用 ACK 预检，报告准确的最终事件容量和候选 RTT/进展；
连接先验证同包全部数据/控制帧，再提交 ACK，并在统一事务完成后交付回调。
探测次数、有限截止、重传内容与发送公平性仍须由连接恢复驱动实现。

## 拥塞策略与发送节奏

所有在途数据共用一个 NewReno 窗口。初始窗口 12,000 字节，最小 2,400 字节；
本地最大值默认 4MiB，可配置范围 12,000..64MiB，不由对端协商扩大。
慢启动按新确认的在途字节增长；拥塞避免累计确认字节，每完成当前窗口的字节额度增加
一个 1,200 字节数据报。应用或流控受限时不增窗；本地容量到顶不积存增长额度。

第一次新丢失将窗口减半（不低于最小值），记录当前最大已发送包号为恢复水位。
同一水位内后续丢失不反复减窗，旧包确认也不增长窗口。
同一次 ACK 引起的丢失先于确认增长处理；取消、ACK-only 退休不表示拥塞。
持续拥塞必须由驱动以连续丢失和实测 RTT 证据判定，随后收缩到最小窗口；
单次 PTO 不能调用这个入口。策略公式参考 RFC 9002 第 7 节，不复用 QUIC 的线上协议。

pacing 使用本地平滑 RTT 与窗口确定平均速率，以 GCRA 限制瞬时最多约两数据报的突发，
无论空闲多久均不积累额外信用。计算使用饱和整数算术，避免宽整数编译器依赖。
PTO 探测可暂时超过窗口，但仍受 pacing、发送记录预留和硬在途上限约束；
驱动每次真实 PTO 最多授权两个包，不能将所有重传或游戏数据标成探测。
ACK-only 可以及时发送，但端点必须单独限制控制流量、地址反射与 CPU 工作量。
拥塞组件只消费发送记录产生的可信、唯一最终事件，调用方不得重复消费事件。

## 无状态地址 cookie

Token 固定 40 字节：8 字节大端服务器单调微秒签发时间，后接 32 字节 HMAC-SHA256。
MAC 输入依次为 ASCII 域 XRUDP001/address-cookie（无终止符）、16 字节非零端点域、
32 字节规范初始探测摘要、23 字节规范源地址、8 字节签发时间。
规范地址为 family:u8（4/6）、port:u16、zone:u32、address:16；所有整数大端。
IPv4 地址只占前四字节，尾十二字节与 zone 为零；IPv6 包含接口作用域。
摘要必须绑定客户端连接 ID、目标身份与其他重要探测字段，不能只摘要任意填充字节。

验证器先验证 HMAC，再检查时间；未来签发时间或超过配置寿命的有效 token 视为超时。
最大寿命固定 30 秒，可收紧，不可放宽。期间可接受一代旧服务器密钥供轮换；
服务器重启使用全新随机密钥。地址、端口、接口作用域、端点域或探测内容变化均需重新挑战。
Cookie 不认证身份，也不是一次性业务凭据；不能替代最终持钥确认和应用授权。
算法不分配、不访问网络；实际端点必须先限制响应放大、CPU、每地址速率和总状态数量。

## 原生端点与所有权

原生端点使用调用方已运行的 XRT Worker；每个端点为一个 IPv4 或 IPv6-only UDP socket。
入口以固定 64 个 IP 桶和总速率限制新握手计算/响应；RETRY 小于 HELLO，验证 cookie 后
才分配半开状态。连接 ID 去重且数据源地址必须与原握手完全相同；地址迁移仍待协议实现。
peer、半开、逻辑内存、发送包数/字节与接收批次都有固定上限；保留关闭句柄仍计费。
多个 peer 共用 UDP 输出队列：成功受理一个 peer 的报文后，从其后开始下一维护轮次。
受阻 peer 在既有固定槽中登记等待，不分配队列结点；等待次序只在成功受理后推进，
本地拒收不推进次序。新输入先给一个更早受阻 peer 重试机会；未轮到的发送暂缓，避免
接收回调绕过队列。当前没有可发送内容时撤去登记；关闭移除登记且仍检查所有 peer 截止，
不让拥塞/流控等待造成跨连接队首阻塞，也不为公平服务放开单连接拥塞、pacing 或发送硬上限。
握手前预留整个配置流池的峰值字节，最终服务端证明排队前构造会话；Confirmed 同时保证
身份/持钥及所有配置流槽资源受理成功，随后可开流/读写。来源不符或未受理内容不记为可靠接收 ACK。
就绪提示按边缘合并，回调内读写产生的后续事件在另一次工作循环交付；外部关闭请求可使
回调中后续读写返回 CLOSED，终结只交付一次。取消可尽力发送一份有界 CLOSE，随后立即排空
本地所有权；这份至多一个数据报的本地取消提示不代表优雅关闭或对端收据。
先关闭端点并等待 peer、UDP、定时器全部终结，才可停止 Engine；关闭不依赖新分配。
回调借用句柄，跨回调保留须显式 Ref；已关闭句柄不再保留引擎资源，可在引擎销毁后释放。
