# XRUDP001 协议草案

状态：开发中，尚未冻结或发布。新增功能可以在首次发布前修订本草案及测试向量；
一旦冻结，其他实现依照相同规范互通。未来协议大版本采用不同标识，不做兼容、转换或降级。

## 报文

所有整数大端；不得将 C 结构体直接复制到线上。每个 UDP 数据报只放一个报文，
上限 1200 字节（包含 48 字节头部与 DATA/PATH 的 16 字节认证标签）；路径可要求更小。
不依赖 IP 分片。尾随数据、未知类型、非零保留位、长度不匹配均拒绝。

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | 固定 ASCII 标识 XRUDP001 |
| 8 | 1 | HELLO=1、RETRY=2、HANDSHAKE=3、DATA=4、PATH=5 |
| 9 | 1 | 保留，必须为零 |
| 10 | 2 | 负载长度；DATA/PATH 包括认证标签 |
| 12 | 4 | 密钥代；握手报文为零，DATA/PATH 从一开始 |
| 16 | 16 | 非零连接/会合标识；不作为认证凭据 |
| 32 | 8 | 非零包号，方向内单调递增，不因换钥归零 |
| 40 | 8 | 保留，必须为零 |
| 48 | 可变 | 负载 |

DATA/PATH 的完整头部必须参与 AEAD 认证。握手自身依据固定 Noise 配置保护，
协议、双方角色、连接上下文和接收限制必须绑定握手。未完成握手前不交付业务数据。
报文解码器只检查结构；其输出不表示身份、真实性或连接状态已经有效。

PATH 复用 DATA 的方向密钥、唯一包号、防重放与账本，固定为总长 84..128B、包号至少 2。
它只能包含至少一个 PATH_CHALLENGE/RESPONSE 及可选 KEY_CONFIRM/PADDING；不承载业务、
ACK 或 PING。CipherSeal 对满足此条件的短控制负载自动选择 PATH，其余仍为 DATA。
密文解开后先检查 PATH 内容，违规不提交密码器状态。类型属于 AAD，修改 DATA/PATH
分类会破坏标签；不能仅改头部就绕过验密。它是当前未冻结草案的修订，不提供旧版本转换。

数据保护固定为 ChaCha20-Poly1305；nonce 为四个零字节拼接包号的 64 位小端表示，
完整 48 字节头部为 AAD。握手 Split 后的两个方向密钥独立，不允许复用同一个密钥。
包号 UINT64_MAX 留给 Noise REKEY，DATA 在达到这个包号前必须建立新会话。
每个方向密钥最多发送 2^24 包；应用可以设置更低上限，不允许提高。

换钥使用 Noise REKEY：以当前密钥、最大 nonce、空 AAD 加密 32 字节全零，
取输出的前 32 字节为新密钥。密钥代递增，包号不归零。下一代首包的标签验证成功后
接收方才提交新密钥，保留至多一代旧密钥供有界乱序宽限期使用。
接收方可靠地发送 KEY_CONFIRM；发送方收到该代的已认证确认前不能再次更新密钥。
旧确认不能确认新代，未来代确认是已认证的协议错误。重复发送新代数据即可恢复
丢失的首个换钥包，不需要可单独丢失的切换命令。协议驱动负责宽限期退休旧钥与确认重传。
轮换不是当前密钥泄露后的恢复机制；后者需要新的可信握手。

低层 CipherOpen 提交的是密码层防重放状态，不发送 ACK。连接层必须在完整验证流状态、
额度及资源受理后才发送可靠接收 ACK；不能把 CipherOpen 成功当作业务或缓存受理成功。
CipherOpen 在认证前遇到报文格式错误统一返回 AUTH_FAILED；只有标签验证通过后才报告
重复、过旧或解密后协议错误。连接层不能凭伪造的重复包号发送确认、认为路径活跃或更新地址。
解密后的帧数量等协议硬上限违规属于已认证 MALFORMED；本地输出容量不足单独返回 LIMIT。

## DATA 帧

解密后按 type:u8、flags:u8、length:u16、body:length 读取帧。
单包最多 64 帧；整个负载先完成结构验证，连接层再验证状态和资源，最后才交付事件。
认证或结构验证失败的包不推进防重放或业务状态。密码层成功后仍需完整连接状态预检；
已认证的连接协议违规直接终结，不能因为部分帧合法而交付数据或确认。

| 类型 | 编号 | body |
| --- | --- | --- |
| PADDING | 0 | 全零字节 |
| PING | 1 | 空 |
| ACK | 2 | delay_us:u32、count:u16、保留零:u16、count 个[first:u64,last:u64]闭区间 |
| STREAM | 3 | stream:u32、offset:u64、数据；flags=1 表示 FIN |
| RESET | 4 | stream:u32、final_offset:u64、reason:u32 |
| MAX_DATA | 5 | 累计连接接收额度:u64 |
| MAX_STREAM_DATA | 6 | stream:u32、累计接收额度:u64 |
| MAX_STREAMS | 7 | 累计可开流数:u32 |
| DATAGRAM | 8 | channel:u32、sequence:u64、数据；flags=1 表示按序号去旧 |
| CLOSE | 9 | reason:u32，不带任意文本 |
| PATH_CHALLENGE / RESPONSE | 10 / 11 | 16 字节挑战值 |
| KEY_CONFIRM | 12 | 已接收密钥代:u32 |
| OPEN | 13 | stream:u32、接收额度:u64、kind:u8、priority:u8、weight:u16 |
| STOP_SENDING | 14 | stream:u32、reason:u32；取消对端对应的发送半流 |
| SHUTDOWN | 15 | final_outgoing_ordinal:u32、drain_ms:u32，均不可变 |
| DRAINED | 16 | 空内容，双方已声明后的可靠数据排空证明 |

帧 flags 除明确列出的位外必须为零。流/通道 ID 不为零；流偏移和数据长度相加不得溢出。
OPEN 的 kind 为 0（字节流）或 1（消息）；priority 为 0..3；weight 不为零。
可靠消息使用字节流上的 u32 长度前缀，不建立第二套可靠性核心。
已实现基础组装器 rudp_message、发送环原子整条入队，以及会话/原生端点的消息流接入。
组装器显式上限为 0..1MiB，零长消息也有四字节前缀，分段前缀与正文不向应用部分交付。
每个组装器只保留一条消息；应用未消费时停止从可靠流提取，额外输入后缀仍由调用者持有。
会话随组装器实际接收字节释放流/连接额度，不能等整条消息齐全才释放共享流控额度，
否则多个流分别占满连接额度但无一完整时会死锁。组装空间必须纳入连接构造/端点准入预算。
发送时预检总环容量、可用空间与最终偏移溢出，再同时排入前缀和正文；失败不保留半条记录。
超出组装上限的长度和截断记录的 FIN 均为 MALFORMED；合法边界 FIN 后允许交付最后完整记录。
短应用输出返回 TRUNCATED 及所需负载大小，既不修改输出，也不消费记录；RESET 清除未交付明文。
不可靠消息无分片；非序号模式 sequence 必须为零，序号模式必须大于零。
消息的待发期限使用本地单调时间，不发送需要两端时钟同步的绝对期限。

ACK 最多 32 个区间，包号从一开始，区间按最大包号降序排列，禁止相交或相邻。
相邻区间必须合并，形成唯一表示。连接层额外验证 ACK 没有确认未发出的包。
ACK 只表示传输接收，不能替代业务收据。

接收确认历史最多保留 32 个按降序排列的连续区间，超过时只保留最新区间。
合并相邻区间；未列出的包不是负确认。发送 ACK 后保留历史，以便 ACK 丢失后重发。
确认延迟从所报告最大包号的首次受理时间计算，以微秒饱和到 u32。
ACK-only 包仍可纳入历史，但不能触发 ACK 反馈循环；触发策略由连接驱动控制。
只有流状态、额度和资源受理均成功的包才登记到确认历史。密码层重复不能直接视为已受理；
重发 ACK 前先检查受理历史。已淘汰的旧区间可以不再确认，发送端通过新包号重传未确认数据。

## 可靠流接收与额度

接收半部使用固定容量数据环及逐字节存在位图，容量为 256B..1MiB 的二次幂，默认 64KiB。
构造后不按片段分配；恶意小片段不能增加元数据数量。外层先查询实际分配大小，
保留端点/连接预算后再构造，不能仅依赖单流上限防止多流耗尽内存。
按顺序消费连续数据，缺口返回待等，只有已知最终偏移且消费完才报告 EOF。

公布的 MAX_STREAM_DATA 为累计绝对额度，初始可以为零。读取释放物理窗口，
但不隐式扩大对端权限；驱动显式扩大额度并重发最新值，额度不超过消费偏移加容量。
连接总流控按各流最高偏移之和计费，包括乱序缺口，不能仅按实际收到的有效载荷计费。
未消费的重叠数据必须逐字节一致；已消费旧内容不再保存，仅忽略迟到重复。

FIN 与 RESET 约定唯一最终偏移，不得低于已观察最高偏移或超过已公布额度；
后续数据不能超过最终偏移。RESET 将未消费的逻辑偏移（含缺口）一次性计为消费，
清理缓冲明文；重复 RESET 不重复归还额度，改变最终偏移/原因视为违规。
干净 EOF 已消费后收到匹配 RESET 不改变已经完成的结果。
所有单帧预检先完成再修改数据，失败不部分填充缺口。
同包 STREAM 批次最多 64 帧，编码长度总和不超过一个受保护 UDP 数据报的负载容量。
纯预检覆盖跨帧重叠及最终偏移，按各流最高偏移相对既有水位的差额合计连接额度；
只有全批通过才写入任何流，失败不返回部分额度或部分数据。批次不产生回调或分配。
连接仍须统一预检 ACK、OPEN、RESET、其他控制帧及权限/生命周期，全部受理后才登记 ACK。

## 可靠流发送与副本确认

发送半部固定容量 256B..1MiB，默认 64KiB。数据被复制到有界环，确认前保留；
应用写入可以只接收可用前缀，入队成功不表示业务成功或远端已收到。
累计字节偏移不回绕；公布的远端额度仅可单调扩大。发送最高偏移增量用于连接总额度，
重复副本不得重复扣除。即使有高偏移已发送，也不能确认仍未发送的中间空洞。

每个数据字节独立标识已发送、已确认及待发状态，固定分层位图定位待发位置，
不随包/片段数量分配元数据。丢失使尚未确认的范围重新可发；新包号承载重传副本。
任意副本被确认即确认逻辑字节，其他副本之后丢失不会复活该字节。
只有连续前缀确认后才回收环空间；乱序已确认尾部仍留在固定预算内。

FIN 固定在停止写入时的最终偏移，可以单独重传；FIN 被确认不表示前面的缺口已确认。
发送半部完成须同时满足 FIN 确认及所有内容确认。PTO 可以探测仍在途的最旧未确认范围，
但只能由恢复驱动授权，仍受探测次数、pacing 与拥塞预算限制。
取消立即清空明文与位图，旧包引用由驱动排空后才能销毁对象。
此缓冲不拥有包号，不自行解析对端 ACK；只有经发送记录验证的最终包事件能解析为字节反馈。

## 接收半流取消

接收缓冲基础层提供本地 ReceiveStop，会话/原生端点以 Stop/StreamStop 驱动。
停止立即清除未读明文/位图，读与窥视返回 CANCELLED；HasFinal 不因本地意图变真。
已计费的最高逻辑偏移（含孔洞）以 ConsumedDelta 一次释放，接收额度保持冻结。
后续 STREAM 仍校验原额度、溢出、最终偏移一致性；负载不复制，丢弃的重叠明文不再比较。
跨帧/流批次保留整体预检；停止流的新最高值只计费/释放一次，正常流照常缓冲和交付。
真实 FIN/RESET 前不允许 Restart，包括尚未收到任何字节时停止的空缓冲；停止不能冒充已排空。
驱动将逻辑消费用于连接额度；不能给停止流持续追加 MAX_STREAM_DATA。
消息流同时清理完整未读记录和部分组装正文，不重复回收此前组装时已释放的字节额度。

STOP_SENDING 固定八字节 body、零 flags、非零 stream ID；同流方向的请求原因不可变，
不同原因的已认证重复请求为协议错误。同包请求、ACK、流内容和额度整体预检后才提交。
请求不取消反向半流或其他流；发送方清空未确认/未发送缓冲，以实际最高已发送偏移发 RESET。
已有本地 RESET 保留其原因；先前已完成发送的流无需额外 RESET，已存在的真实 FIN 仍然有效。
重复请求不重新取消、清空新状态或重复报告事件；退休 ID 的迟到帧按既有单调 ID 历史忽略。

控制和流引用共用发送账本、ACK/丢失、NewReno/pacing 与硬探测预算，受理背压不提交控制状态。
请求被确认或收到真实 FIN/RESET 后停止重发；未知最终偏移的每个停止请求另有独立期限，
以配置 ProgressTimeoutUs 从下次本地时刻观察起算。ACK、PING、其他流进展和重复 Stop 均不能续期，
期限包含在下一次 Poll 截止；超时终结连接并释放资源，不伪造对端最终偏移以提前复用槽位。
PendingReceiveStops 与流的 ReceiveStopDeadlineUs 可观察等待状态。流槽退休仍需真实终结与全部引用排空。
发送 RESET 的等待确认也采用独立 ProgressTimeoutUs 期限，从下次本地时刻观察起算，
本地主动 Reset 与对端 STOP_SENDING 触发使用相同规则。重复请求、重传与其他流进展不续期，
合法 ACK 只撤去一次等待；PendingSendResets 与 ResetDeadlineUs 暴露状态，超时终结连接。
双向同时请求停止可交叉处理各自 STOP/RESET；最终偏移和逻辑消费逐方向独立核算。

StreamChanged 的 WRITE_STOPPED 提示认证对端请求取消发送，发送 API 随即返回 CLOSED；
READ_DONE 表示已消费干净 EOF、RESET，或已停止接收且获得真实最终偏移，与 READ_EOF 分开。
默认流的 Changed 提供同义提示；WRITE_DONE 同时覆盖 FIN/RESET 被确认的发送终结。
取消后撤去发送容量提示，不向关闭的发送半流暗示可继续写入。提示延后合并，回调内取消、
释放借用句柄或关闭端点遵守既有临时引用和终结顺序，不递归派发。

## 双向字节流会话配置

完整握手后的默认双向字节流 ID 为 1，无需另一条 OPEN；占用双方各一个开流额度。
会话核心的 StreamCapacity=N（1..64），Local.MaxStreams<=N；默认 N=1。
构造时预留 2*N-1 对固定接收/发送环：默认流一对，本端/对端各 N-1 个额外流槽。
所有流共用密码器、包号、ACK、发送记录、连接额度与 NewReno/pacing，不各建拥塞连接。
kind=1 为可靠有序消息流；可选游戏 DATAGRAM 及下文的已验证路径迁移均已接入。
默认流 1 始终为字节流，消息流只能由额外 OPEN 创建，双方 max_message_size 均非零才允许。
发送 API 的本地上限还受发送环总容量减四字节约束，临时空闲不足完整拒收，不保留半条前缀。
接收上限独立于流/连接窗口；窗口小于一条消息也能通过固定组装器逐段接收并释放额度。
当本地消息上限非零，构造时给所有 2*N-2 个额外槽预留该上限的组装空间，计入准入峰值，
不在 OPEN 或收发时临时分配。一次 Input/Poll 最多组装 4096 字节，起点轮转；未完成工作在
不晚于下一毫秒继续维护。完整消息等待应用消费时停止提取该流，不影响其他有额度的流。
READ_READY 只指完整记录或 EOF/RESET；空消息是成功的零长负载，不能当成背压或 EOF。
当前消息头的至多四个长度字节在整个包提交前以既有重组数据和候选 STREAM 的覆盖视图预检；
超长长度/截断 FIN 不能使同包的有用 ACK、其他流数据、额度更新或 OPEN 部分提交。
尚有完整未读记录时不越过它解析后续记录；应用取走后，维护在任何下一次输出前校验新队首。
RESET 覆盖未交付的当前记录，清空组装明文并报告 CANCELLED，不把被丢弃内容当成截断 FIN。
消息完整但未被应用取走时，不允许报告接收 EOF 或退休；最后一条消费后才暴露 EOF。

额外流由可信握手角色分配：发起方依次 3,5,7…，响应方依次 2,4,6…。
ordinal=id/2+1，默认流在双方均占 ordinal 1；MAX_STREAMS 是累计最大 ordinal，
上限 2^31，不是当前活跃数。ID 从不复用；退休一条对端发起的流后可靠公布递增额度。
流槽可按完成顺序复用，长期占用较小 ID 不阻止另一槽反复开流和退休。
接纳新 OPEN 要求 ordinal 连续；同包可乱序排列多个连续 OPEN，STREAM 可先于其 OPEN。
较早 OPEN 丢失时，尚未接纳的后续 OPEN/STREAM 返回暂时背压，整包不提交、不 ACK；
发送方按原内容使用新包号重传，不能期待同一加密包重新进入业务提交。
密码层已认证的新密钥代仍可单独确认，不能因此错误确认尚未接纳的包。
所有较小 ordinal 均已开过，已不存在的较小 ID 因而确定为退休流；晚到内容不重开、不再次计费。
不保存随连接寿命增长的墓碑列表；固定槽与累计水位足以区分未来开流和退休流。

本端优先级 0..3、权重 1..16；对端线上权重虽为非零 uint16，调度服务上限仍裁为 16。
采用有界亏额轮转，量子为 1200*min(weight,16)*(4-priority) 字节；仅 UDP 受理成功后
按整包线路字节扣除，空闲流不积攒无限额度。最早未发送 OPEN 优先，避免主动制造 ordinal 缺口。
RESET 只取消本端发送半部，最终偏移取实际最高发送位置，不把未发送缓存收取为对端额度。
取消半部忽略后续流额度，不以未使用的额度反复刷新有用进展截止。
退休要求发送 FIN/RESET 已确认、接收 EOF 已消费或已 RESET、OPEN 已确认且全部包副本引用排空。
退休默认流 1 被拒绝；半部对象清除明文与位图后无分配重启，旧包事件不可能落入新流槽。
核心通过固定合并事件提供对端开流、读写就绪、发送完成、EOF 与退休就绪，不在事务中回调。
RETIRE_READY 在两半结束、OPEN 确认且所有旧包引用排空时发出；若之后发送流额度控制包
重新持有引用，清除尚未提取的提示，待引用再次排空时重新提示。应用仍须重检当前状态。
原生 PeerStream* API 提供额外流操作；StreamChanged 同时覆盖额外流和默认流 1。
每次通知在进入应用前提取最多 8 条提示，批次间隔至少 1ms；回调中新建提示在后续批次交付。
应用回调可回收流、读写或关闭/释放自有句柄；已退休 ID 的旧批次提示丢弃，关闭后停止余下派发。
Changed 继续提供默认流提示，并在对端累计开流额度增长时给出 STREAMS_READY；
本端槽退休及该额度提示均可用来重试 Open，不靠轮询等候。活跃流状态仅限所有者查询，
关闭后高级流操作返回 CLOSED，不再访问 Engine；连接整体保留不可变的关闭统计快照。

会话拥有固定接收/发送环、最多 256 个普通包位置和额外 32 个恢复位置，以及同等有界的
引用/最终事件空间。构造前查询包含密码器的总逻辑字节并预留；构造失败不接管密码器。
所有操作由一个所有者串行执行，处理输入、维护、读写、取消和销毁不再分配。
输出回调必须复制后才返回受理成功，不可重入或销毁会话；暂时背压/内存不足不消耗
逻辑发送额度、不授予确认、不创建发送记录，后续使用新包号重试而不会复用 nonce。

ACK、STREAM、RESET、额度及控制状态在完整预检后统一提交，不逐帧提前回调。
同包重叠 ACK 不重复完成，流偏移、FIN 和 RESET 在整个包内一致；连接额度按最高偏移
增量核算，RESET 消费缺口一次归还连接额度。读取自动扩大本配置的滑动接收额度，
最新额度在丢包/ACK 丢失后重发至确认。零额度仍允许偏移零的空 FIN。

每次维护最多受理 8 个输出包，真实 PTO 只授予 2 个探测且不宣布全部在途丢失。
ACK-only 按本地间隔限速；只对受理历史里的 eliciting 重复包重新触发 ACK，避免 ACK-of-ACK。
512B 数据报可以只编码最新的一部分 ACK 区间，为控制和数据保留空间；遗漏不是负确认。
所有 eliciting 控制、数据和探测共享 NewReno/pacing，不允许游戏/控制绕过在途硬上限。
每个 eliciting 输出携带当前接收密钥代确认；新代输入可触发受拥塞管理的确认 PING，
确认或其 ACK 丢失由 PTO 恢复，旧接收密钥宽限为 3 个基础 PTO，收紧在 1..60 秒内。

新受理的认证包才刷新空闲，重复/过旧/伪造包不会续命。另设 1 秒..10 分钟的有用进展截止，
默认 30 秒；有待确认数据/FIN/额度时启用，只有真实数据、最终大小、额度或其确认取得进展
才延长。单纯 PING/探测 ACK 只可清零网络 PTO 退避，不能无限延长卡住的应用工作。
不带时间参数的本地读写在空闲后首次产生工作时，于下一次 Poll/Input 观察到当前时间后
启动一次进度截止，不沿用上次空闲维护的旧时间；后续本地操作不能借此重新计时。
维护返回下一次单调微秒截止，调用方在该时刻以及读写/接收后驱动；时钟倒退拒绝，
到 UINT64_MAX 终结，饱和值不表示无限存活。底层包保护使用不分配诊断的 AEAD 尝试入口，
坏标签作为不可信流量丢弃；本地输出容量不足和认证后的协议错误分别处理。

## 密码层防重放窗口

每个接收方向使用固定 1024 位窗口。Check 不修改状态；认证成功并通过必要验证后
Accept 才滑动和标记。巨大包号跳跃的工作量仍有固定上限。重复包或窗口外旧包不交付。
重传可靠数据使用新包号，因此旧报文超出窗口不会让可靠流永久产生缺口。
不得依据未认证包号推进窗口；不会跨不同连接或不同接收方向共享窗口。

## 固定握手组件

仅使用 Noise_IK_25519_ChaChaPoly_SHA256，不协商模式，不降级。
发起方预先可信绑定接收方静态公钥。接收方必须提供可信 pin 或有界、只读的授权回调；
同时提供时二者必须通过。未验证的消息不能触发授权回调。回调不得重入或销毁当前对象。
临时私钥由系统安全随机源生成；确定性临时密钥仅存在于内部测试入口，不作为公共 API。

两条 Noise 消息的长度分别为 96+参数长度和 48+参数长度，参数最多 256 字节。
握手参数只承载协议/权限元数据，不允许作为应用请求执行。接收的参数直到 Noise 完成才可取出。
完整头部、会话连接 ID、角色和应用域的绑定由连接驱动规范化为双方相同的 Prologue。
原始 Noise 组件不自动构造这项绑定，也不负责 Cookie 或线路重传。

读写均先在候选状态上执行，失败清理候选秘密并保留原对象。
成功生成的握手报文由驱动缓存原始字节供重发，不重复调用 Write 推进密码状态。
Split 后立即清理静态私钥副本、临时私钥和握手密码状态；方向密钥只允许转交给一个包保护器，
转交成功即清理原副本，避免相同密钥创建多个从一开始的包号域。
Noise 完成后，接收方仍须验证发起方的最终持钥确认才能发布业务连接。
连接驱动必须保证业务事件在身份、参数、授权与最终确认全部通过后才交付。

## 固定线上握手配置

握手头仍为通用 48B，非 DATA 的 key_epoch=0。初始 scope 为非零公开监听/协调 ID。
HELLO（PN=1，目标 scope）负载固定 96B：client_id:16、目标静态公钥:32、随机 nonce:16、
应用上下文:32。ID/nonce 均不为零；客户端 ID 不与 scope 相同。上下文可为全零，
mdo 则应使用已授权协调通道下发的上下文并在监听侧要求精确匹配。

HELLO 摘要为完整规范 HELLO 报文的 SHA256。RETRY（PN=1，目标 client_id）负载 88B：
server_id:16、HELLO 摘要:32、地址 cookie:40。server_id 为 SHA256 的前 16 字节，
输入为 ASCII XRUDP001/server-id（不含终止符）、HELLO 摘要、cookie；禁止零值与 ID 冲突。
cookie 的原有 HMAC 同时绑定 scope、HELLO 摘要、源地址和签发时间。
RETRY 仅 136B，不放大初始 144B HELLO；监听端仍须先应用每地址/端点 CPU 与响应配额。

客户端向 server_id 发送 HANDSHAKE（PN=1）：HELLO 负载 96B、cookie 40B、Noise 第一飞行
128B，共 312B。接收侧先查现有 CID，再验证 cookie、上下文与派生 server_id，最后才允许
预留状态并执行 DH，不能让有效 cookie 重复创建同一活动连接。
Noise Prologue 固定为 ASCII XRUDP001/IK/prologue（无终止符）+ scope:16 + HELLO 负载:96
+ server_id:16，共 148B；角色和方向由固定 IK 模式定义。应用上下文、公钥与两个连接 ID
因此参与认证，不能只存在于未认证的外部元数据里。
服务端第二 HANDSHAKE（PN=2，目标 client_id）仅带 Noise 第二飞行 80B，共 128B。

Noise 加密参数固定 32B，大端：connection_credit:u64、stream_credit:u32、max_streams:u32、
idle_timeout_ms:u32、max_ack_delay_us:u32、datagram_size:u32、max_message_size:u32。
max_message_size 为本端每条可靠消息的最高接收负载，0 关闭消息流，其余值最多 1MiB；
该值由 Noise 认证，与窗口额度独立，配置端必须预留对应组装预算。
初始连接额度至多 64MiB，流额度至多 1MiB，流数 1..1024，空闲截止 1s..1h，
ACK 延迟至多 25ms，数据报上限 512..1200B；本地实际分配仍受更严格的全局预算约束。
双方公布独立接收额度，不将对端参数当成本端可以无限分配的配置。

Noise 派生完成仍不发布业务连接。客户端首次 DATA（epoch=1、PN=1）仅含 PING 和
KEY_CONFIRM(1)；服务端验证后首次 DATA（epoch=1、PN=1）依次含 PING、KEY_CONFIRM(1)、
ACK(delay=0,range=[1,1])。提前 STREAM 或任何其他证明形状拒绝，且不交付应用数据。
客户端验证该回复后建立；服务端先验证客户端证明并排队回复后才向应用发布。
业务包从 PN=2 开始，连接接收历史与发送退休前缀必须初始化为证明占用的 PN=1。
发送窗口可从可信本地退休水位构造；ACK 只覆盖该前缀时没有新完成或 RTT，
ACK 同时覆盖前缀及新业务包时，只完成实际保留的新包，不能把旧证明当作新的进展。

各阶段重传缓存完全相同的原始报文，不能再次推进 Noise 或重新加密另一份 PN=1 内容。
发送间隔从 250ms 指数增长至 2s；每阶段至多 16 次，总截止默认 10s、可选 1..60s，
不会因重复输入延长。Cookie 最多 30s，超长断链应在外层创建全新握手，而不是续签旧 Cookie。
已建立服务端短期保留最终回复供丢失恢复，转交密钥不会销毁该缓存；端点必须有限退休。
只有认证后才能判定协议违规，本地输出容量不足不能充当认证依据。

## 恢复时间计算

全部时间使用单调微秒。初始 RTT 默认 333ms，初始方差为其一半；定时器粒度下限 1ms。
RTT 样本来自本端发送到收到有效 ACK 的实测间隔；零间隔按 1us 处理，不能相信对端自报 RTT。
首样本直接设置最小值、平滑值与方差。后续最小 RTT 取原始样本最小值，
ACK 延迟最多采信本端配置值（协议上限 25ms），且扣除后不能低于观测最小 RTT。
平滑 RTT 按 7/8 旧值 + 1/8 调整样本；方差按 3/4 旧值 + 1/4 绝对差。

PTO 为平滑 RTT + max(4*方差,1ms) + 最大 ACK 延迟，再做指数退避。
丢失时间阈值为 ceil(9/8*max(最近 RTT,平滑 RTT))，至少 1ms。
整数运算不能溢出或生成零超时；不可表示的期限饱和至 UINT64_MAX。
驱动仍必须以有限的握手、空闲、关闭截止约束连接，不能将饱和期限当作无限存活。
只有有效确认取得真实进展才清零退避；重复/伪造确认不延长连接寿命。
这些公式参考 [RFC 9002](https://www.rfc-editor.org/rfc/rfc9002.html)。

## 发送记录与丢失事件

发送端记录实际送交 UDP 的每个 DATA 包，含 ACK-only，包号严格递增；发送失败可以留空洞。
有界环形历史的普通容量默认 256、上限 4096，额外保留 32 个 PTO 探测位置；
不能先发送再发现记录空间不足。未来 ACK 或覆盖当前保留区间内未发空洞的 ACK 整包拒绝，
不得部分完成。已退休的旧历史不再授予完成/字节额度；不将未知旧历史误判为新进展。

每个包只交付一次 ACKED、LOST、EXPIRED 或 CANCELLED 最终事件，携带原始数字标识；
声明丢失后迟到的 ACK 不再次交付完成。可靠数据由上层使用新包号重传并按流偏移去重。
ACK-eliciting 及包含 PADDING 的包均计入在途字节，不可靠游戏消息也占用拥塞预算。
仅 ACK-only 元数据可按保守寿命退休且不引发拥塞丢失；不得形成 ACK-of-ACK。

包丢失阈值为最大已确认包号领先至少 3，或该包位于最大已确认包之前且发送时间超过
RTT 组件计算的时间阈值。PTO 触发本身不把全部在途数据判丢。重复 ACK 不重新提供 RTT 样本；
只有最大 ACK 包仍为新确认且包含新确认的 ACK-eliciting 包时才采样。
处理事件输出不足时无状态变更，所有包/标识仍由原有所有者持有。
发送记录提供无副作用 ACK 预检，报告准确的最终事件容量和候选 RTT/进展；
连接先验证同包全部数据/控制帧，再提交 ACK，并在统一事务完成后交付回调。
探测次数、有限截止、重传内容与发送公平性由会话恢复驱动统一约束。

## 拥塞策略与发送节奏

所有在途数据共用一个 NewReno 窗口。初始窗口 12,000 字节，最小 2,400 字节；
本地最大值默认 4MiB，可配置范围 12,000..64MiB，不由对端协商扩大。
慢启动按新确认的在途字节增长；拥塞避免累计确认字节，每完成当前窗口的字节额度增加
一个 1,200 字节数据报。应用或流控受限时不增窗；本地容量到顶不积存增长额度。

第一次新丢失将窗口减半（不低于最小值），记录当前最大已发送包号为恢复水位。
同一水位内后续丢失不反复减窗，旧包确认也不增长窗口。
同一次 ACK 引起的丢失先于确认增长处理；取消、ACK-only 退休不表示拥塞。
持续拥塞必须由驱动以连续丢失和实测 RTT 证据判定，随后收缩到最小窗口；
单次 PTO 不能调用这个入口。策略公式参考 RFC 9002 第 7 节，不复用 QUIC 的线上协议。

会话使用 [RFC 9002 第 7.6 节](https://www.rfc-editor.org/rfc/rfc9002.html#section-7.6)
的持续拥塞证据原则：区间两端均为实际受理的普通 ACK-eliciting 包并已由网络丢失
检测终结；发送时已经取得真实 RTT 样本；发送时刻之差严格大于三倍基础 PTO，
其中基础 PTO 不含指数退避，三倍运算饱和。中间任一包被确认即切断区间，
包括纯 ACK、尺寸探测以及已判丢/已退休包的迟到确认。所有密钥代共享现有单调包号空间。
单纯等待、PTO 次数、没有 RTT 样本、本地输出拒收、路径/尺寸重建的本地丢弃，
均不能当作网络连续丢失证据。MTU 探测本身不充当持续拥塞区间端点。

每个会话预留一份与发送账本总槽数相同的固定元数据环，按发送次序退休完整的终结前缀；
流引用的提前复用不影响此历史。只保存一个前缀区间摘要，不按时长或包数增长分配。
迟到确认命中已退休区间时，保守丢弃该摘要，不猜测已遗忘的中间发送时刻；
仍在环内但已判丢的记录则保留确认屏障。RTT 阈值缩短时重新检查现有摘要，
同一连续区间只报告一次；地址迁移清除旧路径摘要，重新取得 RTT 后才允许新证据。
证明完成后，在下一次发送前将窗口收缩到 2,400 字节，保持实际在途字节和所有权账本不变。
SessionState.PersistentCongestion 统计已证明区间，不统计 PTO。

pacing 使用本地平滑 RTT 与窗口确定平均速率，以 GCRA 限制瞬时最多约两数据报的突发，
无论空闲多久均不积累额外信用。计算使用饱和整数算术，避免宽整数编译器依赖。
PTO 探测可暂时超过窗口，但仍受 pacing、发送记录预留和硬在途上限约束；
驱动每次真实 PTO 最多授权两个包，不能将所有重传或游戏数据标成探测。
ACK-only 可以及时发送，但端点必须单独限制控制流量、地址反射与 CPU 工作量。
拥塞组件只消费发送记录产生的可信、唯一最终事件，调用方不得重复消费事件。

## 无状态地址 cookie

Token 固定 40 字节：8 字节大端服务器单调微秒签发时间，后接 32 字节 HMAC-SHA256。
MAC 输入依次为 ASCII 域 XRUDP001/address-cookie（无终止符）、16 字节非零端点域、
32 字节规范初始探测摘要、23 字节规范源地址、8 字节签发时间。
规范地址为 family:u8（4/6）、port:u16、zone:u32、address:16；所有整数大端。
IPv4 地址只占前四字节，尾十二字节与 zone 为零；IPv6 包含接口作用域。
摘要必须绑定客户端连接 ID、目标身份与其他重要探测字段，不能只摘要任意填充字节。

验证器先验证 HMAC，再检查时间；未来签发时间或超过配置寿命的有效 token 视为超时。
最大寿命固定 30 秒，可收紧，不可放宽。期间可接受一代旧服务器密钥供轮换；
服务器重启使用全新随机密钥。地址、端口、接口作用域、端点域或探测内容变化均需重新挑战。
Cookie 不认证身份，也不是一次性业务凭据；不能替代最终持钥确认和应用授权。
算法不分配、不访问网络；实际端点必须先限制响应放大、CPU、每地址速率和总状态数量。

## 原生端点与所有权

原生端点使用调用方已运行的 XRT Worker；每个端点为一个 IPv4 或 IPv6-only UDP socket。
入口以固定 64 个 IP 桶和总速率限制新握手计算/响应；RETRY 小于 HELLO，验证 cookie 后
才分配半开状态。连接 ID 去重；握手期间源地址固定，确认后的业务须来自当前已验证地址，
其他地址先隔离并进行下文的随机挑战验证，不能直接交付业务或切换发送目标。
peer、半开、逻辑内存、发送包数/字节与接收批次都有固定上限；保留关闭句柄仍计费。
多个 peer 共用 UDP 输出队列：成功受理一个 peer 的报文后，从其后开始下一维护轮次。
受阻 peer 在既有固定槽中登记等待，不分配队列结点；等待次序只在成功受理后推进，
本地拒收不推进次序。新输入先给一个更早受阻 peer 重试机会；未轮到的发送暂缓，避免
接收回调绕过队列。当前没有可发送内容时撤去登记；关闭移除登记且仍检查所有 peer 截止，
不让拥塞/流控等待造成跨连接队首阻塞，也不为公平服务放开单连接拥塞、pacing 或发送硬上限。
握手前预留整个配置流池的峰值字节，最终服务端证明排队前构造会话；Confirmed 同时保证
身份/持钥及所有配置流槽资源受理成功，随后可开流/读写。来源不符或未受理内容不记为可靠接收 ACK。
就绪提示按边缘合并，回调内读写产生的后续事件在另一次工作循环交付；外部关闭请求可使
回调中后续读写返回 CLOSED，终结只交付一次。取消可尽力发送一份有界 CLOSE，随后立即排空
本地所有权；这份至多一个数据报的本地取消提示不代表优雅关闭或对端收据。
先关闭端点并等待 peer、UDP、定时器全部终结，才可停止 Engine；关闭不依赖新分配。
回调借用句柄，跨回调保留须显式 Ref；已关闭句柄不再保留引擎资源，可在引擎销毁后释放。

## 端点候选回程检查

启用端点配置的 `ConnectivityChecks` 后，`xrtRudpEndpointCheck` 可在 owner
Worker 上对可信单播候选启动一次有界回程检查。候选数量为
1..`XRUDP_ENDPOINT_CHECK_CANDIDATES_MAX`（8），不得重复，且须与端点 socket
同地址族。每个候选至多发送五次请求；调用期限为 1..10000ms，仍受端点检查
总寿命限制。检查复用已有 socket 和 Worker，辅助发送的总准入间隔至少 50ms。

`xrtRudpEndpointCheckInfo` 把当前观察复制到 `xrudpcheckstate`，不触发回调。
端点存活时只能由 owner 查询；CLOSED 后快照不再变化。`Reply` / `Replies`
记录自身请求得到的返回地址，`Confirmed` / `Confirmations` 记录对端返回本端
cookie 的地址；`Sent`、`Rejected`、`DeadlineUs`、`Reason` 和 `Active` 提供
有界统计、截止时间及终止状态。快照不暴露密钥或 nonce。应用自行轮询并选择拨号
候选，这些地址提示不代表对端身份、业务数据受理或 Noise 握手成功。

`xrtRudpEndpointCheckCancel` 在 owner 上幂等取消检查：活动检查返回 `XRUDP_OK`，
清除凭据和待发包，保留公开观察并以 `XRUDP_CANCELLED` 结束；已停止或 CLOSED
时返回 `XRUDP_DONE`。端点关闭也会在 Close 回调之前取消检查。检查得到的提示
不能放宽后续 Noise 握手的来源和公钥校验。

## 路径验证与生产验收边界

路径验证的前置接口已实现：CipherInspect 使用栈内私有密码器副本完成同样的 AEAD/帧/确认
检查，返回前清除副本；不提交原密码器的防重放位、接收换钥或发送换钥确认。未知地址的
有效密文并不等于受理成功，预检结果不能用于数据交付、ACK 或自动切换业务地址。
验证路径后可用 SentDiscardPath 一次排空旧在途，输出唯一 LOST/EXPIRED 事件，保留全局包号
及 ACK 水位、继续允许新发送；迟到旧 ACK 不再产生所有权、交付或 RTT 样本。
上层必须处理可靠重发/游戏丢弃和旧拥塞在途，再从保守初值建立新路径拥塞/RTT 状态。
前置接口本身不直接验证地址；其上的地址随机挑战、反放大预算、有界验证期限和切换后的
路径状态和下文的 MTU 增长/回退已接入核心/原生驱动，完整跨平台生产验收仍待完成。设计参考
[RFC 9000 的路径验证与迁移章节](https://www.rfc-editor.org/rfc/rfc9000.html#section-8.2)，
本协议并不宣称兼容或完整实现 QUIC。

线上握手、原生多流/可靠消息、连接关闭、路径迁移、MTU、持续拥塞区间证明、
端点 Future 数据操作及并发取消已有实现。首次冻结前仍须完成广泛的安全/接入压力审查，
继续扩展独立互操作和关键状态机模糊测试，并完成实体 Android、双独立 NAT 与实际长稳。
组件实现和短测通过不等于这些生产验收已经完成；进度证据见 implementation-status.md。

## 数据报队列与会话契约

rudp_datagram 只负责固定队列和本地调度，不拥有套接字、密码器、包重传或独立拥塞窗口。
最多 64 个通道，发送/接收各 1..256 个固定槽，槽负载上限 1112B；构造只有一次分配，
处理、期限清理、取消和错误路径均不再分配。应用须通过可靠控制或固定协议约定通道 ID/模式，
ID 在连接内不删除/复用，避免清空序号水位后接纳迟到旧包。未知 ID 不隐式开通或分配状态。

INDEPENDENT 发送序号为零，独立接收；ORDERED 使用非零递增序号，丢弃旧/重复，
缺序号直接跳过，不等待补齐；LATEST 另把同通道已接受但未读的快照替换为较新的快照。
不同通道之间不保证读取顺序。LATEST 对无法接纳的超大负载保留既有可用快照；
但已观察的序号水位仍前进，队满后释放空间也不能使迟到的旧快照复活。
模式不符、未知 ID、过旧、超出本地容量或队满均按不可靠消息丢弃，并有独立计数。
必须在整个认证包的所有帧预检通过后才调用队列 Input，不能把未验密文交给它。

发送期限为本地单调微秒绝对值，零表示不设单条期限；非零须在当前时刻后且不超过十分钟。
接收存活时间从本地认证输入时刻起算，不发送或比较依赖两端时钟同步的绝对期限。
Maintain 在观察到时刻推进时清理到期记录；Peek 为纯查询，只观察最近维护后的队列。
Read 先按调用时刻维护，再整条交付；短缓冲返回所需信息而不写输出、不消费记录。

可选择替换同通道尚未提交的待发记录；被替换的旧明文先清理，每次受理产生新的 ticket。
Peek 不消费；只有实际 UDP 受理后才 Sent，校验当前 ticket，旧快照的 ticket 不能误删新快照。
成功提交按完整受保护包字节扣减有界亏额预算，优先级 0..3、权重 1..16；空闲不积攒预算。
失败入队不消耗序号或 ticket，两者禁止回绕；序号耗尽须换连接/新通道，不能复用旧 ID。
Abort 清理全部待发/待读明文并封闭修改接口，统计和通道历史保留，重复取消不再次扣减资源。
Session.Datagrams 全零时关闭本地队列；非零配置完整验证，构造一次分配且计入会话/端点准入。
通道协议不新增握手参数；应用预先约定 ID/模式，或在可靠控制交换后再发送业务数据。
关闭本地队列仍可接收整包中的可靠内容，DATAGRAM 只计数丢弃，传输 ACK 不表示应用接纳它。
整包 ACK/流/控制预检通过后才入接收队列；同包后续非法内容不能留下已交付的数据报。
有效包中未知/模式不符/过旧/超大/队满的数据报按策略丢弃，不使连接或同包可靠数据失败。

每个输出游戏包包含一个 DATAGRAM 和 KEY_CONFIRM，可附加放得下的 ACK；不分片。
应用有效发送上限为 min(本地队列负载容量, 双方报文上限的较小值 - 88B)。
共用 CipherSeal、唯一包号和真实 UDP 受理入口，只有成功受理后提交队列及正常发送记录。
所有在途游戏字节共用已有 NewReno/pacing，不能占 PTO 探测保留位、不能标成探测。
ACK/丢失反馈按包进入同一拥塞控制；游戏引用只更新计数，不解析为可靠字节范围或重发负载。
应用受限判断包含等待游戏记录的负载/线路开销与当前在途字节，空记录也有发送需求；
可靠流的连接/单流额度耗尽不使独立游戏业务被误判为应用无需求，从而冻结拥塞窗口增长。
两类积压业务交替整包发送；轮到的一类暂时受拥塞/容量限制时保留机会，不允许另一类小包
反复填满 ACK 释放的空隙导致长期饥饿。纯 ACK 不消费轮次，PTO 仍优先且遵守既有探测硬上限。
流控受阻或没有到期控制/可靠数据时，游戏可以使用空闲机会，不额外扣减字节流的连接/单流额度。

维护时刻推进先清除过期工作再判断有用进度超时，但不刷新对端 Activity 或延长空闲期限。
会话 Poll 的下一截止包含待发/待读期限，原生端点以自己的单调时钟驱动，无两端时钟同步假设。
PeerDatagramWrite 使用调用时刻起算的相对 lifetime；核心 API 使用本地绝对 deadline。
Changed 增加 DATAGRAM_READ_READY/WRITE_READY；成功 Read 后若仍有记录，至少 1ms 后再提示，
不递归回调；短缓冲/空队列不会自发循环提示。回调内关闭/取消遵守已有借用引用与终结规则。
定时读写发现连接超时会立即关闭原生 peer 并清理密码器别名；单条过期返回 TIMEOUT 时连接仍可用。

## 地址验证与单路径切换

会话可在首次加密 I/O 前用 EnablePaths 绑定握手已验证地址与地址化发送回调，此后只能用
PathInput 提供原始源地址，不能通过旧 Input 绕过验证。原生端点在受理会话时自动启用；
握手 HELLO/RETRY/证明仍固定原地址，确认前不接受新地址探测。每个原生端点使用同一
IPv4 或 IPv6-only 套接字，PeerProbePath 拒绝跨地址族和错误所有者；不迁移本地套接字。

PATH_CHALLENGE/PATH_RESPONSE 继续使用固定编号 10/11、零 flags、16 字节内容。
本版选择严格的单地址对契约：随机 challenge 与当前候选源地址同时匹配才证明该候选；
来自其他地址的响应不替它完成证明。这不是 QUIC 的多路径/迁移兼容契约。
未知地址首先经 CipherInspect 验密，新数据、ACK、额度、流状态、换钥、防重放均不提交。
已经接收过的包、过旧包、坏标签或超出本地报文上限不能建立候选或购买发送额度。
旧 Input 在地址化模式返回 ARGUMENT；认证成功也不等于数据受理成功。

每个会话只有一个候选；其他地址不能覆盖正在验证的候选。首次自动候选要求包号高于当前
路径已接收水位及会话范围的未受理包号水位；候选只按高于这两个水位的新验密包号
收取一次字节额度。该水位跨候选失败/冷却、可信重启和迁移保留，重放未受理密文不能
反复开启尝试或购买额度；安全随机源失败也消耗那份被动触发包。候选输入最多每秒
32 次验密，拆成普通报文 24 次和 PATH 8 次，互不借用。业务洪峰不能耗尽路径响应预算；
伪造 PATH 也只能消耗那 8 次，未知地址/无效密文不能触发额外无界验密。切换、失败和重试
不重置同秒额度；只有进入新秒才恢复。当前已验证路径独立于此额度。
收到新地址业务只触发有界验证并返回 BACKPRESSURE，不交付或 ACK 这些内容。
候选响应必须是 PATH/KEY_CONFIRM/PADDING 构成的探测包；有效响应前缀不能夹带业务、
ACK 或额度来绕过隔离。已验证路径中的挑战则与其他内容一同整包预检，非法尾帧不能留下响应。

挑战由 XRT 安全随机源生成，16 字节令牌不出现在公开快照或日志中。3 秒绝对期限，最多
三次实际受理的挑战，重试间隔依次 200/400/800ms；背压不消费次数、字节或待回显所有权。
失败后 3 秒冷却，重复输入、探测、其他流和定时器迟到均不续期；迟到维护以原期限计算冷却。
候选出口至多为新验密字节的三倍，计费接收额度上限 1200B、累计候选出口上限 3600B；
只有可信调用方主动 ProbePath 才有最多 336B 的固定初始许可，用于在没有入包时打开 NAT。
不能从未认证帧指定任意发送目标。候选失败只撤去候选并提示 PATH_FAILED，旧路径继续可用。
Path.Failure 分开记录候选的 TIMEOUT/IO_ERROR；候选目标的直接 UDP 路由拒收不升级成
整个连接失败，旧路径业务可在同次 Poll 继续发送。密码器、账本、拥塞内部错误和 active
目标的真正发送错误仍是连接错误，不能被“候选失败”分支掩盖。随机源失败也只撤去该尝试，
保留已有连接并记录失败/冷却，候选计数在生成新令牌前清零，避免混入上次尝试的统计。

回显在收到挑战的路径排队，每条 active/candidate 路径各一个固定槽，可与本地挑战同包。
每个 Poll 最多一个路径控制且包含在总计最多八包内，控制服务间隔至少 50ms；它与业务
共用唯一包号、密码器、发送账本、NewReno/pacing、共享原生 UDP 公平等待，不另开无限出口。
首次挑战已经到期但仍等待该限速时，下一维护时刻必须包含限速解除点；即使没有业务、
在途或待回显，也不能直接睡到验证失败期限。
正常账本满时也只有真实 PTO 授予的最多两个保留探测机会；路径控制不能自行伪造 PTO 预算。

证明有效且整个探测包受理后，SentDiscardPath 将旧在途一次反馈为 LOST/EXPIRED；可靠
字节重新排队，游戏负载只计丢失而不重传。再保留全局包号/ACK 水位、流 ID/偏移/额度和
防重放状态，从初始拥塞窗口与配置 RTT 重建恢复状态，清除旧 PTO/退避并重发必要额度。
迟到旧 ACK 不会再次交付、采样 RTT 或增长窗口。已验证新地址成为唯一业务目标。
不再按原地址设置固定禁用期：新包号可立即触发 A→B→A 的全新挑战，仍须证明后才切换。
被动候选的匹配响应还必须新于当前 active 包号水位，防止迟到的旧路径证明压过更新的
当前路径证据；乱序的候选业务可以先于匹配证明到达，不要求证明高于候选自身水位。
当前地址上已认证但因等待 OPEN/本地容量而暂缓的包，也更新此地址的包号证据；
它们不因此获得业务交付、传输 ACK、活性或进度续期。坏标签不更新这个水位。
可信显式 ProbePath 表示调用方偏好另一条可达路径，其本次新令牌的匹配证明可以在
当前路径仍持续收到更高包号时完成选择；地址/令牌匹配、绝对期限和预算仍全部适用。
此处借鉴 [RFC 9000 的迁移次序与路径验证原则](https://www.rfc-editor.org/rfc/rfc9000.html#section-9.3)，
是 xrudp 的单路径策略，不声明 QUIC 线路互操作。
PATH_CHANGED 按边缘合并，PeerInfo 在回调前已发布新地址；回调可释放 peer、中止或关闭端点。

关闭中的既有候选仍可完成排空所需切换，但不续期 STOP/RESET 或优雅关闭期限；本地 Shutdown
后拒绝主动新 Probe，Ready/驻留阶段不再接受新候选。地址验证只证明可达性，未证明新路径
支持当前协商的 512..1200B 报文；尺寸证明由后文的 DPLPMTUD 建立，完整穿透协调仍待实现。

## 映射发现

发现使用 [RFC 8489](https://www.rfc-editor.org/rfc/rfc8489.html) 的 Binding 格式，
支持 XOR-MAPPED-ADDRESS 的 IPv4/IPv6 与可选 FINGERPRINT；这不是另一套 xrudp 身份认证。
不实现 classic STUN、凭据协商、重定向、TURN 或完整 ICE。坐标仍必须来自已认证的应用
协调通道，最终业务只在 Noise/xrudp 验证后开放。映射可能依赖目的地址，不能用一次结果
承诺所有 NAT 可穿透，后续保留既有中继。

本库自定工作量边界：包长不超过 512B、最多 64 个属性、16 个唯一未知必需属性，
整包结构/指纹预检失败不改变输出。属性 padding 不解释，重复映射/错误字段只取首个；
完整性属性只标记出现且屏蔽后续普通属性，不冒充 HMAC 已验证。原始凭据与错误文本不导出。

发现状态由单一所有者维护，固定存储、不创建网络对象或线程。事务只在 Init 使用安全随机源，
失败保留调用方对象。Next 只提供固定请求；Sent 必须在实际 UDP 受理后调用，才推进次数与
500ms 起的退避，最多 7 次。默认总时限 39.5s，显式应用时限可提前终止；所有时钟单调、
期限饱和也有限，背压、未知来源、错误事务或迟到输入不续期。成功只接受原服务器和事务的
映射响应；终结擦除内部请求/随机值。远端错误码可查询，不自动跟随新服务器。

原生 EndpointDiscover 把发现核心接入握手/业务的同一 UDP 套接字。四个固定任务槽计入
端点构造预算，不占半开/peer 槽；使用已有定时器，无 peer 时也会工作。单调 ID 不复用，
已终结但尚未交付结果的任务仍占槽。来源必须与本次配置的服务器精确匹配，不接受响应
携带新的请求目的地。全局发现输出每 50ms 最多一包，和 peer 按实际受理交替获得队列
优先机会，不绕过 peer 的拥塞/额度/轮转。背压/临时内存拒收不计重试，路由拒收只终结
该任务并保留错误对象，不中止现有可靠连接。

每个受理任务恰好一次回调，常规完成至少延后 1ms；回调中的新任务/取消也延后，不递归。
公开结果没有事务随机值；错误对象只在回调中借用。关闭取消 pending 任务并在端点 Close
前交付结果，已完成结果不被关闭错误覆盖。发送与关闭竞态中，关闭请求生效后观察到的
拒收也由关闭路径结算取消，不能被发送分支抢先改成路由错误。关闭后句柄不访问 Engine。

原生测试核对 STUN 观察端口、端点绑定端口及 Noise 可靠流源端口一致；独立互操作工具
tools/test_xrudp_discovery_interop.py 使用标准库 UDP/struct/zlib 服务端，覆盖 IPv4/IPv6、
可选指纹与伪造结果。它使用共享清单构建，原始事务/报文只在内存保留。
映射发现仅返回地址提示；授权协调、候选配对和最终选路由调用方负责，
预热出站能力见下一节。映射结果本身不等于身份确认或公网直连成功。

### 打洞出站预热核心

`rudp_punch` 提供无 I/O 的固定存储调度器，为监听端主动打开对端方向的 NAT 过滤。
它不是连通性检查，更不是设备认证。可信应用在调用 Init 前授权 1..8 个去重的单播地址；
不会从 UDP 内容扩展候选，也不预测/扫描端口，不解析主机名。原生接线必须使用随后接收
Noise 握手与业务的同一个 UDP 套接字；多地址族只允许由适配器分别路由到正确的套接字。
跨任务还须限制每套接字至少 50ms 才受理一份 indication，不能靠多建任务放大发包预算。

线路复用 RFC 8489 的 Binding indication（类型 0x0011），固定 28B、携带 FINGERPRINT，
没有任何请求响应、认证属性或业务数据。参见 [RFC 8489 6.3.2](https://www.rfc-editor.org/rfc/rfc8489.html#section-6.3.2)。
每个实际受理的 indication 使用独立的 96 位安全随机事务；它们不是同一 STUN 请求的重传。
Init 一次性预留最多 48 份事务，后续 Next/Sent/Reject/Cancel/State 不需要随机源或堆分配。
本地尚未受理的同一 offer 保持原字节、地址与索引；仅真实 UDP 接纳后调用 Sent。
收包不能触发回应、配额增加、地址添加或成功状态，收到的 indication 也不能完成映射发现。

每候选至多六次受理，间隔 200/400/800/1600/2000ms；所有候选共享至少 50ms 的发送间隔。
采用轮转服务已到时的候选，暂时背压/内存不足不消费次数或轮转游标，调度晚到不追赶突发。
硬路由错误通过 Reject 仅撤销当前目的地，不终止其他候选；已受理的全局发包门仍保留。
默认绝对期限 8s，可指定 1000..10000ms，任何输入/背压/重试均不续期；时刻饱和仍有限终结。
公开状态无事务值，终结和硬失败擦除对应事务；失败 Init 保留整个旧对象/未受理 offer。

DONE 只说明全部六次出站报文已被本机 UDP 受理，不能证明送达、打洞成功或授予业务权限。
部分硬路由失败后继续其余目的地，全部结束时报 IO_ERROR，并分别保留 Completed/Failed
及逐候选状态；超时/取消只结束剩余目标。适配器在真实 Noise 确认、回退中继、授权变化或关闭时
取消剩余预热；确认仍需可信协调提供的设备公钥、Scope、ApplicationContext 与账户 ACL。
原生 EndpointPunch/EndpointPunchCancel 已接入同一个 UDP 套接字，固定两个任务槽，不占 peer/
halfopen；槽、核心及回调记录已包含在端点 MemoryLimit 中，不创建另一线程/Engine/套接字。
原生端点要求全部候选与绑定地址族相同。打洞任务使用独立的单调不复用 ID 空间；API 失败
保留 ID、没有回调。所有任务与映射发现共用同一个 50ms 受理门，两个辅助类别按实际受理
轮换优先权，再与 peer 输出轮换机会，不能通过多任务扩大同套接字预算或饿死可靠数据。
队列满、AGAIN 或临时内存不足仅延后 1ms，不消耗核心次数；硬路由错误保留第一个错误对象
到结果回调，继续其他候选。已生效关闭与拒收同时发生时，以关闭取消尚未终结的任务。

结果至少延迟 1ms、恰好一次，先释放槽再调用用户；回调可以取消兄弟、创建新 ID、关闭端点
或释放自有引用，不递归调用结果。端点关闭在全局 Close 前完成所有任务，保留已经终结的
DONE/错误结果；已关闭句柄可在 Engine 销毁后检查/释放，线程与引用规则沿用 Endpoint。
原生实现不会把预热完成自动绑定到任意连接：应用必须按协调授权关系，在对应的真实
Noise 确认、切换中继或取消授权时取消该任务。候选优选、协调服务、mdo 直连/回退仍继续。

## 连接优雅关闭

CLOSE(9) 继续表示立即中止，不保证可靠数据排空。SHUTDOWN(15) 内容为大端
final_outgoing_ordinal:u32、drain_ms:u32，flags=0，长度精确为 8。最终序数包含
隐含流 1，范围 1..2^31；相对等待为 1000..600000ms，不依赖两端墙上时钟同步。
DRAINED(16) 长度为零且 flags=0。关闭声明与 ACK、OPEN、字节/消息及额度在整个
认证包预检后一次提交；不同的重复声明、超出已授予序数、声明以后的新 OPEN 均非法。
声明可以先于此前在途 OPEN；接收者等到全部已声明序数受理，不能漏掉迟到流就宣布排空。
同包 SHUTDOWN 与 DRAINED 不依赖排列顺序；DRAINED 要求双方声明及全部对端流已受理。

本地 SessionShutdown/PeerShutdown 禁止新开流和字节/消息写入，给每个已受理发送半流
排入 FIN；已 RESET 的半流继续等待 RESET 确认。仍允许读取、接收取消和符合条件的退休。
关闭不再通过退休扩大新流额度。此前在途的对端 OPEN 仍可受理，其本地发送半流直接 FIN，
接收内容继续交付。排队的游戏数据报立即清除，SendCancelled/ReceiveCancelled 记录数量；
迟到游戏内容按策略丢弃并计数，不能把向已停止队列插入的失败当成内部连接错误。

收到 SHUTDOWN 只禁止本地新开流，已有流仍可写入异步业务回复；不因某刻发送队列为空
就自动 FIN。State.Shutdown.PeerRequested 和原生 SHUTDOWN_REQUESTED 单次边缘提示
要求应用完成已有回复后显式 Shutdown；关闭请求不是取消已有请求或代替应用的业务协议。

本地 Ready 要求双方声明、全部已声明流受理、每个活跃发送半流 FIN/RESET 确认、每个
接收半流真正消费/终结，以及全部旧流包引用释放。消息组装器已缓存但应用未读取的消息
仍未排空；退休流此前已经满足这些条件。Ready 后不再生成流/额度重传引用。
DRAINED 通过原有唯一包号、密码器、发送账本、NewReno/pacing 和有界 PTO 重传；在自己的
声明未被确认前，每份 DRAINED 都同时包含 SHUTDOWN，允许声明丢失或乱序。
单纯字节传输 ACK 不能证明对端应用已读，必须收到对端 DRAINED。

进入驻留还要求本地 DRAINED 已被 ACK，以及覆盖对端 DRAINED 包号的 ACK 已真实受理到
UDP；只检查本次实际编码且可能被截断的 ACK ranges，完整本地历史不能代替线路证据。
UDP 背压不提交这项证明。最终 ACK 带有 PING，避免只有一个正常账本槽时该纯 ACK 丢失后
无法恢复：驻留中的真实 PTO 仍最多授权两个 ACK+PING 探测，使用原有有界保留槽/拥塞路径，
不恢复业务数据、流控制或游戏重传，也不另设无限发送通道。
已提交最终确认后的普通重试只回复 ACK，不让 PING 触发新的 PING/ACK 循环；
只有真实 PTO 才重新携带恢复 PING。

驻留为 max(100ms,3*基础 PTO)，不超过已有关闭总期限；输入、重复 DRAINED 和 ACK 均不能
续期。期间保留密钥/防重放/ACK 状态，仍校验整个认证包，回答重试的最终确认。到期以
CLOSED 和 Shutdown.Succeeded=true 终结，保留真实流终结快照，不伪造 RESET/取消已完成发送。
本地取消、对端 CLOSE、非法输入、I/O 错误和超时均不能设置 Succeeded。

本地总期限从下一次所有者时刻观察起算；对端相对期限从首份有效声明受理时起算，两者取早。
重复声明、其他流进展和探测不能续期。驻留前仍适用既有 idle/useful-progress 与独立 STOP/RESET
期限，可能更早失败；驻留后只有不可延长的最终计时。有限网络确认不能解决无限丢包下的双方
共同知识问题，不能保证另一方也收到最后 ACK，更不等于业务收据或游戏数据已交付。

## 路径报文尺寸与黑洞回退

Local/Peer.DatagramSize 是认证后的不可变接收上限，仍为 512..1200 个 UDP 负载字节。
启用 DiscoverMtu 时，发送者为当前已验证地址另外维护 Effective，初始为 512；短握手或
PATH_RESPONSE 只证明地址可达，不能证明 512B 或更大的报文可以穿过路径。
原生端点默认启用并要求 UDP PMTU_PROBE 成功：禁止 IP 分片，绕过陈旧的内核路径 MTU 缓存。
低层 Session 只在适配器承诺不分片时启用；关闭时按既有认证上限发送，不声称具备尺寸探测。
相关原则来自 [RFC 8899](https://www.rfc-editor.org/rfc/rfc8899.html)；
Windows 模式见 [Microsoft UDP 选项说明](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options)。

探测不增加线路帧类型：PING、KEY_CONFIRM 和全零 PADDING 组成精确目标长度的加密 DATA。
只有本地已真实受理到 UDP、仍在账本中的对应唯一包号被认证 ACK，才确认该完整尺寸。
较小响应、对端自行报告的长度、未知地址报文、迟到的已退休 ACK 和本地发送背压均不能晋升。
有效普通报文 >=512B 的真实 ACK 也可确认基础尺寸；增大 Effective 仍只靠专用尺寸探测。
按 512、768、1024、认证上限探测，中间目标不超过上限；每尺寸最多三次真实受理尝试，
每次等待 max(1s,3*基础 PTO)，失败重试同样间隔。增长失败保留已证实尺寸，60 秒后再搜索；
基础 512B 始终无法确认则 TIMEOUT，不被其他小报文成功续期为无限尝试。
已到达上限时停止定期尺寸探测；后续路径变化或实际大报文停滞会重新建立证据。

尺寸探测使用正常账本槽、共享密码器/唯一包号/换钥、拥塞窗口、在途与 pacing；
不使用 PTO 保留资格，每 Poll 最多一份且计入总八包。超时单独退休探测并释放一次在途，
其孤立丢失不作为普通拥塞证据，孤立确认也不增窗；普通数据混合丢失仍正常执行拥塞恢复。
纯 ACK 可使用固定元数据预留空间，留下两个槽供真实 PTO；不携带 PING、数据或填充，
不产生在途，也不消耗/增加 PTO 次数，避免双方单正常槽同时满时确认只能循环等待 PTO。
元数据仍保存以验证 ACK 孔洞并有界过期；不会动态增大内存或把未交付包伪装成确认。
会话控制 ACK 的区间编码另外按 512B 基础报文预算预留控制帧空间；即使已有较大尺寸
证明、存在很多稀疏区间，纯确认、降级为纯确认及最终排空确认也不会因此超过基础尺寸。
最新区间优先，裁剪不能确认未收到的包号。普通可靠/游戏数据仍按当前有效 MTU 分包。

普通 >=512B 报文的独立大尺寸期限为 max(1s,3*基础 PTO)，更大报文提升待证尺寸但不延长
原期限。只有不早于本次待证包号且实际长度足够的 ACK 可以解除；小报文、其他流进展、
发送重试及 PTO 重置不能续期。到期将旧在途唯一反馈为丢失/过期，保留逻辑字节偏移、
流 ID、额度、ACK/防重放与全局包号；可靠范围重新拆成较小包，不重传游戏负载。
退回 512B 并重新确认基础尺寸，至少 60 秒后再增长；基础重检时不能靠再次回退清零尝试次数。
路径验证完成后的地址迁移也将尺寸证据重置为未确认的 512B，不能沿用旧地址的大包证明。

未发送且超过新尺寸的游戏记录由 DatagramTrimSend 擦除，SendSizeDropped 单独计数；
其余顺序、序号、票据、接收记录不变。DatagramSendLimit 是当前 Effective 减去 88B 开销
与本地载荷预算的较小值；新超限写入返回 LIMIT。MTU_CHANGED 延迟合并提示发布后状态，
尺寸增大同时提供 DATAGRAM_WRITE_READY。新路径或缩包不修改对端的认证接收上限。
优雅关闭不启动新的尺寸搜索；既有尺寸超时释放账本，但已完成排空不被新探测打断。
