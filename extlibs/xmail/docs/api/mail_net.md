# 邮件网络配置 API

`mail_net` 是 SMTP、POP3 和 IMAP 客户端共享的 XRT 网络接入层。它不公开另一套 socket
或 stream 抽象，只统一三种协议确实相同的 TCP 拨号、截止时间、取消、动态线路缓冲和
关闭语义。`mail_net_tls` 是独立可裁剪层，只在需要 TLS 时加入安全传输。

## 所有权

`xmailnetconfig` 借用调用方的 `xnetengine`、`xnetresolver`、主机名和 TLS 共享对象。
客户端不会创建或销毁这些对象，因此多个协议客户端可以共享同一高性能 Engine 和 DNS
缓存。同步客户端函数不能从该 Engine 的 Worker 回调中调用。

## 安全模式

默认配置使用 `XMAIL_SECURITY_PLAIN`，因此基础模块不依赖任何 TLS、X.509 或密码模块。
`XMAIL_SECURITY_PLAIN` 建立明文 TCP；`XMAIL_SECURITY_TLS` 完成隐式 TLS；
`XMAIL_SECURITY_STARTTLS` 先建立明文连接，再由具体协议状态机完成能力检查、升级命令和
TLS 接管。后两种模式要求启用 `mail_net_tls`；TLS 模式必须提供 `Tls.Verifier`，不会
静默关闭证书验证。空 SNI/验证名称会从拨号主机补齐；数字 IP 只补验证名称。
隐式 TLS 握手遵守调用方的截止时间和取消请求；握手中取消、超时或对端异常关闭
都会使拨号失败，失败的邮件传输对象不持有活动 TCP/TLS Stream。
STARTTLS 接管任务尚在传输 Worker 队列中时，截止时间或取消会撤销接管；Worker
恢复后不会再读取借用的 TLS 配置或占用原 TCP，明文连接仍由调用方持有。若接管
已在 Worker 上开始，调用会先等待引用交接完成，再根据截止时间或取消结果清理
TLS。协议客户端仍应按自身状态机决定失败后的会话终态。

## 缓冲边界

默认线路上限为 64 KiB，接收按 4 KiB 动态增长，不为每个连接固定保留 8 KiB。发送按
16 KiB 分片，并同时受 TCP 写入硬上限和 TLS Future 未完成字节上限约束。协议客户端可
调整这些值，但所有增长都保持有界并接受统一 `int64` 与 `xcancel`。
每个发送分片在提交前检查截止时间与取消状态，包括 TCP 队列立即接受数据的路径；
TCP 写队列重试前也重新检查。连接请求在提交 TCP/TLS 异步拨号前检查已到期的
截止时间和已请求的取消，避免无效调用触发 DNS 解析或建立连接；
DNS 查询已经开始时，调用方取消或截止时间到期仍会及时停止等待并取消拨号 Future，
不等待解析回调结束，也不会向调用方交付失效连接。
发送中途失败可能已提交先前分片，协议客户端会将该会话置为失败终态并立即异常中止
传输，以阻止仍在排队的 TLS 分片继续发送；原始错误会保留供调用方诊断。
已建立 TLS 连接上的接收等待超时或取消会撤销本次尚未完成的 Future，本层不自动
关闭传输；上层协议仍须自行决定会话是否可以继续。TLS 发送若在 Worker 开始处理前
取消，不会提交该分片；已经开始的发送不能假定可回滚，调用方不得盲目重发命令。
TLS 正常关闭会在请求 `close_notify` 后按 `ReadChunk` 消费并丢弃剩余 TLS 明文，
直到认证 EOF，再等待连接关闭终态。协议结束后分片到达的压缩尾字节因此不会
通过读取背压阻塞 `close_notify`；该过程仍遵守调用方截止时间和 TLS 关闭超时，
不会把未经认证的 EOF 或分配失败当作正常关闭。
正常关闭若在提交请求、消费残留明文、创建等待 Future 或等待终态时失败，共享传输层会立即
异常中止连接并保留原始错误；不会把尚未完成的关闭留给调用方销毁时才处理。
