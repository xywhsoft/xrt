# JSON 性能基线 2026-07-31

## 环境

- 系统：Windows 10.0.19045
- CPU：AMD Ryzen 5 5600 6-Core Processor
- GCC：15.2.0，`-O3 -std=c11`，x64
- TinyCC：0.9.27，`-O2 -m32`
- 输入：181 字节，包含嵌套对象、数组、整数、布尔值和 Unicode 转义
- 参数：每条路径 100,000 次

## 结果

| 编译器 | DOM 解析 | 解析吞吐 | 事件访问 | 访问吞吐 | DOM 写出 |
|---|---:|---:|---:|---:|---:|
| GCC x64 | 424,687 ops/s | 73.307 MiB/s | 1,312,264 ops/s | 226.516 MiB/s | 398,039 ops/s |
| TinyCC `-m32` | 82,914 ops/s | 14.312 MiB/s | 235,366 ops/s | 40.628 MiB/s | 91,301 ops/s |

两次运行的校验和均为 `32600000`。

## 解释

直接事件访问不创建 `xvalue` DOM，在两种工具链下都明显快于 DOM 解析。这个差异是预期的分层成本，不应通过把 DOM 所有权或安全检查移入事件层来消除。

本文件是同一机器、工具链、架构、输入和参数下的回归起点。后续比较应同时关注三条路径；只有解析变慢通常指向扫描、Unicode 或 Value 构建，访问和解析同时变慢通常指向共同扫描层，只有写出变慢通常指向 Value 遍历、数字格式化或 Buffer 增长。
