## 数值转换路径

跨整数/浮点哈希与相等要求只接受可无损转换为 `int64` 的浮点数。GCC 能把
`isfinite + floor` 优化为高效指令；TinyCC 会为 `floor` 付出明显库调用成本。
实现因此保持一个仅按编译器能力划分的等价路径：

- GCC、Clang、MSVC 使用 `isfinite`、范围与 `floor`。
- TinyCC 使用范围、整数转换和反向精确比较。

TinyCC 的 Hash+Equal 从优化前约 `4,415,544 ops/s` 提升到
`16,025,443 ops/s`，GCC 没有为兼顾 TinyCC 牺牲热路径。

## 使用

堆尺寸类、数值规范化、Hash、Equal 或输出安全门禁后应重新记录结果。跨机器结果只作
参考，不直接使用绝对阈值。
