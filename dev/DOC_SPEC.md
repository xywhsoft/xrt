# XRT API 文档质量规范（DOC_SPEC）

> **本文件是文档深化长期任务的唯一质量权威。**
> 每个工作会话的第一步：重读本文件 + `dev/DOC_PROGRESS.md` 台账，然后才动笔。
> 任何与记忆冲突之处，以本文件为准。

版本：v1.0-draft（试点 array + net 审定后冻结为 v1.0；此后修改必须升版本号并在
`dev/DOC_PROGRESS.md` 记录变更理由与影响范围）。

适用范围：`docs/api/*.md` 全部 80 个手写文件（`*-reference.md` 为自动生成，不适用）。

## 1. 文档结构

### 1.1 模块级骨架（每个文档文件开头，按序）

```markdown
# <模块名>

<一段定位：这个模块是什么、不是什么、何时选用。>

## 裁剪与依赖          ← 特性宏表（保留现有内容，校对后沿用）
## 稳定契约            ← 跨 API 的不变量清单（保留现有内容）
## 常量                ← 每个公共常量一节
## 类型                ← 每个公共类型一节：签名 + 字段表 + 语义
## <功能分组标题>       ← 若干组，如"生命周期""编辑""查找"
   ### `xrtXxxYyy`     ← 每个 API 一节（模板见 1.2）
```

模块级**必须**包含（若无现有内容则补写）：

- **错误码总表**：本模块的结构化错误域与代码，失败如何取得（`xrtGetError()`）；
- **线程约束总览**：本模块 API 的线程规则（无锁/原子快照/Worker 专用/回调期间有效）；
- **所有权规则**：借用、接管、引用计数的总述。

### 1.2 API 级模板（每个 `XRT_API` 函数一节，逐项如下）

````markdown
### `xrtXxxYyy`

<一句话语义。>

```c
<与头文件完全一致的签名（可换行对齐；不含 XRT_API 前缀）>
```

#### 参数

| 参数 | 方向 | 约束 | 说明 |
|---|---|---|---|
| `pXxx` | 输入 | 非空 | …… |

#### 返回值

| 返回 | 含义 | 失败时状态 |
|---|---|---|
| `true` | …… | — |
| `false` | …… | <不变量如何保持；错误经 `xrtGetError()` 报告> |

#### 错误        ← 返回 bool / 指针 / 可失败句柄的函数必填

- `XERR_XXX` — <触发条件>
- ……

#### 并发与所有权   ← 仅在与模块总述不同/有额外细节时写；可省略

<线程规则；参数与返回值的所有权归属。>

#### 范例

[<范例目录名>](../../examples/<路径>) · <该范例覆盖本 API 的哪一段>

```c
<≤12 行片段，必须可追溯（见 §4）>
```
````

## 2. 各节的最低信息量

### 2.1 参数表

- **行数 ≥ 签名形参数**（`void` 除外）；每个形参一行，不得合并。
- **方向**三选一：`输入` / `输出` / `输入输出`。出参（写调用方存储）标`输出`；
  既读又写（如游标结构）标`输入输出`。
- **约束**列：空指针是否允许、取值范围、单位、生命周期要求（"存活到回调结束"等）。
  无约束写 `—`。
- **说明**列：语义 + 成功/失败后该参数的状态变化。禁止只重复参数名。

### 2.2 返回值表

- `bool` 返回：**必须两行齐全**（true/false 各自含义），失败行必须写明
  对象状态是否改变与错误获取途径。
- 枚举返回：**每个枚举值一行**（含"不会出现的情况"可省略）。
- 指针返回：非空/空各一行，说明空的触发条件与借用/所有权归属。
- `size_t` 哨兵返回（如 `XRT_NPOS`）：写明哨兵含义。
- 无失败路径（void/纯查询）：单行说明 + `—`。

### 2.3 错误节

- 只列**本函数可设置**的错误；格式 `- `XERR_XXX` — 触发条件`。
- 错误域/代码以**实测为准**（写文档时用探针确认，不确定的必须实测），
  不凭猜测。实测与头文件注释冲突时按 `dev/EXAMPLES_LIBRARY_ISSUES.md`
  流程记问题，文档按实测写并加"（与头文件注释不符，见 ISSUES-xx）"。

### 2.4 范例节

- 链接目标**必须是已注册进 modules.json 且通过编译运行校验的范例**。
- 片段 ≤ 12 行；**可追溯规则**：片段剥离注释、空白后，必须是所引用范例
  源文件的（规范化）子串——保证片段永远来自可编译的真实代码。
- 片段前的引导句说明该片段在范例中的位置/前提。

## 3. 术语表（全部文档统一用词）

| 类别 | 术语 | 含义（唯一定义） |
|---|---|---|
| 方向 | 输入 / 输出 / 输入输出 | 参数表专用 |
| 所有权 | **借用** | 指针/视图仅在调用期间有效，库不持有 |
| | **接管** | 成功后归库所有，由库释放（Take 族）；失败仍归调用方 |
| | **引用** | Ref/Destroy（或 Free/Release/Unit）配对的共享所有权 |
| | **移交** | 所有权转移给回调/出参，原持有者不得再用 |
| 线程 | 任意线程 | 无约束（内部原子或只读） |
| | **Worker 专用** | 仅传输所属 Worker 线程可调，违规得 STATE 错误或无效 |
| | 回调期间有效 | 借用指针仅在回调执行期间可解引用 |
| | 并发快照 | 可与其他线程并发读取的一致性级别 |
| 时序 | 恰好一次 | 成功路径上必发生且仅发生一次 |
| | 空操作 | 合法调用但无效果（常允许空指针） |
| | 原子失败 | 失败时对象状态完全不变 |
| 数字 | 単位 | 字节用"字节"，时间用"微秒/毫秒"显式标注；协议字段按线格式（如"16 位大端"） |

**禁用词**：大概、可能（表示不确定的实现猜测时）、应该（规范语义时）、
之类的、等等（列举不完整时）。文档只写已验证事实；未验证的不写。

## 4. 机器质量门禁（每任务必过，全绿才算完成）

| # | 门禁 | 工具 | 判据 |
|---|---|---|---|
| G1 | 签名一致 | `python tools/check_api_reference_detail.py --doc <file>` | 文档每个 ```c 首签名块与公共头声明（剥离 XRT_API、规范化空白）逐字符一致 |
| G2 | 覆盖完备 | 同上 | 头文件全部 `XRT_API` 函数在文档各有 `###` 节；每节有 `#### 参数`（行覆盖全部形参）、`#### 返回值`；bool/指针返回另有 `#### 错误`；有 `#### 范例` 且链接路径存在 |
| G3 | 片段可追溯 | `python tools/extract_doc_examples.py --doc <file>` | 每个 `#### 范例` 下的 ```c 片段（剥注释/空白规范化）是所引范例源文件的子串 |
| G4 | 范例已注册 | 同 G2 内建 | 范例路径出现在 config/modules.json 任一 examples 数组 |

**禁操作清单**（违反即任务作废重来）：

1. 禁止对 `config/modules.json`、既有 `docs/api/*.md` 之外文件做批量脚本改写
   而不跑对应校验；
2. 禁止 `git checkout --` 还原未提交的他人/前批改动；
3. 禁止跳过门禁"先记完成"；
4. 禁止为过门禁而降低模板（如删 `#### 错误` 节规避检查）；
5. 每任务一个 commit，消息格式 `docs(api): <模块> 按 DOC_SPEC v1 细化`。

## 5. 每任务流程（固定，不得精简）

1. 重读本规范 + 台账，确认目标任务与上下文；
2. `G1/G2` 跑目标文件 → 得到当前缺口清单；
3. 读该模块公共头注释、已验证范例（examples/）、台账中相关语义/问题/摩擦条目；
4. 逐 API 写：先签名（从头文件复制），再参数表 → 返回值 → 错误 → 范例片段；
5. 跑全部四项门禁 → 全绿；
6. 更新 `dev/DOC_PROGRESS.md`（状态、四项门禁数字、发现的问题）；
7. commit + 汇报（报告里必须含四项门禁数字）。

**完成定义（DoD）**：G1–G4 全绿 + 台账已记 + commit 完成。三者缺一不算完成。

## 6. 特殊情形处理

- **镜像函数**（如 PtrArray 对 Array 的对应接口）：仍写全模板，但说明列可
  简短并链接基础函数节；参数表不得省略。
- **平台差异**：分平台列差异（如"Windows 无数据报错误队列"），标注平台名。
- **文档化中发现库问题**：记入 `dev/EXAMPLES_LIBRARY_ISSUES.md`（编号续接），
  文档按实测行为写并引用编号；**不改库代码**。
- **多模块共用文档文件**（如 array.md 含 array+ptr_array）：门禁按文件聚合
  全部相关头的并集检查。
- **头文件在本任务期间变更**：门禁跑的是当前头 → 变更即红 → 该任务顺带
  修订对应文档节，台账记录"库变更带动修订"。
